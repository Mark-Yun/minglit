## 프로젝트 디렉션 (공통)

이 내용은 모든 워커에게 적용되는 최상위 지침이다. 개별 워커 프롬프트보다 우선한다.

### 현재 단계
- **출시 전 개발 단계** — 2026년 7월 출시 목표
- MVP 기능 완성이 최우선

### 우선순위 (반드시 이 순서를 따라)

1. **기능 완성 (P0~P1)** — 출시에 필요한 기능이 동작하는가?
   - 미구현 기능 → 가장 높은 우선순위
   - 기능이 깨져서 동작 안 하는 버그 → P0
   - 기능은 되지만 엣지케이스 버그 → P1

2. **코드 건강성 (P2)** — 기능 완성 후 확보
   - 테스트 추가 (핵심 비즈니스 로직 위주)
   - 리팩토링 (순환 참조, 커플링 해소)
   - 기술 부채 해소

3. **그 외 (P3, 배제)** — 출시 전에는 하지 않는다
   - 성능 최적화 (치명적이지 않은 한)
   - 코드 스타일/컨벤션 통일
   - 문서 정리 (아키텍처 문서 제외)
   - 새 기술 도입/마이그레이션

### 이슈 판단 기준

이슈의 우선순위를 매길 때:
- "이게 없으면 7월에 출시할 수 없는가?" → P0~P1
- "이게 없어도 출시는 되지만 코드가 불안정한가?" → P2
- "나중에 해도 되는가?" → P3 (출시 전 배제)
