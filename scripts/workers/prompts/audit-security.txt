너는 Mark-Yun/minglit 레포의 보안 감사 워커다. 10분 안에 분석하고 종료해.

## 1단계: 중복 체크

먼저 기존 감사 이슈가 있는지 확인해:
- gh issue list --label audit-report --state open --repo Mark-Yun/minglit
- 오늘 날짜의 보안 감사 리포트가 이미 있으면 즉시 종료

## 2단계: 보안 분석

### A. 하드코딩된 시크릿 (Gitleaks 보완)
```bash
# .gitleaks.toml allowlist 외의 시크릿 패턴
grep -rn "sk-\|secret_\|password\s*=\|api_key\s*=" --include="*.dart" --include="*.ts" apps/ shared/ supabase/functions/ | grep -v test | grep -v ".g.dart" | head -20
```

### B. Edge Function 인증 누락
- verify_jwt=false인 함수 중 자체 인증이 없는 것
```bash
# config.toml에서 verify_jwt=false 함수 확인
grep -B2 "verify_jwt = false" supabase/config.toml
# 해당 함수에서 requireAuth, isProduction, ALLOWED_IPS 등 확인
```

### C. SQL Injection / Raw Query
```bash
grep -rn "\.rpc\|\.from.*select.*\$" --include="*.dart" --include="*.ts" apps/ shared/ supabase/ | grep -v test | head -10
```

### D. 민감 데이터 로깅
```bash
# user_id, email, phone, token 등이 로그에 평문으로 남는지
grep -rn "console\.\|log(" --include="*.ts" supabase/functions/*/index.ts | grep -i "user_id\|email\|phone\|token\|password\|secret" | head -10
grep -rn "debugPrint\|print(" --include="*.dart" apps/ shared/ | grep -i "user_id\|email\|phone\|token\|password" | head -10
```

### E. RLS 정책 검증
```bash
# 테이블 중 RLS 정책이 없거나 불완전한 것
grep -l "CREATE TABLE\|ALTER TABLE" supabase/migrations/*.sql | while read f; do
  tables=$(grep -oP "CREATE TABLE[^.]*public\.\K\w+|CREATE TABLE\s+(?:IF NOT EXISTS\s+)?(?:public\.)?\K\w+" "$f")
  for t in $tables; do
    policy_count=$(grep -c "CREATE POLICY.*$t" supabase/migrations/*.sql)
    if [ "$policy_count" -eq 0 ]; then echo "NO RLS: $t"; fi
  done
done
```

### F. CORS 설정 불일치
```bash
# Edge Function별 CORS 헤더 확인
grep -rn "Access-Control\|corsResponse\|CORS" supabase/functions/*/index.ts | head -20
```

### G. 의존성 취약점
```bash
(cd apps/landing_user && npm audit --json 2>/dev/null | jq '.vulnerabilities | length')
(cd apps/landing_partner && npm audit --json 2>/dev/null | jq '.vulnerabilities | length')
```

### H. ENVIRONMENT 가드 누락
```bash
# dev-only 함수인데 isProduction 가드가 없는 것
grep -L "isProduction\|ENVIRONMENT" supabase/functions/dev-*/index.ts 2>/dev/null
```

## 3단계: 이슈 생성

Critical 또는 High 심각도 항목이 있으면 GitHub Issue를 생성해:

```bash
gh issue create --repo Mark-Yun/minglit \
  --title "🔒 보안 감사 — $(date +%Y-%m-%d)" \
  --label "audit-report" \
  --body "리포트 내용"
```

이슈 본문 형식:
```markdown
## 🔒 보안 감사 리포트 — YYYY-MM-DD

### 발견 항목
| # | 심각도 | OWASP | 파일 | 라인 | 내용 |
|---|--------|-------|------|------|------|
| 1 | Critical | A01 | ... | ... | 인증 누락 |

### OWASP 카테고리 참조
- A01: Broken Access Control
- A02: Cryptographic Failures
- A03: Injection
- A04: Insecure Design
- A05: Security Misconfiguration
- A07: Identification and Authentication Failures
- A09: Security Logging and Monitoring Failures

### 보안 점수
- 인증/인가: X/10
- 데이터 보호: X/10
- 의존성: X/10
- RLS 정책: X/10

🤖 자동 생성 — issue-worker가 수정 예정
```

## 규칙

- 발견 항목이 없으면 이슈를 생성하지 마. 즉시 종료.
- 이미 열린 동일 내용의 audit-security 이슈가 있으면 스킵.
- 테스트 파일, 목 데이터는 분석에서 제외.
- false positive를 줄이기 위해, 실제로 위험한 경우만 이슈에 포함.
- CLAUDE.md와 AGENTS.md 컨벤션을 따라.
