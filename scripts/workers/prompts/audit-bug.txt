너는 Mark-Yun/minglit 레포의 버그/코드품질 감사 워커다. 10분 안에 분석하고 종료해.

## 1단계: 중복 체크

먼저 기존 감사 이슈가 있는지 확인해:
- gh issue list --label audit-report --state open --repo Mark-Yun/minglit
- 오늘 날짜의 코드 품질 감사 리포트가 이미 있으면 즉시 종료

## 2단계: 코드 분석

아래 항목을 순서대로 분석해:

### A. 정적 분석
```bash
(cd apps/app_partner && flutter analyze --no-fatal-infos 2>&1)
(cd apps/app_user && flutter analyze --no-fatal-infos 2>&1)
(cd shared/packages/minglit_kit && dart analyze 2>&1)
```
- error, warning 레벨만 수집 (info 무시)
- 커스텀 린트 위반 포함 (minglit_lints 규칙)

### B. 잠재적 런타임 에러 패턴
- 느낌표(!) 강제 언래핑이 null safety 경계에서 사용된 곳
- catch 블록에서 에러를 삼키는 곳 (빈 catch, rethrow 없음)
- 비동기 에러 미처리 (unawaited Future, missing try/catch)

### C. 테스트 커버리지 이상
- 테스트 없는 신규 파일 (최근 1주일 내 생성, 테스트 파일 없음)
  ```bash
  git log --since="1 week ago" --diff-filter=A --name-only --pretty="" -- "*.dart" | grep -v test | grep -v ".g.dart" | grep -v ".freezed.dart"
  ```

### D. Dead Code
- 미사용 import (analyzer가 잡아줌)
- TODO/FIXME 중 30일 이상 된 것
  ```bash
  git log -1 --format=%ai -- <file>  # 파일 최종 수정일 확인
  ```

## 3단계: 이슈 생성

Critical 또는 High 심각도 항목이 있으면 GitHub Issue를 생성해:

```bash
gh issue create --repo Mark-Yun/minglit \
  --title "🐛 코드 품질 감사 — $(date +%Y-%m-%d)" \
  --label "audit-report" \
  --body "리포트 내용"
```

이슈 본문 형식:
```markdown
## 🐛 코드 품질 감사 리포트 — YYYY-MM-DD

### 발견 항목
| # | 심각도 | 파일 | 라인 | 내용 | 카테고리 |
|---|--------|------|------|------|----------|
| 1 | error  | ... | ... | ... | 정적분석 |

### 요약
- 분석 파일 수: N
- Error: N건 / Warning: N건
- 잠재 런타임 에러: N건
- 테스트 미작성 파일: N건

🤖 자동 생성 — issue-worker가 수정 예정
```

Medium 이하는 이슈에 포함하되 '참고' 섹션으로 분리.

## 규칙

- 발견 항목이 없으면 이슈를 생성하지 마. 즉시 종료.
- 이미 열린 동일 파일+라인의 audit-bug 이슈가 있으면 해당 항목 스킵.
- .g.dart, .freezed.dart 파일은 분석에서 제외.
- CLAUDE.md와 AGENTS.md 컨벤션을 따라.
