# Google TypeScript 스타일 가이드 요약

이 문서는 `gts` 도구에 의해 강제되는 Google TypeScript 스타일 가이드의 주요 규칙과 모범 사례를 요약합니다.

## 1. 언어 기능
- **변수 선언:** 항상 `const`나 `let`을 사용하세요. **`var`는 금지됩니다.** 기본적으로 `const`를 사용하세요.
- **모듈:** ES6 모듈(`import`/`export`)을 사용하세요. **`namespace`를 사용하지 마세요.**
- **Export:** 명명된 내보내기(`export {MyClass};`)를 사용하세요. **기본 내보내기(default exports)를 사용하지 마세요.**
- **클래스:**
  - **`#private` 필드를 사용하지 마세요.** TypeScript의 `private` 가시성 수정자를 사용하세요.
  - 생성자 외부에서 재할당되지 않는 속성은 `readonly`로 표시하세요.
  - **`public` 수정자를 절대 사용하지 마세요** (기본값임). 가능한 경우 `private`이나 `protected`로 가시성을 제한하세요.
- **함수:** 명명된 함수에는 함수 선언을 선호하세요. 익명 함수나 콜백에는 화살표 함수를 사용하세요.
- **문자열 리터럴:** 작은따옴표(`'`)를 사용하세요. 보간 및 여러 줄 문자열에는 템플릿 리터럴(`` ` ``)을 사용하세요.
- **동등성 검사:** 항상 일치 연산자(`===`)와 불일치 연산자(`!==`)를 사용하세요.
- **타입 단언:** **타입 단언(`x as SomeType`)과 non-null 단언(`y!`)을 피하세요**. 꼭 사용해야 한다면 명확한 정당성을 제시하세요.

## 2. 허용되지 않는 기능
- **`any` 타입:** **`any`를 피하세요**. `unknown`이나 더 구체적인 타입을 선호하세요.
- **래퍼 객체:** `String`, `Boolean`, `Number` 래퍼 클래스를 인스턴스화하지 마세요.
- **자동 세미콜론 삽입 (ASI):** 이에 의존하지 마세요. **모든 문장은 명시적으로 세미콜론으로 끝내세요.**
- **`const enum`:** `const enum`을 사용하지 마세요. 대신 일반 `enum`을 사용하세요.
- **`eval()` 및 `Function(...string)`:** 금지됨.

## 3. 명명 규칙
- **`UpperCamelCase`:** 클래스, 인터페이스, 타입, 열거형, 데코레이터.
- **`lowerCamelCase`:** 변수, 매개변수, 함수, 메서드, 속성.
- **`CONSTANT_CASE`:** 전역 상수 값 및 열거형 값.
- **`_` 접두사/접미사:** 식별자(비공개 속성 포함)에 **`_`를 접두사나 접미사로 사용하지 마세요.**

## 4. 타입 시스템
- **타입 추론:** 단순하고 명확한 타입에는 타입 추론에 의존하세요. 복잡한 타입은 명시하세요.
- **`undefined` 및 `null`:** 둘 다 지원됩니다. 프로젝트 내에서 일관성을 유지하세요.
- **선택적 vs `|undefined`:** 타입에 `|undefined`를 추가하는 것보다 선택적 매개변수 및 필드(`?`)를 선호하세요.
- **`Array<T>` 타입:** 단순한 타입에는 `T[]`를 사용하세요. 복잡한 유니온 타입에는 `Array<T>`를 사용하세요 (예: `Array<string | number>`).
- **`{}` 타입:** **`{}`를 사용하지 마세요**. `unknown`, `Record<string, unknown>`, 또는 `object`를 선호하세요.

## 5. 주석 및 문서화
- **JSDoc:** 문서화에는 `/** JSDoc */`을, 구현 주석에는 `//`를 사용하세요.
- **중복:** **`@param`이나 `@return` 블록에 타입을 선언하지 마세요** (예: `/** @param {string} user */`). TypeScript에서는 중복입니다.
- **정보 추가:** 주석은 단순히 코드를 다시 설명하는 것이 아니라 정보를 추가해야 합니다.
