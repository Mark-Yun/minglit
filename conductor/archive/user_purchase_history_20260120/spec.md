# 명세서: 유저 앱 구매 내역 구현 (User Purchase History)

## 1. 개요
유저가 자신이 예매한 이벤트 티켓 목록과 결제 내역을 한눈에 확인하고 관리할 수 있는 '구매 내역' 화면을 구현합니다. 마이페이지를 통해 접근하며, 티켓의 상태(결제 완료, 취소 등)와 주요 이벤트 정보를 제공합니다.

## 2. 주요 기능

### 2.1. 진입 및 목록 조회
- **진입 경로:** 마이페이지(My Page) 내 '구매 내역' 메뉴를 통해 진입합니다.
- **정렬 방식:** 최신 구매 순(기본)으로 정렬된 리스트를 제공합니다.
- **데이터 소스:** `event_applications` 테이블을 기반으로 `events`, `parties` 정보를 조인하여 표시합니다.

### 2.2. 내역 카드 구성 요소
각 구매 내역 아이템은 다음 정보를 포함해야 합니다:
- **이벤트 정보:** 제목, 대표 이미지, 장소 요약(예: 서울 강남), 이벤트 시작 일시.
- **티켓 정보:** 티켓 이름, 구매 수량.
- **결제 정보:** 총 결제 금액, 결제 일시.
- **상태 배지:** 현재 상태 표시 (결제 완료, 심사 중, 취소됨, 환불 완료 등).

### 2.3. 사용자 액션
- **환불/취소 신청:** 해당 신청 건에 대해 취소 또는 환불 절차를 시작합니다. (환불 시스템 트랙과 연동)
- **영수증 보기:** 결제 상세 정보 또는 영수증 UI를 띄웁니다.
- **주최자 문의:** 해당 파티의 파트너(주최자)에게 문의할 수 있는 통로를 제공합니다.

## 3. 기술 스택
- **Frontend:** Flutter (Riverpod for state management)
- **Backend:** Supabase (PostgreSQL views or direct table queries)

## 4. 수락 기준
- [ ] 마이페이지에서 구매 내역 화면으로 정상적으로 이동할 수 있다.
- [ ] 사용자가 구매한 모든 티켓 목록이 최신순으로 정확하게 표시된다.
- [ ] 각 아이템에 이벤트 일시, 장소, 금액, 상태가 명확히 표시된다.
- [ ] 환불, 영수증, 문의 버튼이 UI상에 적절히 배치되어 있다.

## 5. 범위 제외 (Out of Scope)
- 실제 환불 처리 로직 및 정책(Refund Logic)은 `user_refund_cancellation_system` 트랙에서 담당하며, 본 트랙은 해당 기능을 호출하는 UI 접점까지만 구현합니다.
