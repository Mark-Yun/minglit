# 명세서: 파티 참여자 심사 및 환불 관리 시스템 (Application Review System)

## 1. 개요
파트너(관리자)가 신청된 파티 참여 내역을 심사하고 승인 또는 거절하는 기능을 구현합니다. 복잡한 '보완 요청' 프로세스 대신, **거절 시 즉각적인 자동 환불**과 **알림을 통한 재신청 유도**라는 단순하고 명확한 프로세스를 채택하여 운영 효율성과 시스템 안정성을 확보합니다.

## 2. 주요 기능

### 2.1. 파트너 앱 (심사 관리)
- **신청 목록 조회:** 대기 중(`pending_review`)인 신청 건을 목록으로 확인.
- **상세 심사 화면:** 유저 프로필, 제출된 인증 데이터(사진 등) 확인.
- **심사 액션:**
    - **승인 (Approve):** 상태를 `approved`로 변경 -> 티켓 발권(`ticket_issued`) -> 유저에게 "참여 확정" 알림.
    - **거절 (Reject):** 거절 사유 선택 후 상태를 `rejected`로 변경 -> **자동 환불 로직 실행** -> 유저에게 "취소 및 환불" 알림.

### 2.2. 거절 사유 (Rejection Reasons)
- **증빙 서류 식별 불가:** "사진이 흐릿하거나 잘려서 확인할 수 없습니다."
- **자격 요건 불충분:** "제출하신 서류가 파티 자격 요건을 충족하지 않습니다."
- **정원 초과/기타:** 직접 입력 가능한 텍스트 필드 제공.

### 2.3. 유저 앱 (결과 확인)
- **알림 및 딥링크:**
    - 승인 시: "파티 참여가 확정되었습니다! 티켓을 확인하세요." -> 티켓 화면으로 이동.
    - 거절 시: "심사가 반려되어 환불되었습니다. (사유: ...)" -> **해당 파티 상세 화면**으로 이동하여 재신청 유도.

### 2.4. 백엔드 (Payment & State)
- **환불 트리거:** `event_applications` 상태가 `rejected`로 업데이트되면 Supabase Edge Function이 Portone 결제 취소 API를 호출.
- **정합성 보장:** 환불 실패 시 상태를 `refund_failed`로 표시하고 관리자가 수동 처리하도록 기록.

## 3. 기술 스택
- **결제 연동:** Portone API (Cancel Payment).
- **상태 관리:** Supabase Database Trigger & Edge Function.

## 4. 수락 기준
- [ ] 파트너가 거절 버튼을 누르면 사유 선택 팝업이 떠야 함.
- [ ] 거절 처리 시 DB 상태가 변경되고 결제 취소 API가 호출되어야 함.
- [ ] 유저에게 거절 사유가 포함된 푸시 알림이 발송되어야 함.
- [ ] 거절된 유저가 파티 상세 화면으로 이동했을 때 다시 "신청하기" 버튼이 활성화되어야 함.
