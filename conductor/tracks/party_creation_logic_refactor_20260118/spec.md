# 명세서: 파티 생성 시 최대 인원 로직 개선 및 티켓 수량 통합

## 1. 개요
현재 파티 생성 시 '최대 인원'을 수동으로 입력받고 있으나, 이는 티켓 수량의 총합과 불일치할 수 있는 문제가 있습니다. 이를 개선하여 티켓 수량의 합계가 곧 파티의 최대 수용 인원이 되도록 로직을 통합합니다. UI에서는 중복 입력을 제거하고, DB 레벨에서는 트리거를 통해 데이터 일관성을 보장합니다.

## 2. 주요 기능

### 2.1. 데이터베이스 및 로직 (`minglit_kit`, DB)
- **자동 동기화 트리거:** `tickets` 테이블에 `INSERT`, `UPDATE`, `DELETE` 발생 시, 해당 파티/이벤트의 `max_participants` 값을 티켓 수량(`quantity`)의 합계로 자동 업데이트하는 트리거 구현.
- **최소 인원 검증:** `min_confirmed_count`가 자동 계산된 `max_participants`보다 클 수 없도록 DB 제약조건(Constraint) 또는 애플리케이션 로직 강화.
- **Seeder 업데이트:** 테스트 데이터 생성 시 임의의 `max_participants` 대신 티켓 수량에 맞춰 생성하도록 `DatabaseSeeder` 수정.

### 2.2. 파트너 앱 UX 개선 (`app_partner`)
- **입력 필드 제거:** 파티 생성/수정 위저드에서 '최대 인원(Max Participants)' 입력 필드 삭제.
- **실시간 합계 표시:** 티켓 관리 화면에서 티켓을 추가하거나 수량을 변경할 때, "총 수용 인원: N명"을 실시간으로 계산하여 표시.
- **최소 인원 유효성 검사:** '최소 확정 인원' 입력 시 현재 티켓 합계를 초과하지 않도록 검증 로직 추가.

## 3. 데이터 처리 전략
- **Legacy Data:** 기존 데이터는 일괄 업데이트하지 않고 유지하며, 파트너가 파티 정보를 수정하는 시점에 새로운 로직(트리거)에 의해 동기화되도록 함.

## 4. 수락 기준
- [ ] 파트너 앱에서 '최대 인원' 입력란이 사라져야 함.
- [ ] 티켓을 추가/수정하면 DB의 `events` 및 `parties` 테이블의 `max_participants` 값이 자동으로 변경되어야 함.
- [ ] 최소 인원을 티켓 합계보다 크게 설정하면 에러 메시지가 표시되어야 함.
- [ ] `integration_scenario_tester` 및 시더(Seeder) 실행 시 데이터 불일치 오류가 없어야 함.
