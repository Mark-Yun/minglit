# 명세서: 이벤트 상세 화면 (유저 앱)

## 1. 개요
`app_user` 애플리케이션에서 특정 이벤트의 상세 뷰를 구현합니다. 이 화면은 사용자가 이벤트 세부 정보를 확인하고 입장 절차(신원 확인 -> 자격 심사 -> 티켓 선택)를 진행하는 주요 전환 포인트 역할을 합니다.

## 2. 사용자 스토리
- **사용자**로서, 참석 여부를 결정하기 위해 이벤트의 상세 정보(장소, 시간, 호스트, 설명)를 보고 싶습니다.
- **사용자**로서, 이벤트에 필요한 구체적인 입장 조건(나이, 성별, 자격 요건)을 확인하고 싶습니다.
- **게스트**로서, 참여를 시도할 때 로그인/회원가입을 안내받고 싶습니다.
- **로그인한 사용자**로서, 현재 나의 입장 상태(예: "본인 인증 필요", "참여 가능")를 확인하고 다음 단계로 안내받고 싶습니다.

## 3. 기능 요구사항
### 3.1. 데이터 표시
- **이벤트 헤더:** 대형 히어로 이미지, 이벤트 제목, 호스트 이름.
- **이벤트 정보:** 날짜/시간, 장소(가능한 경우 지도 미리보기 포함), 설명.
- **입장 조건:** `EntryGroupDetail`을 사용하여 구조화된 조건 목록(나이, 성별, 직업 등)을 표시합니다.

### 3.2. 입장 로직 (신뢰 시스템)
- `EventAdmissionController`와 연동합니다.
- **상태:**
  - `Guest`: "로그인하고 참여하기" 표시.
  - `IdentityRequired`: "본인 인증하기" 표시.
  - `QualificationRequired`: "자격 심사 신청하기" 표시.
  - `NotEligible`: 사유와 함께 "참여 불가" 표시.
  - `Eligible`: "티켓 선택하기" 표시.

### 3.3. 인터랙션
- **주요 CTA:** 입장 상태에 따라 변하는 하단(고정 또는 스티키)의 동적 버튼.
- **뒤로 가기:** 리스트로 돌아가는 표준 뒤로 가기 버튼.
- **새로고침:** 이벤트 데이터와 입장 상태를 다시 로드하는 당겨서 새로고침(Pull-to-refresh).

## 4. 기술 요구사항
- **프레임워크:** Flutter (app_user)
- **상태 관리:** Riverpod (`EventDetailController`, `EventAdmissionController`)
- **네비게이션:** GoRouter (Coordinator 패턴)
- **에러 핸들링:** API 실패 시 `handleMinglitError` 사용.
- **컴포넌트:** `MinglitButton`, `MinglitImage`, `EntryGroupDetail` (`minglit_kit`에서 재사용).

## 5. UI/UX 가이드라인
- `minglit_kit` 디자인 토큰(색상, 타이포그래피, 간격)을 따릅니다.
- 노치 디바이스를 위한 "Safe Area" 지원을 보장합니다.
- 로딩 상태는 표준 스켈레톤이나 스피너를 사용해야 합니다.
