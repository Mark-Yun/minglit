# 파트너 QR 체크인 화면 — UX 강화 스펙

**관련 이슈**: #1779
**상태**: 승인 대기 (report-exec)
**작성자**: needs-pm-claude-1
**작성일**: 2026-04-23

## 개요

현재 파트너 앱의 QR 체크인 화면은 전체 화면 카메라 뷰와 스캔 성공/실패 피드백만 제공한다. 파트너가 현장에서 필요한 **"지금 누가 얼마나 들어왔는가"** 정보가 UI에 없어, 별도 화면을 번갈아 보며 운영해야 한다.

이 스펙은 QR 스캐너 화면에 **실시간 입장 현황**을 통합하여, 파트너가 체크인 중에도 한눈에 진행률·그룹별 현황을 파악할 수 있게 만든다.

### 참고 앱 분석

| 앱 | 강점 | 밍글릿 적용 |
|----|------|-------------|
| **Eventbrite Organizer** | 실시간 체크인 대시보드, 티켓 타입별 breakdown, 혼잡 게이트 분석, 오프라인 sync | 엔트리 그룹별 현황 + 오프라인 모드 (v2) |
| **Meetup for Organizers** | 하단 고정 progress bar — "N/M 체크인" 상시 노출 | 스캐너 하단 progress 바 + 숫자 |
| **Luma Mobile** | 수동 검색 fallback (이름/이메일), 실시간 게스트 리스트 | 수동 체크인 버튼 + 참가자 리스트 시트 |

### 핵심 원칙

1. **카메라 우선** — 체크인 동작은 QR 스캔이 기본. 통계는 방해하지 않는다.
2. **한 화면 운영** — 파트너가 스캔 중 다른 화면으로 이동하지 않게 한다.
3. **그룹별 가시성** — 이벤트가 엔트리 그룹(성별·연령대 제한)을 가진 경우, 그룹별 진행률을 노출한다.
4. **현장 읽기 가능성** — 카메라 뷰의 어두운 배경에서도 숫자가 명확히 읽혀야 한다.

## 현재 상태 (AS-IS)

```
┌────────────────────────────────┐
│  AppBar: [이벤트명]              │
├────────────────────────────────┤
│                                │
│       ┌──────────┐             │
│       │          │             │
│       │  QR 스캔  │             │  ← 250x250 카메라 프레임
│       │          │             │
│       └──────────┘             │
│                                │
│                                │  ← 빈 공간
│                                │
│  [스캔 성공 시 초록 오버레이]    │
│  [실패 시 빨간 오버레이 + 메시지] │
└────────────────────────────────┘
```

**문제점**:
- 체크인 진행률을 알 수 없음 — "지금 몇 명 들어왔지?"에 답할 수 없음
- 엔트리 그룹별 현황 부재 — 성별/연령대 쿼터 도달 여부 즉시 확인 불가
- QR 인식 실패 시 수동 체크인 경로가 없음
- 혼잡 시간대에 파트너가 스태프와 소통할 정보가 화면에 없음

### 데이터 가용성

현재 코드에 이미 존재하는 자원 (재사용 가능):
- `getEntryGroupParticipantCounts(eventId)` RPC — entry_group별 participant_count 반환
  (`shared/packages/minglit_kit/lib/src/data/repositories/event_repository_queries.dart:272`)
- `Event.currentParticipants / maxParticipants` 필드
- `Event.entryGroups` — 각 그룹의 label, gender, birth_year_min/max 포함

추가 백엔드 작업 필요 (v1 필수):
- `event_participants.checked_in_at: timestamptz` 컬럼 추가 (체크인 시각 기록)
- `get_event_checkin_stats(p_event_id)` RPC 신규 — 그룹별 `total / checked_in` 반환
- 체크인 성공 시 `event_participants.status = 'checked_in'` + `checked_in_at = now()` 업데이트

### 1. 상단 AppBar (변경 없음)

### 2. 요약 카드 (신규)
- 위치: AppBar 바로 아래, 고정
- 높이: 80px
- 내용:
  - 큰 숫자: `23/50` (체크인 완료 / 티켓 발급)
  - Progress bar: 너비 100%, 높이 8px, 색상 `success #22C55E`
  - 퍼센트: `46%` 우측 정렬
  - 부가 정보: `진행중 · 남은 인원 27명` (12px, textSecondary)
- 인터랙션: 탭 시 전체 참가자 리스트 화면으로 이동 (v2)

### 3. 카메라 프레임 (기존 + 조정)
- 크기: 250px → **220px** 로 축소 (상단 카드 공간 확보)
- 프레임 색: 기존 유지 (파트너 primary `#6C3CE1`)
- 스캔 성공: 초록 오버레이 + 참가자 정보 0.8초 표시 (기존 유지)
- 스캔 실패: 빨간 오버레이 + 실패 이유 표시 (기존 유지)
- **신규 성공 정보**: `홍길동 · 남 20대 · 3번째 입장` — 유저명 + 엔트리 그룹 + 시간순 번호

### 4. 보조 컨트롤 (신규)
- 카메라 프레임 아래 horizontal row, 간격 16px
- **플래시 토글 버튼**: 어두운 현장 대비 (아이콘 + 라벨, 44x44pt)
- **수동 체크인 버튼**: QR 인식 실패 시 fallback. 탭 시 참가자 리스트 바텀시트 오픈 (이름 검색 + 체크인 토글)

### 5. 엔트리 그룹별 현황 (신규)

- 바텀시트 내용 (각 그룹):
  - 라벨: `남 20대 초반` (16px, w600)

## 유저 시뮬레이션

### Persona 1: 주말 팝업 이벤트 주최자 (바쁜 현장, 1인 운영)
**민지 · 33세 · 독립 팝업 주최**
- 이벤트 시작 10분 전 입구에 혼자 있음. 체크인 QR 스캔과 환영 인사를 병행.
- 불만 (AS-IS): "총 몇 명 왔지?" 확인하려면 스캐너를 닫고 대시보드로 가야 함. 줄이 밀림.
- 개선 (TO-BE): 스캐너 화면 상단 `23/50` 을 실시간으로 확인 → 인사하면서 스캔 유지.

### Persona 2: 성별 밸런스 이벤트 파트너 (엔트리 쿼터 관리)
**재훈 · 29세 · 소셜 클럽 운영자**
- 남녀 14:14 제한 이벤트. 한쪽 성별이 먼저 차는 경우 추가 입장 통제 필요.
- 불만 (AS-IS): "남자 몇 명 들어왔어요?" 질문에 즉답 불가. 체크인 목록을 수동 카운트.
- 개선 (TO-BE): 하단 시트 풀업 → `남 20대 13/14, 여 20대 8/14` 즉시 확인 → 남자 입장 대기열 공지.

### Persona 3: QR 인식 실패 케이스 (대학 동아리 파트너, 스태프 2인)
**예린 · 24세 · 동아리 임원**
- 참가자의 폰 화면이 깨지거나 배터리 방전 — QR 스캔 불가 케이스 월 1~2회 발생.
- 불만 (AS-IS): 수동 체크인 경로가 없음. 참가자를 되돌려 보내거나 운영팀에 DM으로 요청.
- 개선 (TO-BE): [수동 체크인 열기] 버튼 → 이름 검색 → 체크인. 운영 중단 없이 해결.

### 엣지 케이스
- 이벤트에 엔트리 그룹이 없음 → 하단 시트 섹션 숨김
- 체크인 대상이 아닌 이벤트 (이미 종료) → CheckinPlaceholderPage에서 필터링 (기존 유지)
- 한 파트너가 여러 이벤트 동시 운영 → 기존 이벤트 선택 시트 사용 (기존 유지)
- 참가자 수 0 → "아직 발급된 티켓이 없습니다" 텍스트 + QR 스캐너 비활성화
- 체크인 완료 후 환불된 티켓 → 재스캔 시 "환불된 티켓" 에러

## 승인 요청

이 스펙은 다음과 같은 scope 판단을 포함한다:

- **신규 백엔드 변경 1건** — `checked_in_at` 컬럼 + RPC. 기존 schema에 저침하지 않는 additive 변경.
- **신규 Realtime 구독 1건** — 동시 운영 시 일관성 필수.
- **엔트리 그룹 시트는 하단 축소 UI** — 카메라 뷰를 가리지 않는 대안으로 선택 (대안: 전면 탭 전환).

승인 이후 `needs-uiux` 로 라우팅 → ux-designer 가이드를 받고 구현 이슈를 분할한다.
