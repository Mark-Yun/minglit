# PRD: 파트너 QR 체크인 UX 강화

## Summary

파트너 앱 QR 체크인 화면에 (1) 전체 진행률 요약 카드 (2) 엔트리 그룹별 현황 하단 시트 (3) 수동 체크인 fallback (4) Realtime 자동 동기화를 통합. 파트너가 체크인 중에도 화면 전환 없이 "지금 누가 얼마나 들어왔는가"를 한눈에 파악할 수 있게 한다.

## Motivation / Problem to Solve

- 현재 화면은 전체 화면 카메라 뷰 + 스캔 성공/실패 피드백만 제공. "지금 누가 얼마나 들어왔는가" 부재
- 파트너가 진행률을 확인하려면 스캐너를 닫고 별도 대시보드로 이동 — 현장에서 줄이 밀림
- 엔트리 그룹(성별·연령대 제한)이 있는 이벤트에서 쿼터 도달 여부 즉시 확인 불가
- QR 인식 실패 (참가자 폰 화면 깨짐 / 배터리 방전) 시 수동 체크인 경로 부재 — 월 1~2회 발생
- 출처: 이슈 #1779, 페르소나 인터뷰 (민지 / 재훈 / 예린)

## Goals

### Target Users

- **1인 운영 파트너 (바쁜 현장)**: 입구에서 혼자 스캔 + 환영 인사 병행. 진행률 즉시 확인 필요
- **엔트리 쿼터 관리 파트너**: 성비 / 연령대 밸런스 이벤트 운영. 쿼터 도달 즉시 입장 통제
- **스태프 2인 운영 파트너 (멀티 디바이스)**: QR 인식 실패 케이스 fallback + 다른 기기 체크인 자동 반영

### Key Goals

- **P0**: 전체 진행률 요약 카드 — `N/M` + 연속 프로그레스 바 + 퍼센트 + 남은 인원 (스캐너 화면 상단 상시 노출)
- **P0**: 엔트리 그룹별 현황 하단 시트 — pull-up 으로 확장. 그룹별 라벨 / 비율 / 프로그레스 단계별 색상
- **P0**: 스캔 성공 시 참가자 정보 확장 — 유저명 / 그룹 / 시간순 번호
- **P0**: 수동 체크인 fallback — 참가자 리스트 시트 + 이름 검색 + 체크인 토글
- **P0**: 카메라 플래시 토글 (어두운 현장 대비)
- **P0**: stats 새로고침 액션 (상단바, 네트워크 불안정 대비)
- **P1**: Realtime 자동 동기화 — 다른 기기 체크인 시 stats 자동 갱신
- **P2 (out of scope)**: 오프라인 큐 / 멀티 디바이스 충돌 방지 UI / 시간대별 분포 그래프

### Non-Goals

- **오프라인 모드 (v2)**: 체크인 큐 + 재연결 sync 는 별도 PR
- **참가자 리스트 독립 화면**: 수동 체크인은 시트로만 제공, 독립 라우트 미생성
- **체크인 시간대별 분포 그래프**: 혼잡 시간 분석은 v2
- **멀티 디바이스 충돌 방지 UI**: 여러 스태프 동시 스캔 상태 충돌은 v2

## Product Principles

1. **카메라 우선**: 체크인 동작은 QR 스캔이 기본. 통계 UI 는 스캔을 방해하지 않게 배치.
2. **한 화면 운영**: 파트너가 스캔 중 다른 화면으로 이동하지 않게 한다.
3. **그룹별 가시성**: 엔트리 그룹이 있는 이벤트는 그룹별 진행률 노출. 없으면 섹션 숨김.
4. **현장 읽기 가능성**: 카메라 뷰의 어두운 배경에서도 숫자가 명확히 읽혀야 함. 큰 카운트 폰트 + 충분한 대비.
5. **Fallback 우선**: QR 인식 실패는 가끔 발생 — 수동 체크인 경로를 1탭으로 노출.

## Technical Approach

- **화면**: 기존 QR 체크인 화면 내부 UI 재구성 — 신규 라우트 없음 (v2 에서 참가자 리스트 라우트 추가 예정)
- **데이터 (기존)**: 이벤트 제목 / 참가자 제한 / 전체 참가자 수 / 엔트리 그룹 목록 / 스캐너 로직
- **데이터 (신규)**:
  - `event_participants.checked_in_at` 컬럼 추가 — 체크인 시각 기록
  - 그룹별 체크인 현황 RPC — 그룹별 (total / checked_in) 반환
  - QR 체크인 성공 시 참가자 상태 = checked_in + 체크인 시각 기록
- **Realtime (P1)**: `event_participants` 채널 구독 → 다른 기기 체크인 시 stats 자동 갱신
- **외부 의존성**: 없음 (카메라 / Realtime 기존 인프라 재사용)

## User Journey

### Scenario 1: 1인 운영 파트너의 진행률 모니터링 (CUJ 1-x)

파트너가 이벤트 시작 10분 전 입구에서 혼자 운영. QR 스캔과 환영 인사를 병행하면서, 스캐너 화면 상단의 요약 카드(`23/50`)를 실시간으로 확인.

### Scenario 2: 엔트리 쿼터 관리 (CUJ 2-x)

남녀 14:14 이벤트 파트너가 한쪽 성별이 먼저 차는지 확인하기 위해, 하단 시트를 pull-up → 그룹별 `남 20대 13/14, 여 20대 8/14` 확인 → 남자 입장 대기열 공지.

### Scenario 3: QR 인식 실패 fallback (CUJ 3-x)

참가자 폰 화면 깨짐 / 배터리 방전으로 QR 스캔 불가. 파트너가 [수동 체크인] 버튼 탭 → 참가자 리스트 시트 → 이름 검색 → 체크인 토글로 처리.

### Scenario 4: 멀티 디바이스 자동 동기화 (CUJ 4-x, P1)

스태프 2인이 각자 디바이스로 동시 체크인. 한 명이 스캔하면 다른 디바이스의 stats 가 Realtime 으로 자동 갱신.

## Data Flow

### Scenario 1

체크인 화면 진입 → stats fetch (전체 + 그룹별) → 요약 카드 + 하단 시트 헤더 렌더 → 스캔 → 성공 시 참가자 상태 변경 + 체크인 시각 기록 + stats 재조회 → 카드 갱신

### Scenario 2

스캐너 화면 하단 시트 헤더 탭 또는 pull-up → 시트 확장 → 그룹별 row 노출 (라벨 / 비율 / 프로그레스) → 진행률 단계별 색상 표시

### Scenario 3

[수동 체크인 열기] 탭 → 참가자 리스트 바텀시트 (이름 검색) → 참가자 row 의 체크인 토글 탭 → 서버 업데이트 + stats 재조회

### Scenario 4

체크인 화면 진입 시 Realtime 채널 구독 → 다른 디바이스 체크인 이벤트 수신 → 요약 카드 + 하단 시트 자동 갱신 → 화면 이탈 시 구독 해제

## KPIs / Success Metrics

- **체크인 중 화면 이탈 횟수**: baseline 측정 후 감소 목표 (현재 진행률 확인하러 다른 화면 이동)
- **수동 체크인 처리 시간**: 1건당 30s 이내 (검색 + 체크인 토글)
- **QR 인식 실패 → 수동 체크인 fallback 전환율**: baseline 측정
- **Realtime 동기화 지연**: 다른 디바이스 체크인 → 본 디바이스 stats 갱신 5s 이내 (p95)

## Launch Strategy

P0 (요약 카드 / 그룹 시트 / 참가자 정보 / 수동 체크인 / 플래시 / 새로고침) MVP ship. P1 (Realtime 자동 동기화) 후속 ship. P2 (오프라인 / 멀티 디바이스 충돌 / 시간대 분포) 별도 PR.
