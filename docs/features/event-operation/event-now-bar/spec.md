## Functional Requirements

> 제품 행동 정의 — DB schema SQL / Provider 이름 / Repository 메서드 시그니처 같은 dev detail 은 제외 (코드/migration 이 SSoT).

- **FR-1**: 미니바는 이벤트 시작 3시간 전 ~ 종료 24시간 후 또는 리뷰 작성 완료 시점까지 노출. 그 외 시간에는 미노출.
- **FR-2**: 활성 이벤트 0건 시 미니바 미노출 (홈 피드만 노출).
- **FR-3**: 미니바는 홈 셸의 하단 탭바 바로 위 오버레이 레이어. 라우트 변경 없이 모든 홈 탭에서 노출.
- **FR-4**: 미니바 상태는 (대기 → 체크인 가능 → 체크인 완료 → 매칭 → 결과 → 종료) 6 단계 머신으로 자동 전환. 사용자 액션 없이 서버 변화 → 자동 전환.
- **FR-5**: 미니바 탭 시 현재 상태에 대응하는 모달 시트 표시. 라우트 이동이 아닌 모달.
- **FR-6**: Phase 1 바텀시트 (체크인 전) — QR 코드 + 이벤트명 / 시간 / 장소 + 위치 안내 링크. 높이 ~55%.
- **FR-7**: Phase 2 바텀시트 (체크인 완료) — 체크인 완료 메시지 + 참석자 수 (실시간) + 참석자 아바타 row (최대 5명 + N+ 카운트).
- **FR-8**: Phase 3 바텀시트 (매칭 투표) — 기존 매칭 투표 컨텐츠 임베드. 높이 ~85%, 드래그로 풀스크린 확장 가능.
- **FR-9**: 매칭 투표 컨텐츠는 풀스크린 화면 / 바텀시트 임베드 양쪽에서 동일하게 재사용 가능한 형태로 제공.
- **FR-10**: Phase 4 바텀시트 (결과) — 매칭 상대 프로필 카드 N장. 매칭 0건 시 빈 상태 일러스트 + "이번엔 아쉽지만, 다음 기회에!".
- **FR-11**: Phase 5 바텀시트 (종료) — 별점 입력 + "리뷰 작성하기" Primary CTA + 다음 추천 이벤트 카드.
- **FR-12**: 미니바 해제 조건은 (a) 종료 + 24시간, (b) 리뷰 작성 완료 중 빠른 것.
- **FR-13**: 활성 이벤트 ≥ 2건일 때 미니바 우측에 카운트 배지 + 드롭다운 아이콘 노출.
- **FR-14**: 멀티 이벤트 정렬 우선순위 — 진행 중 (체크인 ~ 결과) > 시작 대기 > 종료. 동일 상태면 시작 시간 빠른 순.
- **FR-15**: 멀티 이벤트 미니바 위로 스와이프 또는 카운트 배지 탭 → 시트에 이벤트 목록 카드 → 선택 → 해당 이벤트 단일 시트.
- **FR-16**: 한 이벤트가 종료될 때 미니바는 즉시 해제되지 않고 "리뷰 작성" 상태로 하단 유지 (다음 활성 이벤트가 상단으로 자동 승격).
- **FR-17**: 앱 백그라운드 / 킬 후 복귀 시 서버 상태 re-fetch → 미니바 자동 복원. 최신 상태 보장.
- **FR-18**: Realtime 채널 끊김 / 실패 시 30 초 간격 폴링 fallback. 폴링 중에는 상태 표시 변경 없음 (사용자에게 노출되지 않음).

## Non-Functional Requirements

> 측정 가능해야 함 — "빨라야 함" 금지. 환경 + 분위수 명시 (예: "에뮬레이터 baseline, p50 200ms 이내").

- **NFR-1**: 미니바 first paint 100ms 이내 (에뮬레이터 baseline, p95). 캐시 hit 가정. 바텀시트 오픈 → first paint 300ms 이내.
- **NFR-2**: 서버 상태 변경 → 미니바 UI 반영 < 5s (p50, realtime 정상), < 60s (p95, 폴링 fallback).
- **NFR-3**: Realtime 채널 끊김 감지 → 폴링 전환 < 10s (p95). 사용자에게 가시적 깜빡임 없음.
- **NFR-4**: 매칭 결과 발표 펄스 애니메이션은 60fps 유지 (저사양 기기 baseline, 1500ms 주기, 5회 반복 후 정지).

## Open Questions

> 결정 못한 항목 — 1주 이상 방치 시 명시적으로 결정 또는 Non-Goal 로 이동.

- [ ] **자정 넘긴 이벤트 종료 처리** — endTime 기준 (확정) vs 캘린더 날짜 기준?
- [ ] **리뷰 작성 중 앱 kill 시 컨텐츠 복구** — 자동 임시 저장 vs 다시 처음부터?
- [ ] **매칭 투표 임베드 vs 풀스크린 전환** — 시트 드래그 풀스크린 vs 별도 풀스크린 라우트 이동?
- [ ] **(오프라인) 표시 정책** — 텍스트 추가 vs 별도 아이콘 / 컬러 변경?
- [ ] **펄스 애니메이션 종료 조건** — 시간 기반(5회) vs 사용자 탭까지 vs 결과 확인 완료까지?
- [ ] **카운트 배지 최대 표시** — 5건 이상이면 "5+" vs 정확한 수?
- [ ] **알림 권한 거부 유저** — 푸시 없이 미니바만으로 충분한 시그널인지 정성 검증 필요

## 화면 구성 (참고)

> dev 가 아닌 product/UX detail 만. MDS spec 이 SSoT.

### 미니바 본체

홈 화면 하단, BottomNavigationBar 바로 위에 고정되는 컴팩트 바.

```text
┌─────────────────────────────────────────────┐
│ ● 강남 밍릿파티 · 체크인 대기 중    19:00 → │
└─────────────────────────────────────────────┘
```

| 요소 | 설명 |
|------|------|
| 상태 인디케이터 (좌) | 컬러 dot — 상태별 색상 변경 |
| 이벤트명 (좌~중) | 1줄 말줄임 |
| 상태 텍스트 (중) | 현재 단계 라벨 |
| 시간/CTA (우) | 시작 전: 시작 시간 / 진행 중: 화살표 아이콘 |

**스타일**: 높이 56px, 배경 surface + 상단 elevation shadow, 좌우 패딩 20px, 라운딩 상단만 16px.

**상태별 dot 색상**:

| 상태 | dot 색상 | 토큰 |
|------|---------|------|
| 대기 | gray | `textSecondary` |
| 체크인 가능 | purple | `primary` |
| 체크인 완료 | green | `success` |
| 매칭 투표 중 | orange | `secondary` |
| 매칭 결과 | purple + pulse | `primary` + pulse |
| 이벤트 종료 | gray | `textSecondary` |

### Phase 1 ~ 5 바텀시트

| Phase | 컨텐츠 | 높이 |
|-------|--------|------|
| 1. 체크인 전 | QR 코드 + 이벤트 정보 + 위치 안내 링크 | ~55% |
| 2. 체크인 완료 / 매칭 대기 | 체크인 완료 메시지 + 참석자 수 + 아바타 row | ~50% |
| 3. 매칭 투표 | 매칭 투표 컨텐츠 임베드 | ~85% (풀스크린 확장 가능) |
| 4. 매칭 결과 | 매칭 상대 프로필 카드 N장 (또는 빈 상태) | ~70% |
| 5. 이벤트 종료 | 별점 + 리뷰 CTA + 다음 추천 이벤트 카드 | ~75% |

### 멀티 이벤트 스택

```text
┌─────────────────────────────────────────────┐
│ ● 강남 밍릿파티 · 체크인 중         2 ▼ │
└─────────────────────────────────────────────┘
```

우측에 이벤트 개수 배지 + 드롭다운 아이콘. 탭 시 시트에 이벤트 목록.

**정렬 우선순위**:
1. 현재 진행 중 (체크인 ~ 결과) > 시작 대기 > 종료
2. 같은 상태면 시작 시간 빠른 순

### 상태 머신

```text
WAITING (대기) ─── event.startTime - 3h ≤ now
  │ (시작 시간 도달)
  ▼
CHECK_IN_READY (체크인 가능) ─── event.startTime ≤ now
  │ (참가자 status = checked_in)
  ▼
CHECKED_IN (체크인 완료) ─── 매칭 후보 대기
  │ (매칭 후보 비어있지 않음)
  ▼
MATCHING (매칭 투표 중) ─── 투표 진행
  │ (매칭 결과 존재)
  ▼
RESULTS (매칭 결과) ─── 결과 확인
  │ (events.status = completed)
  ▼
ENDED (종료) ─── 리뷰 + 다음 추천
  │ (24h 경과 또는 리뷰 작성 완료)
  ▼
(나우바 해제)
```

> DB `events.status` 컬럼은 `scheduled` / `cancelled` / `completed` 3 값만 가지며, MATCHING / RESULTS 등 중간 상태는 참가자 / 매칭 후보 / 매칭 결과로부터 클라이언트 derived.

### 데이터 정의 (참고)

| 항목 | key | 설명 |
