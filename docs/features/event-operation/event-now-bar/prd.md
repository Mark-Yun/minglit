# PRD: 이벤트 나우바 (Event Now Bar)

## Summary

유저앱 홈 하단에 당일 이벤트의 체크인 → 매칭 → 결과를 실시간 안내하는 퍼시스턴트 미니바. 앱 어디에 있든 현재 이벤트 상태를 즉시 확인할 수 있고, 탭하면 단계별 바텀시트로 상세 진입한다.

## Motivation / Problem to Solve

- 첫 참석자가 체크인 / 매칭 / 결과 진입 경로를 별도 안내 없이 찾기 어렵다는 정성 피드백 (페르소나 "지현")
- 같은 날 2개 이상 이벤트 참석하는 헤비 유저(페르소나 "민수") 의 진행 상태 추적 경로 부재
- 매칭 투표 / 결과 알림 푸시를 놓친 유저(페르소나 "수진") 가 앱 복귀 후 최신 상태를 즉시 확인할 경로 부재
- 기존 진입 경로(이벤트 상세 / 알림 / 마이페이지) 가 분산돼 있어 이벤트 진행 중 컨텍스트 단절 발생

## Goals

### Target Users

- **이벤트 신청자**: 당일 이벤트 시작 3시간 전 ~ 종료 24시간 후까지의 모든 유저
- **첫 참석자**: 체크인 / 매칭 흐름을 처음 경험하는 유저 — 자연스러운 진입 유도 필요
- **헤비 유저**: 같은 날 2개 이상 이벤트 참석 — 멀티 스택 UX 필요

### Key Goals

- **P0**: 당일 활성 이벤트 1개일 때 홈 하단에 퍼시스턴트 미니바 노출 (이벤트명 + 현재 상태 + 시간/CTA)
- **P0**: 미니바 탭 → 단계별 바텀시트 (체크인 QR / 매칭 대기 / 매칭 투표 / 결과 / 종료) 자동 전환
- **P0**: 상태 자동 전환 (서버 변화 → realtime 또는 폴링 fallback)
- **P0**: 멀티 이벤트 (2개 이상) 동시 활성 시 수직 캐러셀 스택으로 표시 + 가장 시급한 이벤트가 상단
- **P1**: 앱 백그라운드 / 킬 후 복귀 시 미니바 상태가 최신으로 자동 복원
- **P1**: 매칭 투표 바텀시트는 풀스크린 확장 가능 (DraggableScrollableSheet)

### Non-Goals

- 푸시 알림 자체 변경 (별도 PRD — 나우바는 앱 내 진입점, 푸시는 앱 외부 알림)
- 이벤트 상세 페이지 변경
- 파트너 앱 동등 미니바 (파트너는 별도 운영 화면 보유)
- 이벤트 종료 후 24시간 이후의 미니바 유지

## Product Principles

1. **패시브 모니터링**: 앱 어디에 있든 현재 이벤트 상태를 즉시 확인 가능 (Just Eat 미니바 패턴).
2. **프로그레시브 디스클로저**: 미니바는 최소 정보만, 탭하면 바텀시트로 확장 (Uber 라이드 카드 패턴).
3. **Dismiss 불가**: 이벤트 종료 시까지 자동 유지 (iOS Live Activity 라이프사이클).
4. **상태별 자동 전환**: 사용자 액션 없이도 서버 변화에 따라 미니바 / 바텀시트 컨텐츠가 자동 전환.

## Technical Approach

- **화면**: 미니바 위젯 + 단계별 바텀시트 5종 (Phase 1~5) + 멀티 스택 시트
- **저장**: 신규 테이블 없음. 기존 이벤트 / 참가자 / 매칭 후보 / 매칭 결과 테이블 derived 상태로 표시
- **외부 의존성**: Supabase Realtime (참가자 / 매칭 결과 변경 감지), 기존 QR 위젯 / 매칭 투표 위젯 재사용
- **가드 / 정책**: 라우터 변경 없음 — 미니바는 홈 셸 위 오버레이 레이어. 바텀시트는 `showModalBottomSheet` 모달

## User Journey

### Scenario 1: 단일 이벤트 진행 (CUJ 1-x)

신청자가 이벤트 당일 앱 진입 시 홈 하단에 미니바 노출, 시간 경과에 따라 상태가 자동 전환 (대기 → 체크인 → 매칭 → 결과 → 종료) 되며 각 단계 탭 시 적절한 바텀시트가 열린다.

### Scenario 2: 멀티 이벤트 스택 (CUJ 2-x)

같은 날 2개 이상 이벤트 활성 시 미니바에 카운트 배지 + 드롭다운 노출, 위로 스와이프 또는 탭으로 이벤트 목록 펼침 → 선택 → 해당 이벤트 상세 시트로 진입.

### Scenario 3: 백그라운드 / 킬 후 복귀 (CUJ 3-x)

앱이 백그라운드 / 킬 상태에서 매칭 투표 시작 / 결과 발표 등 상태 변경 발생 → 앱 복귀 시 미니바가 최신 상태로 자동 복원되어 즉시 진입 가능.

## Data Flow

### Scenario 1

홈 진입 → 당일 활성 이벤트 조회 (시작 3h 전 ~ 종료 24h 후 범위) → 이벤트 1건일 때 단일 미니바 렌더 → 상태 머신 (WAITING / CHECK_IN_READY / CHECKED_IN / MATCHING / RESULTS / ENDED) 산출 → realtime 채널 구독 → 상태 변화 시 invalidate → 미니바 / 바텀시트 자동 갱신

### Scenario 2

당일 활성 이벤트 ≥ 2건 → 우선순위 정렬 (진행 중 > 시작 대기 > 종료) → 상단 1건 노출 + 카운트 배지 → 스와이프 / 탭 → 시트에 전체 목록 → 선택 → 해당 이벤트 단일 시트

### Scenario 3

앱 백그라운드 → 서버 측 상태 변경 (realtime push 또는 폴링 fallback) → 앱 포그라운드 진입 시 provider invalidate → 서버에서 최신 상태 fetch → 미니바 즉시 갱신

## KPIs / Success Metrics

- **미니바 노출 → 탭 CTR**: 당일 활성 이벤트 보유 유저 중 미니바 탭 비율 ≥ 60%
- **체크인 진입 경로 분포**: 이벤트 상세 vs 미니바 — 미니바 비율 baseline + 20%p
- **매칭 결과 확인 시간**: 결과 발표 → 유저가 결과 확인까지 평균 ≤ 5분 (p50)
- **첫 참석자 체크인 완료율**: 신규 유저(첫 이벤트) 중 자력 체크인 완료율 ≥ 90%
- **상태 자동 전환 정확도**: 서버 상태 변경 → UI 반영 < 10s (p95, realtime 가정)

## Launch Strategy

- 1단계: 단일 이벤트 + Phase 1~5 바텀시트 출시
- 2단계: 멀티 이벤트 스택 출시 (헤비 유저 데이터 충분히 확보 후)
- 3단계: 오프라인 / 에러 fallback 강화 (realtime 끊김 시 폴링 fallback)
