# 환불 정책 이원화 스펙 (Refund Policy v2)

## 개요

환불 정책을 **플랫폼 자동 환불**과 **파트너 환불**로 이원화한다. 현재 약관·DB·코드가 서로 다른 환불 규칙을 갖고 있어 전자상거래법 제17조/제18조 위반 가능성이 있다. 이번 작업으로 세 곳을 하나의 정책으로 통일하고, 유저가 환불 가능 여부를 명확히 인지할 수 있는 UX를 제공한다.

**출처 이슈**: #765 (환불 정책 약관-코드 불일치)

### 현재 상태 (문제)

| 소스 | 환불 기준 | 문제 |
|------|----------|------|
| **약관** (`landing_user/terms/page.tsx:72-74`) | 3일 전 100% / 2~1일 전 50% / 당일 0% | 코드와 불일치 |
| **DB 정책** (`policies` seed, `refund` key) | grace_period_hours=2, cutoff_days=7 | tier 배열 미사용 |
| **코드** (`refund_utils.ts` + `user-cancel-order`) | 결제 후 2시간 OR 이벤트 7일 전 → 전액/불가 (binary) | 부분환불 없음 |

### 핵심 원칙

1. **법적 안전**: 전자상거래법 제17조 7일 청약철회권 준수
2. **이원화**: 플랫폼이 자동 처리하는 범위 vs. 파트너에게 위임하는 범위를 명확히 분리
3. **투명성**: 유저가 결제 전·후 환불 조건을 정확히 인지
4. **단순성**: binary(전액/불가) 구조를 유지하되, 파트너 환불 경로를 추가

### 참고 앱

| 앱 | 환불 정책 | 밍글릿 적용 포인트 |
|----|----------|-------------------|
| **Frip** | 8일+ 전액 / 3~7일 80% / 1~3일 50% / 당일 불가. 호스트가 정책 커스텀 가능 | 호스트 커스텀은 V3에서 검토. 현재는 플랫폼 단일 정책 |
| **Airbnb Experiences** | 7일+ 전액 / 7일 미만 불가 / 예약 24시간 내+48시간 전 전액 | grace period + cutoff 구조가 밍글릿 현행 코드와 유사 |
| **인터파크 티켓** | 9일+ 전액 / 7~8일 10% 공제 / 3~6일 20% / 2일 30% / 전일·당일 불가 | 다단계 tier는 복잡도 대비 유저 혼선 우려. V2에서는 채택하지 않음 |

### 유저 시뮬레이션

**페르소나 1 — 충동 신청 후 취소하는 직장인 (28세, 여성)**
- 퇴근 후 흥미로운 이벤트 발견 → 즉시 결제 → 30분 후 일정 충돌 확인
- Pain: "방금 결제했는데 환불이 안 된다고?" → grace period 3시간으로 해소
- 기대: 결제 직후 화면에서 "3시간 내 전액 환불 가능" 안내 확인

**페르소나 2 — 계획적 참여자 (32세, 남성)**
- 2주 전 이벤트 결제 → 5일 전 개인 사정 발생
- Pain: cutoff 7일이 지나서 자동 환불 불가
- 기대: "파트너에게 환불 요청하기" 경로가 명확히 보임. 파트너 연락처+메시지 전송

**페르소나 3 — 파트너의 이벤트 취소를 겪은 유저 (25세, 여성)**
- 결제 완료 후 파트너가 이벤트 취소
- Pain: 환불이 언제 되는지 불안
- 기대: 즉시 자동 환불 + 푸시 알림 ("환불이 완료됐어요. 영업일 기준 3일 내에 입금돼요")

## 환불 정책 구조

### Track 1: 플랫폼 자동 환불

플랫폼이 코드 로직으로 자동 판단하고 PortOne API를 통해 즉시 처리하는 환불.

| 조건 | 환불률 | 처리 주체 |
|------|--------|----------|
| 결제 후 **3시간** 이내 (grace period) | 100% | 플랫폼 자동 |
| 이벤트 시작 **7일 전**까지 (cutoff) | 100% | 플랫폼 자동 |
| 파트너 귀책 (이벤트 취소, 심사 거절) | 100% | 플랫폼 자동 |
| 무료 이벤트 취소 | 결제 없음 → 상태만 변경 | 플랫폼 자동 |

**변경 사항**:
- grace_period_hours: 2 → **3** (전자상거래법 7일 청약철회 보완. 충동 결제 후 취소 여유 확보)
- cutoff_days: 7 유지 (Airbnb Experiences와 동일, 법적 최소 기준 충족)

### Track 2: 파트너 환불 (신규)

플랫폼 자동 환불 범위 밖(grace period 초과 + cutoff 초과)인 경우, 유저가 파트너에게 직접 환불을 요청하는 경로.

| 조건 | 처리 방식 |
|------|----------|
| grace period 초과 + cutoff 초과 | 유저 → 파트너 환불 요청 (인앱 메시지) |
| 파트너 승인 | 파트너가 앱에서 환불 승인 → 플랫폼이 결제 취소 처리 |
| 파트너 거절/미응답 | 유저에게 고객센터 안내 |

**파트너 환불 요청 플로우**:
```
유저가 취소 시도 → 자동 환불 불가 판정
  → "환불 요청하기" 바텀시트 표시
  → 환불 사유 선택 (질병/일정변경/기타)
  → 파트너에게 환불 요청 알림 전송
  → 파트너 앱에서 승인/거절
  → 결과 푸시 알림
```

### 1. 유저 앱 — 취소/환불 플로우

#### 1-1. 구매 내역 카드 — 취소 버튼

### 2. 유저 앱 — 이벤트 상세 환불 정책 섹션

## 데이터 소스

### 신규 테이블: `refund_requests`

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | uuid PK | |
| `application_id` | uuid FK → event_applications | 환불 대상 신청 |
| `event_id` | uuid FK → events | 이벤트 |
| `user_id` | uuid FK → auth.users | 요청 유저 |
| `partner_id` | uuid FK → auth.users | 파트너 |
| `reason_code` | text | `schedule_change`, `health`, `other` |
| `reason_text` | text | 기타 사유 텍스트 (nullable) |
| `status` | text | `pending`, `approved`, `rejected`, `expired` |
| `responded_at` | timestamptz | 파트너 응답 시각 |
| `rejection_reason` | text | 거절 사유 (nullable) |
| `created_at` | timestamptz | 요청 생성 시각 |

**RLS**:
- 유저: 자기 요청만 INSERT/SELECT
- 파트너: 자기 이벤트에 대한 요청 SELECT/UPDATE (status, responded_at, rejection_reason)

### 신규 Edge Function: `partner-approve-refund`

파트너가 환불 요청을 승인할 때 호출:
1. `refund_requests.status` → `approved`, `responded_at` → now()
2. 기존 `executeRefund()` 호출 (PortOne 결제 취소)
3. `event_applications.refund_status` → `completed`
4. 유저에게 푸시 알림

### 신규 Edge Function: `partner-reject-refund`

파트너가 환불 요청을 거절할 때 호출:
1. `refund_requests.status` → `rejected`, `rejection_reason` 저장
2. 유저에게 푸시 알림

### 신규 Edge Function: `user-request-refund`

유저가 파트너에게 환불을 요청할 때 호출:
1. 자동 환불 불가 여부 재검증 (서버에서 이중 확인)
2. `refund_requests` INSERT
3. 파트너에게 푸시 알림

### DB 정책 업데이트

`policies` 테이블의 `refund` 키 값 변경:

```json
{
  "grace_period_hours": 3,
  "cutoff_days": 7,
  "partner_refund_enabled": true,
  "partner_response_deadline_hours": 72
}
```

| 파일 | 변경 내용 |
|------|----------|
| `refund_utils.ts` | `gracePeriodHours` 기본값 2→3으로 변경 (DB 정책에서 읽음) |
| `refund_calculator.dart` | 동일하게 3시간 반영 + "파트너 요청 가능" 상태 추가 |
| `user-cancel-order/index.ts` | 자동 환불 불가 시 에러 대신 `{ type: 'partner_refund_available' }` 응답 |

## Non-Goals (이번 범위 밖)

- **부분 환불**: 현재 binary(전액/불가) 구조 유지. 부분 환불은 정산 시스템 고도화 후 V3에서 검토
- **파트너별 커스텀 환불 정책**: Frip처럼 호스트가 자체 정책 설정하는 기능은 V3
- **인앱 실시간 채팅**: 환불 요청은 비동기 메시지 기반. 실시간 채팅은 별도 피처
- **자동 부분 환불 tier**: 인터파크식 다단계 공제율은 복잡도 대비 유저 혼선 우려로 V2에서 채택하지 않음
