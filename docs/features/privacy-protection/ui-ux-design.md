## 1. 설계 개요

### 1.1 목적

유저가 자신의 인증 데이터가 어떤 파트너에게 공유되고 있는지 투명하게 확인하고,
원하면 특정 파트너의 열람 권한을 철회(revoke)할 수 있는 화면을 제공한다.

### 1.2 설계 원칙

| 원칙 | 설명 | 적용 방식 |
|------|------|----------|
| **투명성** | 내 인증이 어디에 공유됐는지 항상 알 수 있어야 한다 | 파트너별 권한 목록 + 만료일 명시 |
| **통제권** | 유저가 언제든 공유를 철회할 수 있어야 한다 | 파트너 단위 revoke 버튼 |
| **안심** | 플랫폼이 만료 시점을 관리하고 있음을 보여준다 | 만료일 카운트다운, 만료 자동 처리 안내 |
| **신중한 액션** | 철회는 되돌릴 수 없으므로 확인 절차를 둔다 | 2단계 확인 다이얼로그 |

### 1.3 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---------|------|----------|
| 일반 유저 | 1~2개 파트너에 인증 제출 | 내 정보가 안전한지 확인 |
| 활발한 유저 | 5개+ 파트너 이벤트 참여 | 어떤 파트너가 뭘 보는지 한눈에 파악 |
| 이탈 예정 유저 | 서비스 사용 중단 | 모든 권한 일괄 철회 |

## 4. 상태 시각화

### 4.1 권한 상태별 표현

| 상태 | 조건 | 시각적 처리 |
|------|------|------------|
| **활성** | `valid_until > now()` | 기본 카드, Primary 아이콘 |
| **만료 임박** | `valid_until - now() ≤ 30일` | Warning 컬러 뱃지, `⚠️ D-N 곧 만료됩니다` |
| **만료됨** | `valid_until ≤ now()` | 그레이 텍스트, 접힌 섹션에 표시 |

### 4.2 인증 카테고리 아이콘

| 카테고리 | 아이콘 | 표시명 |
|---------|--------|--------|
| career | 💼 | 직장 인증 |
| academic | 🎓 | 학력 인증 |
| asset | 💰 | 자산 인증 |
| vehicle | 🚗 | 차량 인증 |
| marriage | 💍 | 결혼 상태 |
| etc | 📋 | 기타 인증 |

### 4.3 D-day 컬러 규칙

| 잔여일 | 컬러 | 비고 |
|--------|------|------|
| D-31+ | `onSurfaceVariant` | 기본 |
| D-30 ~ D-8 | `warning` (Amber) | 만료 임박 표시 |
| D-7 ~ D-1 | `error` (Red) | 긴급 표시 |
| D-0 이하 | `outline` (Grey) | 만료됨, 접힌 섹션으로 이동 |

## 5. 인터랙션 플로우

### 5.1 메인 플로우

```
MyPage → "개인정보" 탭
  │
  ├─ 로딩 → Skeleton shimmer (파트너 카드 2개 placeholder)
  │
  ├─ 데이터 로드 완료
  │    ├─ 활성 권한 있음 → 파트너별 그룹 카드 렌더링
  │    └─ 활성 권한 없음 → Empty State
  │
  └─ 에러 → SnackBar + 재시도 안내
```

### 5.2 권한 철회 플로우

```
[권한 철회] 버튼 탭
  │
  ├─ 확인 다이얼로그 표시
  │    ├─ "취소" → 다이얼로그 닫기
  │    └─ "철회하기" → API 호출
  │         │
  │         ├─ 성공 → SnackBar "권한이 철회되었습니다"
  │         │         → 목록 새로고침
  │         │         → 요약 카드 카운트 업데이트
  │         │
  │         └─ 실패 → handleMinglitError
  │
  └─ (파트너의 마지막 인증이면 파트너 카드 자체가 사라짐)
```

### 5.3 만료된 권한 토글

```
"만료된 권한 (N건)" 탭
  │
  ├─ 접힌 상태 → 펼치기 (ExpansionTile)
  └─ 펼친 상태 → 접기
      └─ 만료 항목은 read-only (철회 버튼 없음)
```

## 6. 데이터 소스

### 6.1 주요 쿼리

```sql
-- 유저의 모든 인증 열람 권한 조회 (파트너 정보 JOIN)
SELECT
  pvu.partner_id,
  p.brand_name,
  p.profile_image_url,
  pvu.verification_id,
  v.category,
  v.display_name,
  pvu.verified_at,
  pvu.valid_until,
  CASE
    WHEN pvu.valid_until <= now() THEN 'expired'
    WHEN pvu.valid_until <= now() + interval '30 days' THEN 'expiring_soon'
    ELSE 'active'
  END AS status
FROM partner_verified_users pvu
JOIN partners p ON p.id = pvu.partner_id
JOIN verifications v ON v.id = pvu.verification_id
WHERE pvu.user_id = auth.uid()
ORDER BY pvu.valid_until ASC;
```

### 6.2 Revoke API

```sql
-- 특정 파트너의 특정 인증 권한 철회
DELETE FROM partner_verified_users
WHERE partner_id = $1
  AND user_id = auth.uid()
  AND verification_id = $2;
```

### 6.3 RLS 고려사항

- `partner_verified_users` SELECT: 유저 본인 row만 조회 가능 (기존 RLS)
- DELETE: 유저 본인이 자신의 row를 삭제할 수 있는 정책 추가 필요

## 7. Phase별 구현 로드맵

### Phase 1: 조회 (프론트엔드 only)

| 작업 | 파일 | 설명 |
|------|------|------|
| Repository 메서드 | `minglit_kit/.../verification_repository.dart` | `getMyVerificationPermissions()` 추가 |
| PrivacyPage UI | `app_user/.../settings/privacy_page.dart` | placeholder → 실제 목록 UI |
| 요약 카드 | 동일 파일 | 활성 권한 수 + 만료 임박 수 |
| Empty State | 동일 파일 | 공유된 인증 없을 때 |
| 만료 섹션 | 동일 파일 | ExpansionTile로 접힌 상태 |

### Phase 2: Revoke

| 작업 | 파일 | 설명 |
|------|------|------|
| RLS 정책 추가 | `supabase/migrations/` | `partner_verified_users` DELETE 정책 |
| Repository 메서드 | `minglit_kit/.../verification_repository.dart` | `revokeVerificationPermission(partnerId, verificationId)` |
| 철회 다이얼로그 | `privacy_page.dart` | 2단계 확인 UI |
| 철회 후 피드백 | 동일 파일 | SnackBar + 목록 갱신 |
| 통합 테스트 업데이트 | `test/integration/flow_my_page_test.dart` | 기대값 업데이트 |
