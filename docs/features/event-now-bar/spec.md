# Event Now Bar 스펙

## 개요

유저앱 홈 하단에 **이벤트 나우바**를 표시하여, 당일 이벤트의 체크인 → 매칭 → 결과까지 실시간으로 안내하는 퍼시스턴트 UI.

### 핵심 원칙

- **패시브 모니터링**: 앱 어디에 있든 현재 이벤트 상태를 즉시 확인 가능 (Just Eat 미니바 패턴)
- **프로그레시브 디스클로저**: 나우바는 최소 정보만 표시, 탭하면 바텀시트로 상세 확장 (Uber 라이드 카드 패턴)
- **Dismiss 불가**: 이벤트 종료까지 자동 유지 (iOS Live Activity와 동일한 라이프사이클)
- **멀티 이벤트 스택**: 2개 이상 동시 이벤트 시 Samsung Now Bar 스택 패턴 적용

### 참고한 앱/트렌드

| 앱 | 참고 패턴 | 적용 포인트 |
|---|---|---|
| Uber (라이드 카드) | 상태별 카드 높이 변경 + 프로그레시브 디스클로저 | 나우바 상태 머신, 바텀시트 컨텐츠 밀도 |
| Just Eat Takeaway (주문 미니바) | 하단 퍼시스턴트 미니바 + 탭하면 풀 트래킹 | 나우바 위치와 인터랙션 모델 |
| Samsung Now Bar (One UI 7) | 멀티 활동 수직 캐러셀 스택 | 멀티 이벤트 스택 UX |
| iOS Live Activity | 시작~종료 자동 라이프사이클 + 서버 푸시 업데이트 | 나우바 활성/해제 조건 |
| 배달의민족 (주문현황) | 3~4단계 스텝 인디케이터 + ETA 중심 | 상태 머신 단순화 (5단계) |

## 유저 시뮬레이션

### 페르소나 1: 지현 (28세, 직장인, 첫 이벤트 참석)

**시나리오**: 토요일 저녁 소셜 이벤트. 전날 신청 완료, 당일 아침 앱 확인.

- 09:00 — 앱 열면 홈 피드 하단에 "오늘 19:00 · 강남 밍릿파티" 나우바 보임 → 안심
- 16:00 — 나우바 텍스트 "3시간 후 시작" → 준비 시작 알림 역할
- 18:50 — 도착, 나우바 탭 → QR 코드 바텀시트 표시 → 파트너가 스캔
- 18:52 — 체크인 완료, 나우바 "체크인 완료! 매칭 투표 대기 중" → 바텀시트가 매칭 화면으로 전환
- 19:30 — "매칭 투표 중 · 남은 8표" → 투표 진행
- 20:15 — "매칭 결과 발표!" 나우바 펄스 애니메이션 → 탭하면 결과 확인
- 20:30 — "오늘 이벤트 끝! 리뷰 작성하기" → 탭하면 리뷰 + 다음 이벤트 추천

**인사이트**: 첫 참석자에게 체크인 방법을 별도 안내 없이도 나우바가 자연스럽게 유도. QR이 바텀시트 안에 있어 진입점 고민 불필요.

### 페르소나 2: 민수 (33세, 이벤트 단골, 같은 날 2개 이벤트)

**시나리오**: 점심 브런치 이벤트 + 저녁 소셜 이벤트 모두 신청.

- 10:00 — 나우바에 "2개 이벤트" 배지, 기본은 가장 가까운 브런치 이벤트 표시
- 10:05 — 나우바 위로 스와이프 → 두 이벤트 카드가 아코디언으로 펼쳐짐
- 11:30 — 브런치 체크인 완료, 저녁 이벤트는 "19:00 시작" 대기
- 13:00 — 브런치 종료 → 나우바가 자동으로 저녁 이벤트로 전환 (스택에서 종료된 건 하단으로)
- 19:00 — 저녁 이벤트 활성 → 동일 플로우

**인사이트**: 멀티 이벤트 시 가장 시급한(현재 진행 중 > 가장 빠른 시작) 이벤트가 자동으로 상단에 올라와야 함. 종료된 이벤트는 즉시 사라지지 않고 "리뷰 작성" 상태로 하단 유지.

### 페르소나 3: 수진 (25세, 학생, 체크인 후 앱을 잘 안 봄)

**시나리오**: 체크인 후 이벤트에 몰입하다가 나중에 매칭 결과 확인.

- 19:00 — 체크인 완료 후 앱 백그라운드
- 19:45 — 매칭 투표 시작 시 푸시 알림 수신 (나우바와 별개)
- 20:00 — 앱 복귀 → 나우바 "매칭 투표 중 · 남은 10표" → 바로 투표 시작
- 20:30 — 다시 백그라운드 → 결과 발표 시 푸시 알림
- 21:00 — 앱 복귀 → 나우바 "매칭 결과 발표!" → 탭하면 결과

**인사이트**: 앱을 계속 보지 않는 유저를 위해 푸시 알림과 나우바의 역할 분리 필요. 나우바는 앱 내 진입점, 푸시는 앱 외부 알림. 앱 복귀 시 나우바가 최신 상태를 즉시 반영해야 함.

## 구성 요소

### 1. 나우바 (Persistent Mini Bar)

홈 화면 하단, BottomNavigationBar 바로 위에 고정되는 컴팩트 바.

```text
┌─────────────────────────────────────────────┐
│ 🟣 강남 밍릿파티 · 체크인 대기 중    19:00 → │
└─────────────────────────────────────────────┘
```

| 요소 | 설명 |
|---|---|
| 상태 인디케이터 (좌) | 컬러 dot — 상태별 색상 변경 |
| 이벤트명 (좌~중) | `titleSmall` (14px/bold), 1줄 말줄임 |
| 상태 텍스트 (중) | `bodySmall` (13px), 현재 단계 라벨 |
| 시간/CTA (우) | 시작 전: 시작 시간, 진행 중: 화살표 아이콘 |

**스타일**:
- 높이: 56px (버튼 높이와 동일)
- 배경: `surface` (`#F9FAFB`) + 상단 `elevation` shadow
- 좌우 패딩: `screenEdge` (20px)
- 내부 간격: `small` (8px)
- 라운딩: 상단만 `card` (16px), 하단 0
- 상태 dot: 8px circle, 컬러는 상태별 (아래 테이블)

**상태별 dot 색상**:

| 상태 | dot 색상 | 참조 토큰 |
|---|---|---|
| 대기 | `#4B5563` | `textSecondary` |
| 체크인 가능 | `#9900FF` | `primary` |
| 체크인 완료 | `#22C55E` | `success` |
| 매칭 투표 중 | `#FF9900` | `secondary` |
| 매칭 결과 | `#9900FF` | `primary` + pulse animation |
| 이벤트 종료 | `#4B5563` | `textSecondary` |

### 3. 멀티 이벤트 스택

2개 이상 활성 이벤트 시:

```text
┌─────────────────────────────────────────────┐
│ 🟣 강남 밍릿파티 · 체크인 중         2 ▼ │
└─────────────────────────────────────────────┘
```

- 우측에 이벤트 개수 배지 + 드롭다운 아이콘
- 탭 시 바텀시트에 이벤트 목록 → 선택 → 해당 이벤트 상세 시트

**정렬 우선순위**:
1. 현재 진행 중 (체크인~결과) > 시작 대기 > 종료
2. 같은 상태면 시작 시간 빠른 순

## 데이터 소스

### 신규 Provider

| Provider | 역할 | 소스 |
|---|---|---|
| `todayActiveEventsProvider` | 오늘 활성 이벤트 목록 (시작 3시간 전 ~ 종료) | Supabase `event_participants` JOIN `events` |
| `eventNowBarStateProvider(eventId)` | 이벤트별 나우바 상태 머신 | `event_participants.status` + `events.status` 조합 |
| `eventRealtimeProvider(eventId)` | Supabase realtime 구독 | `event_participants` 테이블 변경 감지 |

### 기존 Provider 재사용

| Provider | 용도 |
|---|---|
| `matchCandidatesProvider(eventId)` | 매칭 투표 후보 목록 |
| `myMatchesProvider(eventId)` | 매칭 결과 |
| `myVoteCountProvider(eventId)` | 투표 사용량 |
| `maxVoteCountProvider(eventId)` | 최대 투표 수 |

### 상태 머신

> **NOTE**: DB `events.status` 컬럼은 `scheduled`, `cancelled`, `completed` 값만 가진다.
> 매칭 관련 상태(MATCHING, RESULTS)는 `events.status`가 아니라
> `event_participants`, 매칭 후보/결과 테이블 등에서 파생하여 클라이언트 상태 머신이 결정한다.

```text
시작 3시간 전 도달
  │
  ▼
WAITING (대기) ─── event.startTime - 3h ≤ now
  │
  │ (시작 시간 도달)
  ▼
CHECK_IN_READY (체크인 가능) ─── event.startTime ≤ now
  │
  │ (event_participant.status = 'checked_in')
  ▼
CHECKED_IN (체크인 완료) ─── 매칭 투표 대기
  │
  │ (matchCandidatesProvider가 비어있지 않음 — 매칭 상태는 event_participants 및 매칭 관련 테이블에서 파생)
  ▼
MATCHING (매칭 투표 중) ─── 투표 진행
  │
  │ (myMatchesProvider 결과 존재 — 매칭 완료 여부는 매칭 결과 테이블에서 파생)
  ▼
RESULTS (매칭 결과) ─── 결과 확인
  │
  │ (events.status = 'completed')
  ▼
ENDED (종료) ─── 리뷰 작성 + 다음 추천
  │
  │ (24시간 경과 또는 리뷰 작성 완료)
  ▼
(나우바 해제)
```

### Supabase Realtime 구독

```dart
// event_participants 테이블 변경 감지
supabase.channel('event-now-bar')
  .onPostgresChanges(
    event: PostgresChangeEvent.update,
    schema: 'public',
    table: 'event_participants',
    filter: PostgresChangeFilter(
      type: PostgresChangeFilterType.eq,
      column: 'event_id',
      value: eventId,
    ),
    callback: (payload) => ref.invalidate(eventNowBarStateProvider(eventId)),
  )
  .subscribe();
```

## 라우트 변경

### 변경 없음 (기존 라우트 유지)

나우바는 라우트가 아닌 **위젯 레이어**로 구현. `UserShellRoute`의 `Scaffold` body 위에 오버레이.

### 신규 위젯 경로

```text
apps/app_user/lib/src/features/home/widgets/
├── event_now_bar.dart              ← 퍼시스턴트 미니바
├── event_now_bar_controller.dart   ← 상태 머신 + 로직
├── event_now_bottom_sheet.dart     ← 탭 시 확장 바텀시트
└── event_now_multi_stack.dart      ← 멀티 이벤트 스택 UI
```

### 네비게이션 통합

- 나우바 탭 → `showModalBottomSheet` (라우트 변경 아님)
- 바텀시트 내 "이벤트 상세 보기" → `EventCoordinator.pushEventDetail(eventId)`
- 바텀시트 내 "매칭 투표" → 바텀시트 내 임베드 (별도 push 아님)

| 상태 | 처리 |

| 상태 | 처리 |
