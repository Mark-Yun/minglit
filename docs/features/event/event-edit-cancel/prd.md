# PRD: 이벤트 수정·취소 (Event Edit & Cancel)

## Summary

파트너가 이미 생성한 이벤트의 핵심/부수 정보를 수정하거나, 이벤트를 취소하면서 참가자에게 자동으로 알림 + 전액 환불을 보장하는 기능. 이슈 #1396 (Blocked #1338 통합 테스트) 해결.

## Motivation / Problem to Solve

- 파트너가 이벤트를 만든 뒤 시간·장소·정원·제목 등을 변경할 UI 가 부재 — 일정 변경 시 이벤트 삭제 후 재생성 우회, 기존 결제자 손실
- 인원 미달 / 장소 문제 등으로 이벤트를 취소해야 할 때 참가자에게 자동 환불·알림이 가지 않음 — 운영팀 수동 처리
- Eventbrite 는 취소 시 전액 환불을 플랫폼이 강제. 미이행 파트너에게 플랫폼이 대신 환불 후 청구하는 수준의 강한 보호 제공 — 밍글릿은 이 수준의 신뢰 보장 부재
- 통합 테스트(#1338)도 본 기능 부재로 blocked

## Goals

### Target Users

- **파트너 (수정자)**: 일정 / 장소 / 정원 등을 변경해야 하는 상황
- **파트너 (취소자)**: 인원 미달, 시설 문제, 개인 사정 등으로 이벤트를 취소해야 하는 상황
- **유저 (참가자)**: 변경된 정보를 즉시 알아야 하는 확정 참가자 / 결제 완료자

### Key Goals

- **P0**: 모든 핵심 필드(시작·종료·장소) + 부수 필드(제목·설명·이미지·정원) 수정 가능
- **P0**: 핵심 필드(시간 / 장소) 변경 시 확정 참가자에게 자동 푸시 + 인앱 알림
- **P0**: 이벤트 취소 시 유료 참가자 전원 전액 자동 환불 (Eventbrite 수준 강제)
- **P0**: 취소는 불가역 + 2단계 확인 (실수 방지)
- **P1**: 부수 필드(제목 / 설명 / 이미지 / 정원) 변경은 알림 없이 조용히 반영 (알림 피로 방지)
- **P1**: 정원 줄이기는 현재 참가자 수 이상만 허용 (좌석 손실 방지)

### Non-Goals

- 이벤트 복제 (취소 후 신규 생성 자동화) — 후속 피처
- 수정 이력 조회 화면 — 현재 필요성 낮음
- 반복 이벤트 시리즈 일괄 편집 — `recurring-events` feature 범위
- 취소 이메일 커스터마이즈 (Luma 패턴) — V2
- 부분 환불 — `refund-policy-v2` 범위
- 이벤트 연기(postpone) 별도 액션 — 수정으로 충분히 대응 가능

## Product Principles

1. **파트너 자율성**: 자기 이벤트는 자유롭게 수정·취소 가능. 플랫폼이 막지 않음
2. **참가자 보호**: 유료 이벤트 취소 = 전액 자동 환불 강제 (Eventbrite 패턴)
3. **투명한 알림**: 일정 / 장소만 알림 발송. 부수 정보 변경은 알림 없음 (피로 방지)
4. **불가역 취소**: 2단계 확인. 한 번 취소된 이벤트는 복구 불가
5. **기존 흐름 재사용**: 이벤트 생성 화면을 편집 모드로 재사용 — 학습 비용 0

## Technical Approach

- **화면 (파트너)**: 이벤트 편집 화면(생성 화면 재사용), 핵심 변경 확인 다이얼로그, 취소 사유 바텀시트, 최종 취소 확인 다이얼로그
- **화면 (유저)**: 취소된 이벤트 상세에서 "취소됨" 상태 표시
- **저장**: `events` 테이블 metadata 에 취소 사유 저장, `event_applications` 에 취소 상태 추가
- **외부 의존성**: PortOne(결제 취소), 푸시 알림, 인앱 알림
- **가드**: 파트너 권한 검증, 이벤트 상태(scheduled/active) 검증, 정원 감소 시 현재 참가자 수 검증

## User Journey

### Scenario 1: 파트너가 핵심 정보 수정 (CUJ 1-x)

파트너가 이벤트 상세에서 수정 진입 → 시간 / 장소 변경 → 확인 다이얼로그(변경 내용 + 참가자 수 표시) → 저장 → 확정 참가자에게 자동 알림.

### Scenario 2: 파트너가 부수 정보 수정 (CUJ 2-x)

파트너가 제목 / 설명 / 이미지 / 정원만 변경 → 저장 → 알림 없이 조용히 반영.

### Scenario 3: 파트너가 참가자 있는 이벤트 취소 (CUJ 3-x)

파트너가 취소 진입 → 사유 선택(선택) → 최종 확인 다이얼로그(환불 총액 + 정산 차감 안내) → 취소 → 유료 참가자 전원 전액 자동 환불 + 모든 참가자에 알림.

### Scenario 4: 파트너가 참가자 없는 이벤트 취소 (CUJ 4-x)

신청자 0명 상태에서 취소 → 환불 / 알림 없이 상태만 변경.

## Data Flow

### Scenario 1

이벤트 상세 → 수정 진입 → 이벤트 생성 화면 편집 모드(기존 값 프리필) → 핵심 필드 변경 → 저장 시 확인 다이얼로그 → 확정 후 서버에 변경 전송 → 핵심 필드 변경 감지 → 확정 참가자에게 푸시 + 인앱 알림

### Scenario 2

이벤트 상세 → 수정 진입 → 부수 필드만 변경 → 저장 → 서버에서 핵심 변경 없음 판정 → 알림 발행 없이 갱신 완료

### Scenario 3

이벤트 상세 → 취소 진입 → 사유 바텀시트 → 최종 확인 다이얼로그(환불 총액 노출) → 확정 → 서버에서 유료 참가자 PortOne 결제 취소 일괄 처리 → 신청 상태 일괄 취소 → 이벤트 상태 취소 → 알림 발행 (참가자 / 환불 완료 안내)

### Scenario 4

이벤트 상세 → 취소 진입 → 최종 확인 다이얼로그(환불 / 알림 안내 없음) → 확정 → 이벤트 상태 취소

## KPIs / Success Metrics

- **취소 후 환불 완료율** ≥ 99% (PortOne 호출 성공 / 시도)
- **수정 시 알림 도달률** ≥ 95% (푸시 + 인앱)
- **수정 우회율 감소**: V1 이전 "이벤트 삭제 후 재생성" 운영팀 케이스 baseline 대비 80% 감소
- **취소 실수율**: 취소 후 24h 내 운영팀 "복구 요청" 케이스 < 1%
- **블로커 #1338 close**: 통합 테스트 통과

## Launch Strategy

전체 파트너 일괄 활성. 점진 출시 / A/B 없음 — 운영 필수 기능.
