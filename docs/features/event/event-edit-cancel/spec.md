## Functional Requirements

- **FR-1**: 파트너는 이벤트 상세에서 수정 진입점(우측 상단 수정 아이콘)으로 편집 화면 진입. 기존 이벤트 데이터가 폼에 프리필.
- **FR-2**: 핵심 필드(시작 시간 / 종료 시간 / 장소) 중 하나라도 변경된 상태에서 저장 시, 변경 전 → 후 diff + 영향 받는 확정 참가자 수를 표시하는 확인 다이얼로그 노출. "변경하기" 확정 시에만 저장 진행.
- **FR-3**: 핵심 필드 변경 저장 성공 시 확정 상태 참가자 전원에게 푸시 + 인앱 알림 발송. 알림 본문에 변경된 항목 명시.
- **FR-4**: 부수 필드(제목 / 설명 / 이미지 / 연락처 / 메타데이터 / 정원) 만 변경 시 확인 다이얼로그 미표시, 알림 발송 없음.
- **FR-5**: 정원 변경 시 현재 참가자 수보다 작은 값으로 변경 시도 → 인라인 에러 메시지 + 저장 차단.
- **FR-6**: 수정 불가 필드 — 파티 ID / 이벤트 상태 / 티켓. 별도 흐름으로만 변경 가능 (티켓 편집은 별도 화면).
- **FR-7**: 핵심 변경 확인 다이얼로그의 Primary CTA 는 보조 강조 색, Secondary CTA 는 "취소". 다이얼로그 dismiss 시 편집 화면으로 복귀 + 변경 내용 유지.
- **FR-8**: 이벤트 취소는 상태가 scheduled 또는 active(체크인 시작 전) 인 경우만 가능. ongoing / completed / cancelled 는 취소 진입점 비노출.
- **FR-9**: 취소 시 사유 선택은 선택 항목. 사유 코드 4종(인원 미달 / 개인 사정 / 장소 문제 / 기타) + 기타 자유 입력. 사유는 CS 분석용으로 저장.
- **FR-10**: 최종 취소 확인 다이얼로그 — 참가자 ≥ 1명 시 환불 총액(유료 참가자 × 결제 금액 합계) + 정산 차감 안내 표시. 참가자 0명 시 환불 / 알림 없이 취소된다는 안내 표시.
- **FR-11**: 취소 확정 시 유료 참가자(결제 완료 상태) 전원에 대해 PortOne 결제 취소 일괄 실행. 무료 참가자는 결제 호출 없이 신청 상태만 취소로 변경.
- **FR-12**: 취소 확정 후 이벤트 상태 취소로 전환. 이벤트 상세에 "취소됨" 배지 표시, 수정 / 취소 버튼 비활성, 신규 신청 차단, 피드 노출 제거.
- **FR-13**: 취소 확정 시 모든 참가자(확정 + 대기) 에게 푸시 + 인앱 알림 발송. 결제한 참가자에게는 환불 완료 시 추가 알림(환불 금액 + 영업일 3일 내 입금 안내).
- **FR-14**: 무료 이벤트 또는 참가자 0명 이벤트 취소 시 PortOne 호출 없이 상태만 변경. 결제 시스템 무관.

## Non-Functional Requirements

- **NFR-1**: 편집 화면 진입 → 폼 프리필 완료 p50 < 300ms (에뮬레이터 baseline). 저장 → 응답 p50 < 800ms (네트워크 정상).
- **NFR-2**: 알림 발송 — 저장 확정 → 푸시 도착까지 p95 < 30초.
- **NFR-3**: 취소 확정 → PortOne 결제 취소 일괄 처리 성공률 ≥ 99% (월간 baseline). 일부 실패 시 재시도 큐 + 운영팀 알림.
- **NFR-4**: 취소 처리 전체 소요 — 참가자 ≤ 50명 기준 p95 < 10초. 50명 초과 시 비동기 처리 + 진행 안내.
- **NFR-5**: 환불 입금 — 영업일 기준 3일 내 (전자상거래법 제18조).
- **NFR-6**: 취소 중 부분 실패 발생 시 데이터 일관성 — 이벤트는 취소 상태로 전환되더라도 실패한 환불 건은 자동 재시도 큐에 적재 (운영팀 알림).

## Edge Cases

| CUJ ID | 케이스 | 기대 동작 |
|--------|--------|----------|
| 1-1 | 저장 중 네트워크 끊김 | 재시도 1회 → 실패 시 "저장에 실패했어요. 다시 시도해주세요" 스낵바. 변경 내용 유지 |
| 1-1 | 핵심 변경 다이얼로그 확정 직전 이벤트가 ongoing 으로 전환 | 서버 재검증 → "이벤트가 이미 시작되어 수정할 수 없어요" 안내 + 화면 새로고침 |
| 1-3 | 동일 필드 여러 번 변경 후 저장 | 최종 값만 저장 + diff 표시 |
| 2-2 | 정원 증가 후 즉시 신청 들어옴 | 별도 알림 없음 (부수 변경). 신청은 정상 수용 |
| 2-3 | 정원 줄이기 시도 중 동시에 참가자 1명 추가됨 | 서버 재검증 → 최신 참가자 수 기준 재판정. 여전히 미만이면 에러 |
| 3-1 | 취소 처리 중 일부 PortOne 환불 실패 | 이벤트는 취소 상태로 전환. 실패 건만 재시도 큐 적재 + 운영팀 알림. 유저에 "일부 환불이 지연되고 있어요. 자동으로 재시도돼요" 스낵바 |
| 3-1 | 취소 처리 중 앱 kill | 서버에서 트랜잭션 보장 — 재진입 시 이미 취소된 상태 반영 |
| 3-2 | 취소 후 동일 이벤트 재취소 시도 | 진입점 비노출. 강제 호출 시 서버에서 거부 |
| 3-3 | 사유 미선택 후 다음 | "다음" 활성 — 사유는 선택 항목 |
| 4-1 | 참가자 0명인데 환불 호출 잘못 트리거 | 서버 분기로 차단 — PortOne 호출 안 함 |
| 4-2 | 유저앱에서 취소된 이벤트 결제 시도(딥링크) | 결제 진입 차단 + "취소된 이벤트입니다" 안내 |

## 화면 구성 (참고)

### 화면 1: 이벤트 편집 화면

이벤트 생성 화면을 편집 모드로 재사용 (`eventId` 파라미터 유무로 모드 분기). 기존 값 프리필 + 변경 감지.

**진입점**: 이벤트 상세 우측 상단 수정 아이콘.


### 취소 후 상태 (참고)

| 항목 | 동작 |
|------|------|
| 이벤트 상태 | scheduled → cancelled |
| 이벤트 상세 | "취소됨" 배지 표시, 수정 / 취소 버튼 비활성 |
| 피드 노출 | 제거 |
| 참가자 알림 | 전원에게 푸시 + 인앱 알림 |
| 유료 참가자 | 전액 자동 환불 |
| 무료 참가자 | 상태만 변경 |
| 신규 신청 | 차단 |

### 알림 트리거 (참고)

| 이벤트 | 알림 대상 | 알림 제목 | 알림 본문 |
|--------|----------|----------|----------|
| 핵심 정보 수정 (시간 / 장소) | 참가 확정자 | "이벤트가 변경됐어요" | "{이벤트명}의 {변경항목}이(가) 변경됐어요. 확인해보세요." |
| 이벤트 취소 | 참가 확정자 + 대기자 | "이벤트가 취소됐어요" | "{이벤트명}이(가) 취소됐어요. {환불 안내}" |
| 유료 이벤트 환불 완료 | 결제한 참가자 | "환불이 완료됐어요" | "{이벤트명} 환불 {금액}원이 처리됐어요. 영업일 기준 3일 내 입금돼요." |
