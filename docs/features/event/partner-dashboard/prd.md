# PRD: 파트너 대시보드 리디자인 (Partner Dashboard)

## Summary

파트너앱의 홈 화면과 바텀 네비게이션을 "오늘 할 일 먼저, 통계 나중" 원칙으로 재구성한다. 파티 관리 / 통계 중심의 기존 구조를 신청 처리 / 체크인 등 일상 업무 진입점 중심으로 전환.

## Motivation / Problem to Solve

- 파트너의 일상 업무는 (a) 신규 신청 승인, (b) 오늘 이벤트 체크인, (c) 정산 확인 — 하지만 현재 홈은 파티 관리 / 통계 위주로 일상 진입점이 깊숙이 묻혀 있음
- 신청 관리 진입에 2-3 탭 필요 → 파트너 페인 (에어비앤비 호스트앱처럼 일상 업무가 1탭 거리여야 함)
- 신규 파트너 온보딩 가이드 부재 — 가입 후 "뭐부터 해야 하지?" 이탈
- 유저앱과 파트너앱이 동일 메인 컬러를 사용 → 파트너가 자기 앱이라는 정체성 약함

## Goals

### Target Users

- **활성 파트너**: 매일 신청 승인 / 체크인 / 정산 확인이 일상 업무
- **신규 파트너**: 가입 후 첫 파티 / 첫 이벤트 생성까지 단계별 가이드 필요
- **다중 이벤트 운영 파트너**: 여러 이벤트가 동시 진행 중일 때 가장 시급한 것을 우선 노출 받고 싶음

### Key Goals

- **P0**: 바텀 네비게이션 4탭 → 5탭 재구성 (홈 / 신청관리 / 체크인 / 정산 / 더보기)
- **P0**: 홈 대시보드를 "오늘 할 일 칩 + 이벤트 액션카드 + 이번 주 성과" 3-블록으로 재구성
- **P0**: 가장 가까운 이벤트 1건을 phase 별(모집 중 / 준비 중 / LIVE / 종료) 자동 분기하여 액션카드 표시
- **P0**: 신청관리 탭에서 이벤트별 그루핑 + 인라인 승인/거절
- **P0**: 체크인 탭에 진입 시 오늘 진행 중/예정 이벤트가 1개면 즉시 QR 스캐너, 2개+ 면 선택 바텀시트
- **P1**: 신규 파트너 온보딩 스텝 가이드 (파티 0개 / 파티만 있음 두 단계)
- **P1**: 파트너 전용 컬러 테마 (유저앱 보라와 차별화된 톤다운 보라)
- **P1**: 섹션별 독립 provider 로딩 (한 섹션 실패가 대시보드 전체를 차단하지 않음)

### Non-Goals

- 미답변 리뷰 칩 실데이터 연결 — 리뷰 시스템 미구현, "준비 중" 라벨만
- 알림 센터 통합 (별도 feature)
- 대시보드 위젯 커스터마이즈 (V2)
- 다국어 — 한국어만

## Product Principles

1. **오늘 할 일 우선**: 신청 승인 / 체크인 등 일상 업무를 1탭 거리. 통계는 보조
2. **시점 기반 자동 분기**: 이벤트 phase 에 따라 액션 버튼 자동 변경 — 파트너가 "지금 뭘 해야 하지" 고민하지 않음
3. **알림 피로 최소**: 부수 정보(정원 / 설명) 변경은 알림 없음. 일정 / 장소만 알림
4. **섹션 독립 로딩**: 한 섹션 실패가 다른 섹션을 막지 않음
5. **온보딩 단계화**: 신규 파트너 진행률 시각화 — 한 화면에 모든 단계 + 다음 액션 명시

## Technical Approach

- **화면 (파트너)**: 새 홈 대시보드 (인사 + 할 일 칩 3개 + 이벤트 액션카드 + 이번 주 성과), 신청 관리 탭, 체크인 탭, 정산 탭(매출 요약 카드 추가), 더보기 탭
- **온보딩**: 파티 0개 → 스텝 가이드(파티 만들기 유도), 파티 1+/이벤트 0개 → 이벤트 넛지
- **이벤트 phase 분기**: 시간 기반 클라이언트 derived (모집중 / 준비중 / LIVE / 종료)
- **저장**: 신규 테이블 없음. 신청 승인 / 거절 액션 추가, 주간 집계 read API 추가
- **외부 의존성**: 신청 승인 / 거절 EF, 주간 집계 RPC
- **테마**: 파트너앱 colorScheme override (Primary `#6C3CE1` 톤다운 보라)

## User Journey

### Scenario 1: 파트너 일일 진입 → 오늘 할 일 확인 (CUJ 1-x)

파트너가 앱 진입 → 인사 영역에서 "오늘 할 일 N건" 확인 → 할 일 칩 탭하여 해당 화면으로 즉시 이동.

### Scenario 2: 가장 가까운 이벤트의 phase 별 액션 (CUJ 2-x)

홈 대시보드의 이벤트 액션카드에 다가오는 이벤트가 phase(모집중/준비중/LIVE/종료) 별로 자동 분기된 CTA 표시.

### Scenario 3: 신청관리 탭에서 일괄 처리 (CUJ 3-x)

신청관리 탭 → 대기중 탭 → 이벤트별 그루핑된 신청 목록 → 인라인 승인 / 거절 또는 하단 전체 승인.

### Scenario 4: 체크인 탭에서 즉시 QR 스캐너 (CUJ 4-x)

오늘 이벤트가 1개면 체크인 탭 진입 = 즉시 QR 스캐너. 2개+ 면 이벤트 선택 바텀시트.

### Scenario 5: 신규 파트너 온보딩 (CUJ 5-x)

가입 직후 파트너 → 홈 진입 → 스텝 가이드 표시 → "첫 파티 만들기" → 파티 생성 후 이벤트 넛지로 자동 전환.

## Data Flow

### Scenario 1

홈 진입 → 할 일 칩 데이터 로드 (승인 대기 수 / 다가오는 이벤트 수 / 미답변 리뷰 수 — 칩별 독립 provider) → 표시 → 탭 시 해당 탭으로 이동

### Scenario 2

홈 진입 → 다가오는 / 진행 중 / 종료 24h 이내 이벤트 조회 → phase 우선순위로 1건 선택(live > preparing > ended > recruiting) → 카드 + 시점별 액션 버튼 표시

### Scenario 3

신청관리 탭 → 이벤트별 그루핑 신청 목록 → 인라인 승인/거절 액션 → 서버에서 신청 상태 변경 + 부수 효과(결제 트리거 / 알림) → 목록 갱신

### Scenario 4

체크인 탭 진입 → 오늘 진행 중/예정 이벤트 카운트 → 1개면 QR 스캐너 자동 진입 / 2개+ 면 바텀시트 → 선택 후 스캐너

### Scenario 5

홈 진입 → 파티 수 / 이벤트 수 조회 → 파티 0개면 스텝 가이드 / 파티 1+ / 이벤트 0개면 이벤트 넛지 / 이벤트 1+ 면 일반 대시보드

## KPIs / Success Metrics

- **신청 승인까지 평균 클릭 수**: 기존 3-4클릭 → 2클릭 이하 (신청관리 탭 인라인)
- **체크인 진입 시간**: 기존 2-3 탭 → 1탭 (또는 1탭 + 선택)
- **신규 파트너 첫 파티 생성률**: 가입 후 7일 내 60% 이상 (현재 baseline 대비)
- **신규 파트너 첫 이벤트 생성률**: 첫 파티 생성 후 7일 내 50% 이상
- **대시보드 부분 로딩 성공률**: 한 섹션 실패 시 나머지 섹션 100% 정상 표시

## Launch Strategy

전체 파트너 일괄 적용 (점진 출시 없음). 기존 사용자에게는 인앱 안내 노티 1회.
