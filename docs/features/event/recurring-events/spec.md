## Functional Requirements

- **FR-1**: 이벤트 생성 화면에 "반복 설정" 섹션 추가. 기본값 OFF. ON 시에만 주기 / 요일 / 종료 입력 노출.
- **FR-2**: 주기 선택 — 매주 / 격주 / 매월 / 커스텀 4종. 커스텀은 V2 (placeholder 만 표시 + 비활성).
- **FR-3**: 매주 / 격주 선택 시 요일 선택 (월 ~ 일 다중 선택). 매월 선택 시 매월 N일 또는 "매월 N번째 X요일" 패턴 선택.
- **FR-4**: 종료 조건 — 무기한 또는 종료일 지정. 종료일은 날짜 선택기로 입력.
- **FR-5**: 입력 변경 시 실시간 미리보기 — 1개월 윈도우 내 생성될 날짜 목록 표시. "총 N회 자동 생성" 안내. 종료일이 1개월 이내면 그 날짜까지만.
- **FR-6**: 저장 확정 시 서버에 규칙 저장 + 1개월 윈도우 내 이벤트 일괄 생성.
- **FR-7**: 자동 생성된 각 이벤트는 파티 템플릿에서 복제 — 입장 조건 / 티켓 / 제목 / 설명 / 이미지 / 장소 / 정원 / 연락처 / 공개 여부. 단일 이벤트 생성과 동일 복제 범위.
- **FR-8**: 생성된 이벤트는 파티 상세의 이벤트 목록에 시간 순으로 노출. 반복 규칙 참조 컬럼 유지.
- **FR-9**: 자동 생성된 회차도 개별 수정 / 취소 가능. 수정 시 시리즈 예외 플래그 ON (해당 회차만 변경, 다른 회차에 영향 없음).
- **FR-10**: 개별 회차 편집은 단일 이벤트 편집과 동일 흐름 (`event-edit-cancel` feature 의 편집 흐름 재사용).
- **FR-11**: 개별 회차 취소는 단일 이벤트 취소와 동일 흐름. 시리즈 전체에 영향 없음.
- **FR-12**: 파티 상세 이벤트 목록에서 반복 규칙으로 생성된 이벤트에는 반복 아이콘(🔄) + 패턴 라벨(예: "매주") 표시.
- **FR-13**: 반복 규칙 관리 화면에서 일시정지 / 재개 / 규칙 수정 / 반복 해제 액션 노출.
- **FR-14**: 일시정지 — 규칙 상태 변경 → 다음 크론부터 새 이벤트 생성 안 함. 기존 생성된 이벤트는 그대로 유지 (취소되지 않음).
- **FR-15**: 재개 — 규칙 활성 복원 + 즉시 1개월 윈도우 부족분 일괄 생성.
- **FR-16**: 규칙 수정 — 주기 / 요일 / 종료 조건 변경 가능. 이미 생성된 이벤트는 변경 없음.
- **FR-17**: 규칙 수정 후 다음 크론부터 새 규칙으로 부족분 생성. 기존 생성분이 새 규칙과 충돌해도(예: 요일 변경) 자동 삭제하지 않음.
- **FR-18**: 반복 해제 — 확인 다이얼로그(불가역 안내) 후 규칙 종료. 새 이벤트 생성 영구 중단. 기존 생성분은 유지.
- **FR-19**: 매일 KST 새벽 시간대 크론으로 활성 규칙 순회. 각 규칙별 마지막 생성일 ~ 1개월 윈도우 부족분 계산 후 일괄 생성.
- **FR-20**: 1개월 윈도우는 슬라이딩 — 매일 1일치씩 앞으로 이동. 미래 생성된 이벤트가 1개월 이내에 항상 채워져 있음.
- **FR-21**: 크론 실행 실패 시 Sentry 에러 + 다음 주기에서 보강. 유저에게 노출하지 않음.

## Non-Functional Requirements

- **NFR-1**: 반복 설정 입력 / 미리보기 갱신 — 클라이언트 연산 p50 < 50ms (저사양 기기). 미리보기 표시 100ms 이내.
- **NFR-2**: 1개월 윈도우 일괄 생성 응답 — p95 < 5초 (최대 ~30회 생성 가정). 비동기 처리 + 진행 안내.
- **NFR-3**: 일시정지 / 규칙 수정 / 해제 액션 — p50 < 800ms (상태 변경만, 이벤트 생성 없음).
- **NFR-4**: 크론 실행 누락률 < 1% (월간). 누락 시 다음 주기 보강. Sentry 알림 → 운영팀.
- **NFR-5**: 동시 활성 규칙 1,000개 기준 크론 1회 처리 < 10분 (서버 baseline).

## Edge Cases

| CUJ ID | 케이스 | 기대 동작 |
|--------|--------|----------|
| 1-1 | 매주 ON 인데 요일 0개 선택 | 미리보기 빈 상태 + "요일을 1개 이상 선택해주세요" 인라인 안내. 저장 비활성 |
| 1-2 | 종료일이 시작일보다 과거 | "종료일이 시작일 이후여야 해요" 인라인 에러. 저장 비활성 |
| 1-2 | 종료일이 1개월 이내 + N건만 생성 | 미리보기에 종료일까지만 표시. "총 N회 자동 생성" 정확 표시 |
| 1-3 | 저장 도중 네트워크 끊김 | 재시도 1회 → 실패 시 "반복 이벤트 생성에 실패했어요. 다시 시도해주세요" 스낵바. 부분 생성된 이벤트는 롤백 |
| 1-3 | 저장 도중 일부 이벤트 생성 실패 (DB 충돌) | 트랜잭션 보장 — 전부 성공 or 전부 실패. 실패 시 운영팀 알림 |
| 2-1 | 개별 수정 후 동일 시점에 크론이 같은 날짜 신규 생성 시도 | 시리즈 예외 플래그가 있으면 중복 생성 안 함 (날짜 + 규칙 ID 유니크) |
| 2-2 | 개별 회차 취소 후 크론이 같은 날짜에 재생성 시도 | 동일 날짜 + 규칙 ID 로 이미 존재(취소 상태)하면 재생성 안 함 |
| 3-1 | 일시정지 시점에 크론이 이미 실행 중 | 해당 cron 실행은 완료 후, 다음 cron 부터 일시정지 반영 |
| 3-3 | 규칙 수정 후 기존 이벤트와 새 규칙 충돌 (예: 요일 다름) | 기존 이벤트 유지 + 새 규칙은 다음 미생성 윈도우부터 적용. 사용자에 "기존 N건은 그대로 유지됩니다" 안내 |
| 3-4 | 반복 해제 후 동일 파티에 새 반복 규칙 생성 | 가능 (별개 규칙). 기존 생성분과 신규 규칙 이벤트가 공존 |
| 4-1 | 크론 실행 중 일부 규칙 실패 | 실패 규칙만 다음 주기 재시도. 성공 규칙은 정상 반영 |
| 4-1 | 크론이 자정 정확히 실행 안 됨 (서버 부하) | 다음 가능 시점 즉시 실행. 누락분 자동 보강 |
| 4-2 | 크론이 24h 이상 누락 | Sentry critical alert → 운영팀 수동 트리거 |

### 반복 관리 액션 (참고)

| 액션 | 동작 | 비고 |

### 데이터 정의 (참고)

| 항목 | key | 설명 |
|------|-----|------|
| 반복 규칙 | `recurrence_rules` | 파티별 반복 패턴 정의 |
| 패턴 | `pattern` | `weekly` / `biweekly` / `monthly` |
| 요일 | `days_of_week` | 1=월 ~ 7=일 |
| 매월 N일 | `month_day` | 매월 N일. null 이면 "매월 N번째 X요일" 패턴 |
| 시작 시각 | `start_time` | 이벤트 시작 시간 (시간 부분) |
| 종료 시각 | `end_time` | 이벤트 종료 시간 (시간 부분) |
| 반복 종료일 | `end_date` | null = 무기한 |
| 규칙 상태 | `status` | `active` / `paused` / `cancelled` |

| 시리즈 예외 플래그 | `events.is_recurrence_exception` | 개별 수정된 회차 |
