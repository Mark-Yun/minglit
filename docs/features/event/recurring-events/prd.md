# PRD: 반복 이벤트 (Recurring Events)

## Summary

파트너가 정기적으로 운영하는 파티(매주 금요 와인파티 / 격주 토요 독서모임 / 매월 마지막 토요 클럽파티 등)에 대해 반복 규칙을 한 번 설정하면, 시스템이 최대 1개월 앞까지 이벤트를 자동 생성한다. 이슈 #1002 해결.

## Motivation / Problem to Solve

- 매주 / 격주 / 매월 동일 파티를 운영하는 파트너가 매번 이벤트를 수동으로 생성 — 깜빡 누락 시 신청 받지 못함
- 현재 데이터 모델은 개별 이벤트만 존재 — "시리즈" 개념 부재
- Party → Event 1:N 관계는 이미 템플릿 구조로 잘 잡혀 있으나 자동화 미연결
- 페르소나 1(바 오너): "매번 같은 내용인데 일일이 만들어야 해서 까먹을 때가 있다"
- 페르소나 2(북카페): "반복이라도 매번 책이 다른데, 자동 생성되면 제목 / 설명 수정이 번거롭지 않을까?" → 개별 이벤트 편집 가능해야 함

## Goals

### Target Users

- **정기 운영 파트너**: 매주 / 격주 / 매월 동일 시간 / 장소에서 파티 운영
- **회차별 변형이 필요한 파트너**: 책 / DJ / 가격 등 회차별 일부 정보가 다른 경우 — 자동 생성 후 개별 수정

### Key Goals

- **P0**: 반복 규칙 설정 UI (주간 / 격주 / 매월 + 요일 + 종료 조건)
- **P0**: 설정 즉시 최대 1개월 앞까지 이벤트 배치 자동 생성
- **P0**: 자동 생성된 이벤트도 개별 수정 / 취소 가능 (시리즈에서 분리)
- **P0**: 미리보기 — 생성될 이벤트 날짜 목록 사전 표시
- **P0**: 파티 템플릿(`entry_groups`, `tickets`, 이미지 등) 자동 복제
- **P1**: 일시정지 / 재개 / 규칙 수정 / 반복 해제 액션
- **P1**: 매일 새벽 KST 크론으로 1개월 윈도우 유지 (last_generated 부터 부족분 채움)

### Non-Goals

- **3-way 편집** (이것만 / 이후 모두 / 전체) — V1 은 "이 이벤트만" 단일 모드. Google Calendar 패턴은 V2
- **시리즈 전체 취소** — V1 은 반복 해제 후 미래 미생성. 기존 생성분은 개별 취소
- **회차별 가격 / 정원 오버라이드 규칙** — V1 은 생성 후 개별 편집만. 슬롯별 커스텀은 V2
- **무제한 반복** — 최대 1개월 윈도우. 3개월 / 무제한은 데이터 폭증 우려로 V2 검토
- **시리즈 구독 / 캘린더 노출 (Luma 패턴)** — V2

## Product Principles

1. **템플릿 상속**: 파티가 이미 템플릿 역할 — 신규 복제 로직 추가 없이 재사용
2. **개별 자율성**: 자동 생성 이벤트도 개별 수정 / 취소 가능 — 시리즈 잠금 없음
3. **제한된 미래**: 최대 1개월 — 데이터 폭증 / 미사용 이벤트 누적 방지
4. **점진적 복잡도**: V1 은 단순 패턴(매주 / 격주 / 매월)만. 고급 RRULE / 3-way 편집은 V2
5. **사전 가시성**: 설정 즉시 미리보기로 생성될 날짜 확인 — "내가 뭘 만들지" 명확

## Technical Approach

- **화면 (파트너)**: 이벤트 생성 화면에 "반복 설정" 섹션 추가 (주기 / 요일 / 종료 조건 / 미리보기), 파티 상세에 반복 이벤트 목록 + 반복 관리 액션, 반복 규칙 관리 화면
- **저장**: 신규 테이블 `recurrence_rules` (파티 ID, 패턴, 요일, 시간, 종료 조건, 상태, 마지막 생성일), `events` 에 반복 규칙 참조 컬럼 + 예외 플래그 추가
- **자동 생성**: 규칙 생성 즉시 1개월 윈도우 배치 생성. 매일 새벽 KST 크론으로 부족분 보강
- **복제 범위**: 파티 템플릿 → 이벤트 생성 시의 기존 복제 로직 재사용 (입장 조건 / 티켓 / 제목 / 설명 / 이미지 / 장소 / 정원 / 연락처 / 공개 여부)
- **외부 의존성**: pg_cron (배치 생성), 기존 파티 → 이벤트 복제 로직

## User Journey

### Scenario 1: 반복 규칙 설정 → 즉시 1개월분 자동 생성 (CUJ 1-x)

파트너가 이벤트 생성 화면에서 반복 설정 ON → 주기 / 요일 / 종료 선택 → 미리보기 확인 → 저장 시 1개월 윈도우 내 이벤트 일괄 생성.

### Scenario 2: 자동 생성된 개별 이벤트 수정 (CUJ 2-x)

파트너가 파티 상세에서 자동 생성된 회차 1건을 선택 → 편집 화면에서 제목 / 설명 / 가격 수정 → 해당 회차만 변경 (시리즈 분리).

### Scenario 3: 반복 관리 — 일시정지 / 규칙 수정 / 해제 (CUJ 3-x)

파트너가 반복 규칙 관리 화면 진입 → 일시정지(새 생성 중단) / 규칙 수정(미래 미생성분에만 반영) / 반복 해제(완전 종료) 액션.

### Scenario 4: 매일 크론으로 1개월 윈도우 유지 (CUJ 4-x)

매일 새벽 KST 크론 → 활성 규칙별로 마지막 생성일부터 1개월 윈도우 부족분 자동 채움.

## Data Flow

### Scenario 1

이벤트 생성 화면 → 반복 ON → 주기 / 요일 / 종료 입력 → 미리보기 계산(클라이언트) → 저장 시 서버에 규칙 + 이벤트 생성 요청 → 규칙 저장 + 1개월 윈도우 이벤트 일괄 생성(파티 템플릿 복제) → 파티 상세에 반복 이벤트 목록 노출

### Scenario 2

파티 상세 → 반복 이벤트 목록에서 1건 선택 → 편집 화면 → 변경 → 저장 → 서버에서 해당 이벤트만 변경 + 시리즈 예외 플래그 ON → 다른 회차에는 영향 없음

### Scenario 3

파티 상세 → 반복 관리 액션 → 일시정지 / 규칙 수정 / 해제 → 서버 규칙 상태 변경 → 다음 크론에서 새 동작 반영 (일시정지: 새 생성 중단 / 규칙 수정: 미래 미생성분만 갱신 / 해제: 완전 종료, 기존 생성분 유지)

### Scenario 4

매일 새벽 KST 크론 → 활성 규칙 조회 → 각 규칙별 마지막 생성일 ~ 1개월 윈도우 부족분 계산 → 파티 템플릿 복제로 신규 이벤트 일괄 생성 → 마지막 생성일 갱신

## KPIs / Success Metrics

- **반복 규칙 채택률**: 정기 운영 파트너 중 반복 규칙 설정 비율 ≥ 60% (출시 후 3개월)
- **수동 생성 감소**: 정기 운영 파트너의 평균 월간 수동 생성 수 -70%
- **개별 편집 비율**: 자동 생성 이벤트 중 개별 수정 비율 < 30% (템플릿이 충분히 좋은지 검증)
- **누락 사고**: 크론 누락으로 이벤트 미생성 케이스 0건
- **데이터 폭증**: 1개월 윈도우 유지 — DB 이벤트 row 증가율이 활성 규칙 수에 비례하는지 모니터링

## Launch Strategy

전체 파트너 일괄 적용. 점진 출시 없음. 신규 기능 안내 인앱 노티 1회.

## References

- **Meetup**: Optional Settings 반복 주기. 2-way 편집(이 이벤트만 / 시리즈 전체) — V1 은 "이 이벤트만" 만 채택, 시리즈 전체는 V2
- **Luma**: Event Series + Clone Event 병행. 시리즈 자동화가 핵심
- **Google Calendar**: 3-way 편집 + RFC 5545 RRULE — V1 은 단순화, 3-way 는 V2 검토
