## Functional Requirements

- **FR-1**: 구매 내역 카드는 신청 상태에 따라 취소 버튼(결제완료/심사 대기/승인 상태) 또는 환불 상태 라벨(환불 요청됨 / 환불 완료 / 거절됨)을 노출한다. 동시에 두 가지를 노출하지 않는다.
- **FR-2**: 자동 환불 가능 시 확인 다이얼로그는 환불 금액 + "영업일 기준 3일 내 입금" 안내를 표시. 주요 액션은 "취소하기"(에러 색), 보조 액션은 "돌아가기".
- **FR-3**: 확정 시 서버가 자동 환불 가능 여부를 재검증한 뒤 PortOne 결제 취소를 호출. 성공 시 환불 완료 상태로 변경.
- **FR-4**: 이벤트 상세의 환불 정책 섹션은 현재 시점 기준으로 3개 상태(cutoff 전 / grace 내 / 자동 불가) 중 하나를 인라인 표시한다. info 버튼 탭 시 3개 조건 전체를 안내 시트로 표시.
- **FR-5**: 자동 환불 불가 판정 시 "환불 가능 기간이 지났어요" 바텀시트를 노출. 본문에 사유 설명 + 라디오(개인 일정 변경 / 건강 문제 / 기타) + 기타 입력 필드.
- **FR-6**: "파트너에게 요청하기" 탭 시 서버가 자동 환불 불가 여부를 이중 검증한 뒤 환불 요청을 저장한다. 동일 신청에 대한 중복 요청은 거부.
- **FR-7**: 요청 전송 직후 결과 화면에 "파트너에게 환불을 요청했어요" 안내. 이후 상태 변경 시 푸시로 유저에 통보.
- **FR-8**: 파트너가 72시간(정책값) 내 응답하지 않으면 요청을 만료 상태로 전환 + 유저에 고객센터 안내 푸시. 파트너에는 더 이상 액션 노출 없음.
- **FR-9**: 파트너 앱 알림 탭에 환불 요청 카드를 노출 (유저명, 이벤트명, 사유, 경과 시간). 탭 시 상세 화면 이동.
- **FR-10**: 파트너 환불 요청 상세 화면에 신청자/이벤트/결제 금액/결제일/사유를 표시. 액션은 "환불 승인하기"(주요) + "거절하기"(보조).
- **FR-11**: "환불 승인하기" 시 확인 다이얼로그("환불을 승인할까요? 정산에서 차감돼요") → 서버가 PortOne 결제 취소 → 요청을 승인 상태로 전환 + 응답 시각 기록 + 유저 푸시.
- **FR-12**: "거절하기" 시 거절 사유 입력 시트 → 서버가 요청을 거절 상태로 전환 + 거절 사유 기록 + 유저 푸시.
- **FR-13**: 파트너 귀책(이벤트 취소 / 심사 거절) 발생 시 신청자 전원 100% 자동 환불 처리 + 푸시.
- **FR-14**: 무료 이벤트 취소는 PortOne 호출 없이 신청 상태만 취소로 변경.

## Non-Functional Requirements

- **NFR-1**: 취소 버튼 탭 → 자동 환불 판정 응답 800ms 이내 (네트워크 정상, 에뮬레이터 baseline, p50 기준).
- **NFR-2**: 자동 환불 / 파트너 승인 환불 PortOne 결제 취소 API 성공률 99% 이상 (월간 baseline). 실패 시 재시도 로직 + 운영팀 알림.
- **NFR-3**: 환불 요청 전송 응답 1.5초 이내 (p95).
- **NFR-4**: 72시간 미응답 에스컬레이션은 매시간 실행 + 누락된 만료 처리 보강. 누락률 1% 미만.
- **NFR-5**: 결제 후 → 환불 완료까지 영업일 기준 3일 이내 입금 (전자상거래법 제18조).
- **NFR-6**: 모든 환불 안내 카피는 약관 페이지와 동일 표현 사용 (약관-UI 동기화).

## Edge Cases

| CUJ ID | 케이스 | 기대 동작 |
|--------|--------|----------|
| 1-1 | 다이얼로그 confirm 도중 grace period 경과 | 서버 재검증에서 판정 변경 → "기간이 막 지났어요" 안내 + 파트너 요청 바텀시트로 전환 |
| 1-1 | PortOne 호출 실패 (PG 에러) | 재시도 로직 → 실패 시 "결제사 오류로 환불이 지연되고 있어요. 자동으로 재시도돼요" 안내 + 운영팀 알림 |
| 1-3 | 환불 완료 후 동일 신청 재취소 시도 | 버튼 미노출. 강제 호출 시 서버에서 거부 |
| 2-1 | cutoff 직전 다이얼로그 확정 시 cutoff 경과 | 서버 재검증 → 자동 환불 가능(시점 보호) 또는 정책에 따라 거부 (정책 결정 필요 — Open Q) |
| 2-2 | 이벤트 상세 진입 시 cutoff 갓 지남 | 인라인 표시 즉시 갱신 (시간 의존, 페이지 재진입 시 재계산) |
| 3-1 | 바텀시트 입력 도중 앱 kill | 미저장. 재진입 시 처음부터 |
| 3-2 | 요청 전송 도중 네트워크 끊김 | 재시도 + 실패 시 인라인 에러. 동일 신청에 대한 중복 저장 차단 |
| 3-3 | 동일 신청에 요청 2회 시도 | 서버에서 중복 거부 + 안내 |
| 3-4 | 72시간 직전 파트너 응답 | 정상 처리. 만료 전환은 응답 없음만 대상 |
| 4-1 | 알림 카드 탭 시 이미 처리된 요청 | 상세 진입 후 현재 상태 표시 (액션 비활성) |
| 4-2 | 승인 도중 유저가 신청 자체를 취소 | 서버에서 충돌 감지 → 파트너에 "이미 처리된 요청입니다" 안내 |
| 4-3 | 거절 사유 입력 없이 제출 | 제출 비활성. 최소 한 글자 필요 |
| 5-1 | 일괄 환불 도중 일부 PortOne 실패 | 실패 건은 재시도 큐 + 운영팀 알림. 성공 건은 즉시 푸시 |
| 5-2 | 무료 이벤트인데 잘못된 PortOne 호출 시도 | 서버 분기로 차단 |

### 환불 정책 표 (참고)

#### Track 1: 플랫폼 자동 환불

| 조건 | 환불률 | 처리 주체 |
|------|--------|----------|
| 결제 후 **3시간** 이내 (grace period) | 100% | 플랫폼 자동 |
| 이벤트 시작 **7일 전**까지 (cutoff) | 100% | 플랫폼 자동 |
| 파트너 귀책 (취소, 심사 거절) | 100% | 플랫폼 자동 |
| 무료 이벤트 취소 | — | 상태만 변경 |

#### Track 2: 파트너 환불 요청

| 조건 | 처리 방식 |
|------|----------|
| grace 초과 + cutoff 초과 | 유저 → 파트너 환불 요청 (인앱) |
| 파트너 승인 | PortOne 자동 취소 |
| 파트너 거절 | 사유 안내 + 고객센터 |
| 72시간 미응답 | 자동 expired + 고객센터 에스컬레이션 |

### 약관 변경 문구 (참고)

> **제N조 (참여 취소 및 환불)**
>
> ① 플랫폼 자동 환불: 다음의 경우 밍글릿이 자동으로 전액 환불을 처리해요.
>   1. 결제 후 3시간 이내에 취소하는 경우
>   2. 이벤트 시작일 7일 전까지 취소하는 경우
>   3. 파트너의 귀책(이벤트 취소, 자격심사 거절 등)으로 취소되는 경우
>
> ② 파트너 환불: 제1항의 자동 환불 기간이 경과한 경우, 유저는 앱을 통해 파트너에게 환불을 요청할 수 있어요. 파트너가 승인하면 전액 환불이 처리돼요.
>
> ③ 환불 금액은 영업일 기준 3일 이내에 원래 결제 수단으로 입금돼요.
>
> ④ 이벤트 시작 시각 이후에는 환불을 요청할 수 없어요.
