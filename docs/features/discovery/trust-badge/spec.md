## Functional Requirements

> 제품 행동 정의 — DB schema SQL / Provider 이름 / Repository 메서드 시그니처 같은 dev detail 은 제외 (코드/migration 이 SSoT).

- **FR-1**: 마이페이지에 신뢰 섹션을 노출하며 현재 등급(None / Verified / Certified / Elite) + 다음 등급 진입 조건을 명시.
- **FR-2**: 미인증 상태에서는 "본인확인 시작" CTA, 본인확인 후에는 "자격인증 추가" CTA, 자격인증 후에는 출석률 안내를 노출.
- **FR-3**: 등급은 (a) 본인확인 완료 여부, (b) 승인된 자격인증 카운트 ≥ 1, (c) 최근 출석률 ≥ 95% 의 3축 조건에서 단일 SSoT 로 산출.
- **FR-4**: 본인확인 완료 즉시 다음 화면 진입 시 신뢰 섹션 / 배지가 Verified 로 갱신 (재진입 / 새로고침 없이도 반영).
- **FR-5**: 자격인증 신청 → 승인 / 거절 워크플로우 진행 중에는 "심사 중" 상태 표시 (배지는 변동 없음).
- **FR-6**: 자격인증 결과(승인 / 거절) 시 인앱 알림 발송 + 마이페이지 신뢰 섹션 즉시 갱신.
- **FR-7**: TrustSheet 는 (a) 헤더 (이름 + 등급명), (b) 3-Layer 진행 표시, (c) 인증 항목 리스트, (d) 활동 지표 메시지의 4섹션으로 구성.
- **FR-8**: 본인 시트에는 미인증 항목 인증 CTA 노출, 타인 시트에는 미노출 (자기 항목만 인증 진입 가능).
- **FR-9**: 배지 위젯은 이름 옆 / 프로필 카드 / 참가자 목록 / 채팅 헤더 등 유저 노출 모든 위치에 동일하게 임베드.
- **FR-10**: 배지 시각 4종 — None(아이콘 없음 또는 회색), Verified(Shield), Certified(Sparkles), Elite(Diamond). 컬러뿐 아니라 형태로 구분.
- **FR-11**: 타인 시트의 인증 항목 리스트는 인증명·카테고리·승인일만 노출하며 원본 문서 / 사진은 비공개.
- **FR-12**: TrustSheet 하단에 컨텍스트별 CTA (이벤트 상세에서 진입 시 "매칭 신청" / 채팅에서 진입 시 닫기) 노출.
- **FR-13**: 등급 변경 시 알림 발송 정책은 본인확인 / 자격인증 / Elite 도달 등 마일스톤에만 한정 (강등 알림은 발송 안 함).
- **FR-14**: Elite 등급은 자격인증 1건 이상 + 최근 N 회 이벤트 출석률 ≥ 95% 를 동시에 만족할 때만 부여 (N 은 정책으로 별도 정의).
- **FR-15**: 등급은 항상 산출 시점 데이터 기준으로 계산되며, 강등 시 즉시 반영 (보유 X — Elite → Certified, Certified → Verified).
- **FR-16**: 자격인증 만료일 도래 시 해당 인증은 미인증 처리되며 등급 재산출에 반영.

## Non-Functional Requirements

> 측정 가능해야 함 — "빨라야 함" 금지. 환경 + 분위수 명시 (예: "에뮬레이터 baseline, p50 200ms 이내").

- **NFR-1**: 배지 위젯 렌더 → first paint 50ms 이내 (에뮬레이터 baseline, p95). 캐시 hit 가정.
- **NFR-2**: 등급 재산출 → UI 반영 ≤ 500ms (p95). 단일 화면에서 5인 이상 참가자 동시 산출 시 ≤ 1s (참가자 16명 기준 평균).
- **NFR-3**: 배지 아이콘은 컬러뿐 아니라 형태로 구분 (a11y — 색약 사용자 식별 가능). semanticsLabel 필수.
- **NFR-4**: 인증 승인 → 배지 갱신 end-to-end 지연 ≤ 30s (서버 이벤트 → 클라이언트 invalidate → 다음 화면 진입 기준).

## 화면 구성 (참고)

> dev 가 아닌 product/UX detail 만.

### 3-Layer Trust 구조

| 레벨 | 명칭 | 아이콘 | 조건 | 의미 |
|------|------|--------|------|------|
| Level 0 | 미인증 (None) | 없음 / 회색 | 본인확인 미완료 | 표시 위치별 정책 (없음 가능) |
| Level 1 | 인증됨 (Verified) | Shield | 본인확인(CI) 완료 | "실존하며 본인 확인이 된 유저" |
| Level 2 | 자격인증 (Certified) | Sparkles | 파트너 인증(직장 / 학력 등) 1개 이상 승인 | "검증된 사회적 배경" |
| Level 3 | 엘리트 (Elite) | Diamond | 자격인증 + 최근 출석률 ≥ 95% | "약속을 잘 지키는 최상위 신뢰" |

### 배지 위젯 (`TrustBadge`)

**노출 위치**: 유저 이름 옆 / 프로필 카드 / 참가자 목록 / 채팅 헤더.
**구성**: 아이콘 (16x16) — 텍스트 없음. 탭 시 TrustSheet.

### 신뢰 시트 (`TrustSheet`)

**섹션 (위→아래)**:
1. 헤더 — 유저 이름 + 등급명 (예: "✨ Certified")
2. 신뢰 요약 — 3-Layer 진행 인디케이터 (어디까지 달성)
3. 인증 내역 — 리스트 (`[직장] 삼성전자` / `[학력] 서울대학교` 등)
4. 활동 지표 — "최근 출석률 100%" / "매칭 만족도 상위 5%" 등 데이터 기반 메시지
5. (본인 시트만) 미인증 항목 인증 CTA / (타인 시트만) 컨텍스트 CTA

### 데이터 정의 (참고)

| 항목 | key | 설명 |
|------|-----|------|
| 등급 | `trust_level` | `none` / `verified` / `qualified` / `elite` (derived) |
| 본인확인 여부 | `is_identity_verified` | CI 완료 boolean |
| 인증 항목 | `verification_snapshots[]` | 인증명·카테고리·완료일 |
| 출석률 | `attendance_rate` | 최근 N 회 또는 N 일 기준 (정책으로 정의) |

> **단일 SSoT 권장**: 등급 산출은 서버 derived view 또는 클라이언트 단일 함수에서 결정. UI 컴포넌트는 결과만 표시 (불일치 방지).
