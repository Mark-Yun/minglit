# 태그 사용 통계 데이터 2차 활용 정책

## 1. 목적

태그 시스템(`tags`, `tag_usage_daily`, `party_tags`, `user_interest_tags`)에서 생성되는 통계 데이터의 이용 범위를 정의하고, 개인정보보호법 제18조(목적 외 이용·제공 제한) 준수를 보장한다.

## 2. 데이터 분류

태그 관련 데이터를 **개인정보 해당 여부**에 따라 두 계층으로 분류한다.

### 2.1 익명 집계 데이터 (개인정보 아님)

| 데이터 | 테이블/컬럼 | 설명 |
|--------|-------------|------|
| 태그별 누적 사용 횟수 | `tags.usage_count` | 파티-태그 연결 총 수 |
| 일별 태그 사용량 | `tag_usage_daily.daily_count` | 일별 신규 파티-태그 연결 수 |
| 트렌딩 태그 순위 | `get_trending_tags()` 결과 | N일간 증가율 기반 상위 태그 |
| 인기 태그 목록 | `tags` WHERE `is_featured = true` | 큐레이션된 태그 리스트 |

**법적 근거**: 개인정보보호법상 **익명정보**(특정 개인을 알아볼 수 없도록 처리한 정보)는 개인정보보호법 적용 대상이 아니다. `usage_count`와 `daily_count`는 파티-태그 연결의 단순 집계이며, 개별 유저를 식별할 수 있는 정보를 포함하지 않는다.

### 2.2 개인정보 (개인정보보호법 적용)

| 데이터 | 테이블/컬럼 | 설명 |
|--------|-------------|------|
| 유저별 관심 태그 | `user_interest_tags` | 유저가 선택한 관심 태그 (user_id 포함) |
| 파티별 태그 | `party_tags` + 파티 소유자 정보 | 파트너가 설정한 태그 (간접적 개인정보) |

**유저별 관심 태그**는 `user_id`와 직접 연결되므로 개인정보에 해당한다. 수집 목적(이벤트 추천) 외 이용 시 개인정보보호법 제18조의 제한을 받는다.

## 3. 이용 범위 정의

### 3.1 익명 집계 데이터 — 허용 범위

| 용도 | 허용 여부 | 조건 |
|------|-----------|------|
| **앱 내 트렌딩 태그 표시** | O 허용 | 수집 본래 목적. 무조건 허용 |
| **앱 내 인기 태그 큐레이션** | O 허용 | `is_featured` 관리 근거 |
| **서비스 개선 내부 분석** | O 허용 | 어떤 태그가 성장하는지, 시즌별 트렌드 등 |
| **파트너 대시보드: 태그 인기도 제공** | O 허용 (조건부) | 아래 §3.2 참조 |
| **외부 마케팅 자료 (블로그, 보도자료)** | O 허용 (조건부) | 특정 파트너/이벤트 식별 불가한 형태로만 |
| **제3자(광고주, 데이터 브로커) 판매** | X 금지 | 출시 전 단계에서 외부 판매 불필요. 향후 검토 시 별도 정책 수립 |

### 3.2 파트너 대시보드 태그 인사이트 제공

**결정: 제한적 허용**

파트너에게 제공하는 태그 인사이트는 **플랫폼 전체 집계 데이터**로 한정한다.

#### 제공 가능 항목

| 항목 | 예시 | 근거 |
|------|------|------|
| 플랫폼 전체 인기 태그 TOP N | "이번 주 인기: #러닝, #와인, #네트워킹" | 익명 집계 — 개인정보 아님 |
| 태그별 트렌드 방향 | "#러닝 ↑ 23% (최근 7일)" | 일별 집계의 단순 증감률 |
| 해당 파트너의 이벤트 태그 성과 | "내 이벤트의 #러닝 태그 이벤트 평균 대비 참여율 +15%" | 본인 데이터 + 익명 집계 비교 |

#### 제공 금지 항목

| 항목 | 사유 |
|------|------|
| 다른 파트너의 태그 사용 패턴 | 경쟁 정보 노출, 간접적 영업비밀 침해 가능 |
| 특정 유저 세그먼트의 태그 선호도 | `user_interest_tags` 기반 분석은 개인정보 처리에 해당 |
| 지역별·연령별 태그 교차 분석 | 소규모 이벤트에서 개인 식별 가능성 (k-anonymity 미보장) |

#### Eventbrite/Meetup 참고

- **Eventbrite**: 주최자에게 자신의 이벤트 분석(판매, 트래픽, 전환율)만 제공. 플랫폼 전체 트렌드는 연간 Event Trends Report로만 공개.
- **Meetup**: 주최자 대시보드에서 그룹 내 통계만 제공. 타 그룹 데이터 접근 불가.
- **밍글릿 적용**: Eventbrite 모델을 따르되, 파트너 대시보드에 플랫폼 전체 인기 태그 정보를 추가 제공하여 이벤트 기획에 활용할 수 있게 한다.

### 3.3 개인정보 (user_interest_tags) — 이용 범위

| 용도 | 허용 여부 | 법적 근거 |
|------|-----------|-----------|
| 이벤트 추천 (수집 목적) | O 허용 | 개인정보보호법 제15조 — 수집 목적 범위 내 |
| 익명 집계 후 트렌드 분석 | O 허용 | 통계작성 목적 (개인정보보호법 제28조의2) — 가명/익명 처리 후 |
| 파트너에게 개별 유저 관심 태그 제공 | X 금지 | 목적 외 제3자 제공 — 별도 동의 필요 (제18조) |
| 마케팅 타겟팅 | △ 조건부 | 회원가입 시 "(선택) 마케팅 정보 수신" 동의한 유저만 |

## 4. 개인정보처리방침 반영 필요 여부

### 4.1 결론: 현 시점에서 변경 불필요, 구현 시 반영 필요

| 시점 | 조치 |
|------|------|
| **현재 (태그 미구현)** | 변경 불필요. 태그 시스템 자체가 미구현 상태 |
| **태그 시스템 구현 시** | 개인정보처리방침에 아래 항목 추가 필요 |
| **파트너 대시보드 태그 인사이트 추가 시** | 파트너 개인정보처리방침에 통계 제공 근거 명시 |

### 4.2 태그 구현 시 개인정보처리방침 추가 항목

유저용 (`landing_user`):

```
[수집 항목 추가]
- 관심 태그 정보 (최대 5개)

[수집·이용 목적 추가]
- 관심사 기반 이벤트 추천 서비스 제공
- 서비스 개선을 위한 익명 통계 분석

[보유 기간]
- 회원 탈퇴 시 즉시 삭제 (user_interest_tags)
- 익명 집계 데이터 (tag_usage_daily)는 개인정보 아님, 별도 삭제 대상 아님
```

파트너용 (`landing_partner`):

```
[통계 정보 제공]
- 플랫폼 전체 태그 인기도 통계 (익명 집계)
- 파트너 본인 이벤트의 태그별 성과 통계
```

## 5. 기술적 보호 조치

| 조치 | 대상 | 설명 |
|------|------|------|
| RLS 정책 | `user_interest_tags` | `auth.uid() = user_id` — 본인만 읽기/쓰기 |
| RLS 정책 | `party_tags` | 읽기 public, 쓰기는 파티 소유 파트너만 |
| API 레벨 집계 | 파트너 대시보드 | RPC 함수에서 집계 결과만 반환, raw 데이터 접근 차단 |
| 로깅 제한 | Edge Functions | `user_interest_tags` 조회 시 user_id를 로그에 남기지 않음 |

5. 변경 이력을 이 문서에 기록
