## 1. 가상 보도자료

> **[2026년 5월]** "밍글릿은 오늘 이벤트 참여 현황 UI를 전면 개편하여, 유저가 '어떤 사람들이 오는지' 미리 파악한 뒤 참가를 결정할 수 있게 되었음을 발표합니다. 이제 유저는 입장그룹별 모집 현황을 한눈에 비교하고, blur 처리된 참여자 정보(나이대·인증뱃지)를 확인하여 더 확신을 갖고 이벤트에 참가할 수 있습니다. 이는 밍글릿의 '신뢰 기반 매칭' 철학을 참가 결정 단계까지 확장한 것입니다."

## 2. 가설 기반 문제 정의

### 관측된 문제 (The Pain)

1. **공간 비효율**: 세로 스택 카드가 높이 대비 정보 밀도가 낮고, 2그룹(남/여)일 때 화면의 절반 이상을 차지
2. **정보 전달력 부족**: 3칸 배터리 게이지가 33% 단위로만 표현, 정확한 비율 전달 불가 + "2명 참여" 텍스트와 "2/10" 게이지의 정보 중복
3. **전체 합계 부재**: 그룹별 인원만 표시되어 전체 참여 인원을 한눈에 파악 불가
4. **참가 결정 정보 부족**: "어떤 사람들이 오는지" 전혀 알 수 없어, 유저가 참가 결정 시 불확실성이 높음
5. **다크모드 밋밋함**: 카드 테두리만으로 시각적 구분 부족

### 핵심 가설

> "입장그룹별 모집 현황을 시각적으로 개선하고(P0), blur 처리된 참여자 기본 정보를 제공하면(P1), 이벤트 상세 → 신청 전환율이 향상될 것이다."

### 신뢰 레이어 매핑

- **Layer 1 (Identity)**: 참여자의 나이대는 본인인증(identity verification)에서 확보된 데이터 기반
- **Layer 2 (Qualification)**: 인증뱃지(직장인, 대학생 등)는 파트너 추가 심사(qualification) 기반
- 참여자 blur 정보는 두 레이어의 교차점 — 인증된 정보만 노출하여 신뢰성 보장

## 3. 잡 스토리 및 ICP 분석

### 페르소나 시뮬레이션

#### 페르소나 A: 김지은 (29세, 직장인, 첫 이벤트 참가 고민 중)
- **상황**: 금요일 저녁 와인 시음회를 발견. 혼자 가야 하는데 어떤 사람들이 오는지 모름
- **현재 불만**: "남성 2/10, 여성 3/10" 숫자만 보이고, 비슷한 또래인지·분위기가 맞을지 판단 불가
- **원하는 것**: "20대 후반~30대 초반이 많고, 직장인 인증된 사람이 있으면 안심하고 갈 수 있는데"
- **Job Story**: "처음 참가하는 이벤트에서, 나와 비슷한 연령대·상황의 사람이 있는지 확인하고 싶다. 혼자 가서 겉도는 상황을 피하고 싶기 때문이다."

#### 페르소나 B: 박민수 (25세, 대학원생, 가격 대비 가치 판단)
- **상황**: 주말 보드게임 모임 (남녀 각 5명 정원). 35,000원 참가비가 아까울 수도
- **현재 불만**: 게이지 바가 3칸짜리라 "2/5"도 "1/5"도 같은 칸으로 보임. 실제로 몇 명인지 직관적이지 않음
- **원하는 것**: 정확한 인원 비율 + "거의 다 찼으니 빨리 결정해야 해" 같은 urgency
- **Job Story**: "정원 마감이 가까운 이벤트에서, 남은 자리를 정확히 파악하고 빠르게 결제하고 싶다. 고민하다 놓치는 걸 피하고 싶기 때문이다."

#### 페르소나 C: 이수진 (파트너, 이벤트 주최자)
- **상황**: 남녀 각 10명 규모 이벤트 운영. 남성은 7명 모집, 여성은 3명만 모집된 상황
- **현재 불만**: 유저 앱에서 성비 불균형이 단순 숫자로만 보여서, 여성 참가자가 "남자만 많은 거 아니야?" 불안으로 이탈
- **원하는 것**: 여성 참가자에게 "같은 또래 여성이 3명 있어요" 같은 안심 정보 제공
- **Job Story**: "성비 밸런스가 맞는 이벤트에서, 유저가 참가자 구성을 미리 확인하고 안심하게 만들고 싶다. 막판 이탈을 줄이고 싶기 때문이다."

## 4. 경쟁 앱 벤치마킹

### 조사 대상 및 참여자 표시 비교

| 앱 | 참여 인원 표시 | 참여자 상세 | 프로그레스/게이지 | 비로그인 처리 |
|-----|--------------|-----------|----------------|------------|
| **소모임** | 전체 "N/M명 참여" | 프로필 카드 (사진+닉네임+나이) | 없음 (텍스트만) | 일부 공개 + 로그인 CTA |
| **문토** | "N명 참여 중" | 참여자 아바타 원형 나열 + 나이대 | 없음 | 카운트만 공개 |
| **Eventbrite** | "N going · N interested" | Facebook 연동 "See Who's Going" | 없음 | 카운트만 공개 |
| **Bumble BFF** | 그룹 이벤트 "N spots left" | 참가자 프로필 blur + 공통점 하이라이트 | urgency 기반 (almost full) | 미공개 |
| **Meetup** | "N attendees" + capacity bar | 참가자 아바타 목록 (공개) | 프로그레스 바 | 제한 공개 |

### 핵심 인사이트

1. **Social proof는 전환의 핵심**: 소모임·Meetup 모두 "누가 오는지"를 보여주는 것이 참가 전환에 기여. 단순 숫자만으로는 부족.
2. **프라이버시 vs 정보**: Bumble의 blur 패턴이 밍글릿에 가장 적합 — 개인 식별 불가하면서도 "나와 비슷한 사람이 있다"는 확신 제공
3. **Urgency 효과**: "N spots left" (Bumble) / "almost full" 표시가 전환에 효과적. 연속 프로그레스 바가 이를 시각적으로 전달
4. **그룹별 분리 표시**: 밍글릿의 입장그룹 구조는 경쟁사에 없는 차별점. 성비·연령대별 모집 현황을 분리 표시하는 것은 소셜 이벤트에서 강력한 의사결정 정보

### 밍글릿 적용 판단

- 소모임/Meetup처럼 프로필 사진·닉네임 공개는 **부적합** — 밍글릿은 "신뢰 기반 매칭" 플랫폼이므로 사전 프로필 노출은 매칭 가치를 훼손
- Bumble의 blur 패턴 + 밍글릿의 인증 시스템(Layer 1+2) 결합이 최적 — "20대 후반 · 직장인" 수준의 정보가 참가 결정에 충분하면서도 프라이버시 보장
- Eventbrite의 "interested" 개념은 현재 불필요 (밍글릿은 유료 결제 기반이므로 "참가 = 결제 완료")

## 5. 성공 지표

### North Star Metric
- **이벤트 상세 → 신청 전환율** (event_viewed → application_started): 현재 대비 +10% 목표

### Counter-Metrics (Guardrails)
- 개인정보 관련 CS 문의 증가 여부 모니터링
- 이벤트 상세 페이지 로딩 시간 증가 없어야 함 (blur 리스트 데이터 추가 로딩)
- 참여자 blur 정보로 인한 특정 이벤트 기피 현상 (역효과)

### Domain Probes
- `participation_section_viewed` — 참가 현황 탭 조회
- `participant_list_expanded` — blur 리스트 전체 펼침 (단일 버튼)
- `participant_list_collapsed` — blur 리스트 전체 접힘 (단일 버튼)
- `login_cta_tapped` — 비로그인 상태 로그인 CTA 탭

## 6. 구성 요소 (위 → 아래)

### 6.1 전체 합계 Summary Bar (신규)

```
┌─────────────────────────────────────┐
│ 👥 전체 참여  4 / 20                │
│ ████████░░░░░░░░░░░░░░░░░░░░░░░░░░ │
└─────────────────────────────────────┘
```

- 섹션 최상단에 전체 참여 인원 합계 표시
- 프로그레스 바: 전체 참여율 시각화
- 색상: primary (#9900FF)
- 입장그룹이 없는 이벤트에서도 표시

### 6.2 입장그룹 카드 (개선)

#### 레이아웃: 가로 스크롤 (Horizontal Scroll)

```
┌──────────────┐  ┌──────────────┐
│ 🔵 남성       │  │ 🩷 여성       │
│   3 / 10     │  │   2 / 10     │
│ ████████░░░░ │  │ █████░░░░░░░ │
└──────────────┘  └──────────────┘
        ← 가로 스크롤 →
```

**설계 결정**:
- 2그룹: 화면에 나란히 표시 (스크롤 불필요)
- 3그룹 이상: 가로 스크롤로 탐색. 카드 너비 고정, 오른쪽 카드 일부가 잘려 보여 스크롤 어포던스 제공
- 카드 상단 color strip (3px): 그룹별 고유 색상으로 시각 구분

**프로그레스 바 개선**:
- 3칸 배터리 → 연속 프로그레스 바 (높이 6px, radius 3px)
- 정확한 비율 표현 가능

**숫자 위계 개선**:
- 참여 인원: `3 / 10` (20px bold) — 단일 표현으로 통합
- "2명 참여" 텍스트 + 게이지 중복 제거

**그룹 색상 정책**:

| 그룹 유형 | 색상 | 코드 |
|----------|------|------|
| 남성 | Blue | `#60A5FA` |
| 여성 | Pink | `#F472B6` |
| 성별 무관 / 기타 | Primary | `#9900FF` |

> **PM 판단**: 남성=Blue, 여성=Pink는 한국 소셜 이벤트 도메인에서 보편적 컨벤션. 차별적 의도가 아닌 시각적 구분 용도. 성별 무관 그룹은 primary로 중립 처리.

### 6.3 참여자 Blur 리스트 (신규 기능)

#### 기본 상태: 접힘

그룹 카드 영역 하단에 **단일 "참여자 정보 ▾" 토글 버튼** 1개를 배치. 탭하면 **모든 그룹의 blur 리스트를 동시에 펼침**.

> **설계 결정**: 그룹별로 각각 펼치기 버튼을 두지 않고, 하나의 버튼으로 전체를 펼친다. 유저가 여러 그룹을 개별적으로 열고 닫을 필요 없이 한 번에 모든 참여자 정보를 확인할 수 있다.

#### 펼친 상태

```
┌──────────────┐  ┌──────────────┐
│ 🔵 남성       │  │ 🩷 여성       │
│   3 / 10     │  │   1 / 10     │
│ ████████░░░░ │  │ ██░░░░░░░░░░ │
│              │  │              │
│ 🔵 20대 후반  │  │ (3명 미만    │
│   · 직장인   │  │  비표시)      │
│ 🔵 30대 초반  │  │              │
│ 🔵 20대 중반  │  │              │
│   · 대학생   │  │              │
└──────────────┘  └──────────────┘
       참여자 정보 ▴    ← 단일 버튼
```

#### 표시 정보 (blur 원칙)

| 항목 | 표시 여부 | 소스 | 비고 |
|------|----------|------|------|
| 나이대 | ✅ | `user_profiles.birth_date` → 계산 | 초반/중반/후반 범위 |
| 인증뱃지 | ✅ (있는 경우만) | `verification_submissions` | "직장인", "대학생" 등 |
| 프로필 사진 | ❌ | — | blur 원칙 |
| 이름/닉네임 | ❌ | — | blur 원칙 |
| 성별 | ❌ | — | 이미 그룹으로 분리됨 |
| 지역 | ❌ | — | 이벤트 장소가 이미 공개되어 불필요 |
| 관심 태그 | ❌ | — | V1에서 제외. 데이터 품질 검증 후 V2 고려 |

#### 나이대 분류 기준

| 표시 | 나이 범위 | 비고 |
|------|----------|------|
| 20대 초반 | 20~23세 | 4세 폭 |
| 20대 중반 | 24~26세 | 3세 폭 |
| 20대 후반 | 27~29세 | 3세 폭 |
| 30대 초반 | 30~33세 | 4세 폭 |
| 30대 중반 | 34~36세 | 3세 폭 |
| 30대 후반 | 37~39세 | 3세 폭 |

> **PM 판단**: "초반/중반/후반" 3단계 분류는 한국에서 보편적으로 사용되는 표현이며, 3~4세 폭으로 k-anonymity를 확보. 정확한 나이가 아닌 범위 표시이므로 개인 식별 위험 매우 낮음. 다만, 소규모 이벤트(5명 이하)에서 나이대 + 인증뱃지 조합으로 식별 가능성이 있으므로, **최소 3명 이상의 그룹에서만 blur 리스트 표시** (k≥3 보장).

#### `show_participant_list` 메타데이터 활용

| 설정값 | 동작 |
|--------|------|
| `true` (기본값) | 카운트 + blur 리스트 모두 표시 |
| `false` | 카운트만 표시, blur 리스트 토글 숨김 |

> **PM 판단**: `false`일 때 카운트까지 숨기면 참가 결정에 필요한 최소 정보가 없어짐. "몇 명이 신청했는지"는 기본 정보로 항상 공개. Blur 리스트만 게이팅.

### 6.4 비로그인 상태 처리

```
┌──────────────────────────────────────┐
│  🔒 로그인하면 참여자 정보를 볼 수    │
│     있어요                           │
│            [로그인하기]               │
└──────────────────────────────────────┘
```

- 참여자 리스트 토글 숨김
- 카운트 + 프로그레스 바는 공개 (소셜 프루프 유지)
- 카드 하단에 로그인 CTA: primary 5% opacity 배경
- CTA 탭 → `/login?from=/events/:eventId` (원래 경로 보존)

### 6.5 다크모드 대응

- 카드 상단 color strip (3px)으로 그룹 구분 + 밋밋함 해소
- 카드 배경: `surfaceContainerLowest` (#1A1A1A)
- 프로그레스 바 트랙: `outlineVariant` (#3D3D3D)
- 텍스트: `text-primary` (#FFFFFF) / `text-secondary` (#AAAAAA)

## 7. 데이터 소스

### 기존 API (변경 없음)
- `entryGroupParticipantCountsProvider(eventId)` — 그룹별 참여 카운트
- `Event.currentParticipants` / `Event.maxParticipants` — 전체 카운트
- `Event.entryGroups` — 입장그룹 목록
- `Event.tickets` — 티켓별 판매량/정원

### 신규 API 필요
- **`getBlurParticipants(eventId, entryGroupId)`** — 그룹별 참여자 blur 정보
  - Response: `[{ age_range: "20대 후반", badges: ["직장인"] }, ...]`
  - RLS: 이벤트가 공개(`visibility = 'public'`) OR 같은 이벤트 참가자만 조회 가능
  - `show_participant_list = false`이면 빈 배열 반환
  - **k-anonymity**: 그룹 내 참여자 3명 미만이면 빈 배열 반환

### 메타데이터
- `MetaKeys.showParticipantList` — 이미 정의됨, 와이어링만 필요

## 10. 핵심 요구사항 및 비목표

### P0 (필수 — MVP)
- [ ] 전체 합계 Summary Bar
- [ ] 2열 그리드 레이아웃 (입장그룹 카드)
- [ ] 연속 프로그레스 바 (3칸 배터리 교체)
- [ ] 숫자 위계 개선 (중복 제거)
- [ ] 다크모드 color strip

### P1 (중요 — MVP 직후)
- [ ] 참여자 blur 리스트 (접힘/펼침)
- [ ] 나이대 + 인증뱃지 표시
- [ ] `show_participant_list` 메타데이터 와이어링
- [ ] k-anonymity 가드 (3명 미만 비표시)
- [ ] 비로그인 CTA

### P2 (장기)
- [ ] 관심 태그 추가 표시 (데이터 품질 검증 후)
- [ ] "거의 마감!" urgency 뱃지 (80% 이상)
- [ ] 실시간 참여자 업데이트 (Realtime subscription)

### Non-Goals (의도적 제외)

- 파트너 앱 참여 현황 UI 개선 — 별도 이슈로 분리

## 11. 개인정보 영향 평가

### 표시 데이터 분류
- **나이대 (초반/중반/후반)**: 개인정보보호법 제23조 민감정보에 해당하지 않음. 3~4세 폭 범위로 blur 처리
- **인증뱃지**: 인증 유형(직장인/대학생)만 표시, 구체적 직장명·학교명 미공개

### k-anonymity 보장
- 그룹 내 참여자 **3명 미만**이면 blur 리스트 미표시 (카운트만 표시)
- 이는 소규모 이벤트에서 나이대+뱃지 조합으로 개인 식별되는 것을 방지
- 3명은 최소 기준. 추후 데이터 분석 결과에 따라 상향 가능

### 추천: Legal 리뷰
- `needs-legal` 이슈로 나이대 범위 표시의 개인정보 영향 확인 요청 필요
- 특히 소규모 이벤트(5명 이하)에서의 식별 가능성 검토
