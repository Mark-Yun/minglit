# 이벤트 수정/취소 스펙 (Event Edit & Cancel)

## 개요

파트너앱에서 이벤트 수정과 취소 기능을 구현한다. 현재 파트너는 이벤트를 생성하고 상세를 조회할 수 있지만, 생성 후 수정하거나 취소하는 기능이 없다. 이 기능이 없으면 일정 변경이나 불가피한 취소 시 유저 경험이 크게 저하되고, 통합 테스트(#1338)도 blocked 상태다.

**출처 이슈**: #1396
**Blocked**: #1338 (통합 테스트)

### 현재 상태 (문제)

| 구성요소 | 상태 | 문제 |
|---------|------|------|
| EventEditRoute | 미구현 | Create/Detail만 존재. 수정 UI 없음 |
| 이벤트 취소 UI | 미구현 | 버튼/다이얼로그 없음 |
| 이벤트 취소 Edge Function | 부분 구현 | `partner-manage-event`에 `update_status` 액션 존재 (scheduled→cancelled만) |
| 참가자 환불/알림 처리 | 미구현 | 취소 시 참가자 자동 환불/알림 없음 |
| 이벤트 수정 시 알림 | 미구현 | 날짜/장소 변경 시 참가자 알림 없음 |

### 핵심 원칙

1. **파트너 자율성**: 파트너가 자기 이벤트를 자유롭게 수정/취소할 수 있어야 한다
2. **참가자 보호**: 유료 이벤트 취소 시 전액 자동 환불 보장 (Eventbrite 강제 정책 수준)
3. **투명한 알림**: 핵심 정보(날짜/시간/장소) 변경 시 참가자에게 즉시 알림
4. **불가역 취소**: 취소는 되돌릴 수 없으며, 2단계 확인으로 실수 방지
5. **기존 코드 활용**: `partner-manage-event`의 `update`/`update_status` 액션을 확장

### 참고 앱

| 앱 | 수정 정책 | 취소 정책 | 밍글릿 적용 포인트 |
|----|----------|----------|-------------------|
| **Eventbrite** | 모든 필드 수정 가능. 환불 정책은 출판 후 더 유연한 방향으로만 변경 가능 | 취소 시 전액 환불 의무 (플랫폼 강제). 미이행 시 플랫폼이 대신 환불 후 청구 | 유료 이벤트 취소 = 전액 환불 강제 채택 |
| **Meetup** | 대부분 필드 수정 가능. 댓글/채팅 설정은 저장 후 잠금 | 취소 불가역 ("cannot be undone"). 취소 시 모든 정보 삭제 | 불가역 취소 + 2단계 확인 채택 |
| **Luma** | 모든 필드 수정 가능 | 유료 이벤트 취소 시 전원 환불 옵션. 취소 이메일 커스터마이즈 가능 | Going 상태 참가자만 알림 채택 |

### 유저 시뮬레이션

**페르소나 1 — 장소가 변경된 와인바 사장 (35세, 남성)**
- 금요일 와인파티를 게시했는데, 건물 공사로 인해 옆 건물로 장소를 옮겨야 함
- Pain: "장소를 바꿨는데 참가자들이 모를까봐 걱정이다" → 장소 변경 시 자동 알림으로 해소
- 기대: 장소만 수정하면 참가자에게 "장소가 변경됐어요" 알림이 자동 발송
- 엣지 케이스: 시간도 같이 변경 → 알림에 "장소 + 시간이 변경됐어요" 통합 표시

**페르소나 2 — 인원 미달로 취소해야 하는 독서모임 기획자 (42세, 여성)**
- 다음 주 독서모임에 2명만 신청. 최소 인원(5명) 미달이라 취소하고 싶음
- Pain: "취소하면 결제한 2명은 어떻게 되지? 환불을 일일이 해줘야 하나?"
- 기대: 취소 버튼 → "참가자 2명에게 전액 환불돼요" 안내 → 확인 → 자동 처리
- 엣지 케이스: 취소 후 같은 시간에 새 이벤트를 열고 싶음 → 취소와 생성은 독립

**페르소나 3 — 시간을 잘못 입력한 클럽 프로모터 (29세, 남성)**
- 이벤트를 20:00~01:00으로 만들어야 하는데 실수로 08:00~13:00으로 만듦
- Pain: "삭제하고 다시 만들면 이미 결제한 사람은?" → 수정으로 해소
- 기대: 시간만 고쳐도 기존 참가자 유지. 변경 알림은 자동
- 엣지 케이스: 날짜까지 변경 → 참가자에게 "일정이 변경됐어요. 참석이 어려우면 취소할 수 있어요" 안내

**페르소나 4 — 정원을 늘리고 싶은 카페 사장 (38세, 여성)**
- 이벤트가 잘 돼서 정원 15명 → 20명으로 늘리고 싶음
- Pain: "정원만 바꾸는 건데 참가자한테 알림이 가면 불안할 것 같다"
- 기대: 정원 변경은 알림 없이 조용히 반영 (부수 정보)
- 엣지 케이스: 정원을 줄이면? → 현재 참가자 수 이하로 줄일 수 없음

**편집 모드 동작**:

### 2. 이벤트 취소 (Event Cancel)

#### 2-1. 취소 가능 조건

| 조건 | 취소 가능 여부 | 사유 |
|------|:------------:|------|
| status = `scheduled` | O | 정상 취소 |
| status = `active` | O | 체크인 시작 전 취소 허용 (Event State Machine #998 구현 후) |
| status = `ongoing` | X | 이벤트 진행 중 취소 불가 |
| status = `completed` | X | 이미 완료 |
| status = `cancelled` | X | 이미 취소됨 |

#### 2-2. 취소 진입점

EventDetailPage의 AppBar 메뉴(더보기 `⋮`) 또는 하단에 "이벤트 취소" 버튼:

- 참가자 0명: TextButton (가벼운 스타일)
- 참가자 1명+: TextButton.error (경고 스타일) — 환불 영향 있음을 시각적으로 암시

#### 2-3. 취소 확인 플로우 (2단계)

**Step 1 — 취소 사유 선택 (바텀시트)**

```
┌─────────────────────────────────────┐
│  이벤트를 취소할까요?                │
│                                     │
│  취소하면 되돌릴 수 없어요.          │
│                                     │
│  ── 취소 사유 (선택) ──              │
│  ○ 인원 미달                         │
│  ○ 개인 사정                         │
│  ○ 장소/시설 문제                    │
│  ○ 기타                              │
│  [기타 사유 입력...]                  │
│                                     │
│  [돌아가기]     [다음]               │

```

- 취소 사유는 **선택 사항** (필수 아님). CS 데이터 수집 목적
- 사유 코드: `insufficient_attendees`, `personal`, `venue_issue`, `other`

## 데이터 소스

### 기존 Edge Function 확장

#### `partner-manage-event` — update 액션 확장

현재 `update` 액션은 이벤트 필드를 업데이트한다. 다음을 추가:

1. **변경 필드 감지**: 요청에 `notify_changes: true`와 변경 전 값(`previous_values`)을 포함
2. **핵심 정보 변경 시 알림 트리거**: `start_time`, `end_time`, `location_id` 변경 시 PGMQ 이벤트 발행
3. **정원 줄이기 검증**: `max_participants` < 현재 `current_participants`이면 에러 반환

```typescript
// update 액션 확장
if (notify_changes && previous_values) {
  const changedCriticalFields = detectCriticalChanges(previous_values, updates);
  if (changedCriticalFields.length > 0) {
    await publishEventModifiedNotification(eventId, changedCriticalFields);
  }
}
```

#### `partner-manage-event` — update_status 액션 확장

현재 `scheduled → cancelled`만 허용. 다음을 추가:

1. **참가자 환불 자동 처리**: 취소 시 유료 참가자(status=`paid`) 전원 환불
2. **알림 발송**: PGMQ를 통해 참가자 알림 이벤트 발행
3. **취소 사유 저장**: `events.metadata.cancel_reason`에 저장

```typescript
// update_status → cancelled 확장
if (status === "cancelled") {
  // 1. 유료 참가자 환불
  const paidApplications = await getPaidApplications(eventId);
  for (const app of paidApplications) {
    await executeRefund(app.payment_id, app.payment_amount);
    await updateRefundStatus(app.id, 'completed');
  }

  // 2. 모든 참가자 신청 상태 → cancelled
  await cancelAllApplications(eventId);

  // 3. 알림 발행
  await publishEventCancelledNotification(eventId, cancelReason);

  // 4. 취소 사유 저장
  await updateEventMetadata(eventId, { cancel_reason: cancelReason });
}
```

## Non-Goals (이번 범위 밖)

- **이벤트 복제**: 취소된 이벤트를 복제하여 새로 생성하는 기능 — 후속 피처
- **수정 이력 관리**: 수정 기록 조회 기능 — 현재 필요성 낮음
- **반복 이벤트 시리즈 편집**: "이 이벤트만" vs "시리즈 전체" 2-way 편집 — recurring-events 스펙에서 관리
- **취소 이메일 커스터마이즈**: Luma처럼 파트너가 취소 메시지를 커스텀 — V2
- **부분 환불**: 취소 시 전액 환불만 지원. 부분 환불은 refund-policy-v2 범위
- **이벤트 연기(postpone)**: Eventbrite처럼 연기 후 재개 기능 — 수정으로 충분히 대응 가능
