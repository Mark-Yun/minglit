# PRD: 회원 탈퇴 (Account Deletion)

## Summary

유저/파트너가 앱 안에서 직접 계정 탈퇴를 요청 → 7일 유예 → 영구 삭제. 개인정보보호법(제36/37조)·앱스토어 정책 필수 기능이며, 현재 처리방침에 고지된 "설정 > 계정 관리에서 탈퇴" 경로의 허위 고지를 해소한다.

## Motivation / Problem to Solve

- 개인정보보호법 제36조(개인정보 파기) / 제37조(처리정지 등 권리) — 앱 내 탈퇴 경로 필수
- Apple App Store Review Guideline 5.1.1 (v) / Google Play Account Deletion Requirements — 계정 생성 가능 앱은 동등한 삭제 경로 의무
- 개인정보처리방침에 "설정 > 계정 관리에서 탈퇴 가능"이라 고지했으나 미구현 → 허위 고지 리스크
- 파트너의 경우 미정산 / 미완료 이벤트 / 환불 진행 건이 있으면 탈퇴 시 데이터 무결성·정산 분쟁 발생

## Goals

### Target Users

- **유저**: 더 이상 서비스를 사용하지 않거나 개인정보가 우려되어 탈퇴를 원하는 일반 유저
- **파트너**: 사업 종료 / 운영 중단 등으로 탈퇴를 원하는 파트너 (단, 진행 중 의무 해소 후)
- **법무·CS**: 처리방침 일치성 확보, 탈퇴 문의 수동 대응 부담 감소

### Key Goals

- **P0**: 앱 내에서 탈퇴 요청 가능 (마이페이지 / 더보기 진입 → 5단계 플로우)
- **P0**: 본인 확인 (소셜 재인증 또는 비밀번호) 후에만 탈퇴 확정
- **P0**: 7일 soft-delete 유예 — 유예 중 재로그인 시 자동 복구
- **P0**: 파트너 탈퇴 시 미정산 / 미완료 이벤트 / 환불 진행 건이 있으면 차단 + 해결 항목 안내
- **P0**: 법정 보존 대상(거래·결제·분쟁·로그인) 데이터 분리 보관 후 식별자 익명화
- **P1**: 탈퇴 사유 익명 수집 (유저 식별 정보 미포함, 통계 목적)
- **P1**: 동일 본인인증(DI) 정보로 30일간 재가입 차단

### Non-Goals

- 탈퇴 데이터 영구 복구 (7일 유예 외에는 복구 불가 — 데이터 최소 보존 원칙)
- 외국어 안내 문구
- 탈퇴 사유 별도 운영 대시보드 (통계는 후속 PR)
- 28일 이상의 장기 유예 (Bumble 패턴) — 데이터 보존 비용 / 법정 보존 기간과 trade-off

## Product Principles

1. **법적 필수 요건 충족**: 개인정보보호법 + 앱스토어 정책 모두 만족하는 경로를 디폴트로 제공한다.
2. **다크 패턴 금지**: 탈퇴 버튼은 숨기지 않으며, 사유 선택은 "선택하지 않고 계속" 경로를 함께 제공한다.
3. **안전장치 우선**: 진행 중 거래·정산이 있으면 탈퇴를 차단하고 해결 경로를 안내한다.
4. **법정 보존 분리**: 식별 정보는 즉시 삭제, 법정 보존 대상은 익명화된 아카이브로 분리 보관한다.

## Technical Approach

- **화면**: 진입점(PrivacyPage / MorePage) + 탈퇴 사유 / 탈퇴 안내 / 본인 확인 / 완료 화면 (다이얼로그 1개 별도)
- **저장**: `user_profiles.deleted_at` 컬럼 (soft-delete), 탈퇴 사유 익명 테이블, 재가입 차단 DI 해시 테이블, 법정 보존 아카이브 테이블
- **외부 의존성**: Supabase Auth `reauthenticate`, FCM 구독 해제, 결제·정산 모듈 (탈퇴 차단 조건 확인)
- **가드 / 정책**: RLS 로 `deleted_at IS NOT NULL` 유저를 검색 / 매칭 / 피드에서 제외 / CRON 으로 7 일 경과 시 영구 삭제 + DI 차단 등록

## User Journey

### Scenario 1: 유저 탈퇴 (CUJ 1-x)

유저가 마이페이지 → 개인정보 설정 → 탈퇴를 눌러 사유 선택(또는 skip) → 안내 확인 → 본인 재인증 → 최종 다이얼로그 확정 → 완료 화면을 본 뒤 자동 로그아웃된다.

### Scenario 2: 파트너 탈퇴 (CUJ 2-x)

파트너가 더보기 → 계정 설정 → 탈퇴를 눌렀을 때, 미완료 이벤트 / 미정산 / 환불 진행 건이 있으면 차단되며, 해결 시 유저와 동일한 5단계 플로우로 진행된다.

### Scenario 3: 유예 기간 / 복구 / 재가입 (CUJ 3-x)

탈퇴 요청 후 7일 유예 중 재로그인하면 탈퇴 취소 다이얼로그가 떠 복구 가능하며, 유예 종료 시 영구 삭제되고 동일 DI 로는 30일간 재가입이 차단된다.

## Data Flow

### Scenario 1

PrivacyPage → 탈퇴 버튼 탭 → 사유 선택 화면 (skip 가능) → 안내 화면 → 본인 확인 (Supabase reauthenticate) → 최종 확인 다이얼로그 → 탈퇴 API 호출 → `user_profiles.deleted_at` 기록 + 익명 사유 저장 + FCM 구독 해제 → 완료 화면 → 3초 후 로그아웃 + 홈 이동

### Scenario 2

MorePage → 계정 설정 → 탈퇴 버튼 탭 → 차단 조건 검사 (미완료 이벤트 / 미정산 / 환불) → 차단 시 해결 항목 + 바로가기 표시 / 정상 시 유저와 동일 5단계

### Scenario 3

유예 기간 중 로그인 → 복구 다이얼로그 → "탈퇴 취소" 탭 → `deleted_at` null 복원 → 정상 진입 / 또는 7일 경과 → CRON 잡이 법정 보존 아카이브 → `auth.users` cascade 삭제 → DI 차단 테이블 등록 → 30일 후 차단 해제

## KPIs / Success Metrics

- **탈퇴 경로 사용률**: CS 채널을 통한 탈퇴 문의 대비 앱 내 셀프 탈퇴 비율 ≥ 90% (런칭 후 4 주)
- **유예 기간 복구율**: 탈퇴 요청 대비 7일 내 복구 비율 — baseline 측정 후 다크 패턴 여부 평가 지표
- **차단 조건 발생률 (파트너)**: 탈퇴 시도 중 미정산 / 미완료 차단 비율 — 결제 / 정산 UX 개선 신호
- **앱스토어 정책 통과**: Apple 5.1.1(v) / Google 정책 리뷰 통과

## Launch Strategy

- 1단계: 유저 앱만 출시 (전체 출시)
- 2단계: 파트너 앱 출시 (차단 조건 검증 충분히 확보 후)
- 7일 유예 기간은 출시 후 데이터로 28일까지 확장 여부 별도 검토
