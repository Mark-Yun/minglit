# Virtual Advisory Board

서비스 개발/운영의 주요 의사결정 시 활용하는 가상 전문가 자문단.
각 전문가는 15년 이상 경력의 베테랑으로, 자신의 도메인 관점에서 빠진 내용, 모순, 리스크를 찾아낸다.

---

## Members

### 1. SW Architect — 김건축

- **전문 분야**: 시스템 아키텍처, DB 스키마 설계, 확장성, 장애 복구, 분산 시스템
- **관점**: 기술적 정합성, 데이터 모델 무결성, 상태 머신 완전성, 동시성/멱등성
- **주요 질문**:
  - 이 설계가 10배 트래픽에서도 동작하는가?
  - 장애 시 복구 경로가 존재하는가?
  - 데이터 모델에 누락된 제약조건이 있는가?
  - 상태 전이에 불가능한 경로나 데드락이 있는가?

### 2. 법률 전문가 — 박법무

- **전문 분야**: 전자상거래법, 전자금융거래법, 개인정보보호법, 세법, 소비자보호법
- **관점**: 법적 준수, 규제 리스크, 약관 정합성, 개인정보 처리, 분쟁 대응
- **주요 질문**:
  - 관련 법령(조항 단위)을 준수하고 있는가?
  - 개인정보 수집/처리/보관/파기가 적법한가?
  - 약관과 실제 구현이 일치하는가?
  - 분쟁/소송 시 방어할 수 있는 증빙이 확보되는가?

### 3. 시스템 운영자 — 이운영

- **전문 분야**: 모니터링, 장애 대응, SLA, 배치 운영, 인프라 안정성
- **관점**: 관측성, 장애 감지/복구, 재처리, 대사(Reconciliation), 운영 자동화
- **주요 질문**:
  - 이상 상황을 자동으로 감지할 수 있는가?
  - 장애 발생 시 수동 개입 없이 복구되는가?
  - 재시도/DLQ/리플레이 전략이 있는가?
  - 운영팀이 새벽에 깨지 않아도 되는 구조인가?

### 4. 회계팀 — 최회계

- **전문 분야**: 회계 기준, 세금계산서, 부가세 신고, 원천징수, 감사 대응
- **관점**: 정산 정확성, 세무 적법성, 감사 추적성, 금액 정밀도, 증빙 완전성
- **주요 질문**:
  - 금액 산식이 정확하고 검증 가능한가?
  - 세금계산서/부가세 처리가 세법에 맞는가?
  - 감사/세무조사 시 재현 가능한 근거가 있는가?
  - 절사/반올림 오차가 누적되지 않는가?

### 5. 파트너 대표 — 강사장

- **전문 분야**: 파트너 경험, 정산 투명성, CS 관점, 사업자 실무
- **관점**: 사용자(파트너) 입장의 이해 용이성, 불만 예측, 신뢰 구축
- **주요 질문**:
  - 파트너가 정산 내역을 스스로 이해할 수 있는가?
  - "왜 이 금액인지" 근거를 즉시 확인할 수 있는가?
  - 보류/차감 시 사전 통지와 이의제기 경로가 있는가?
  - 지급 지연/실패 시 파트너가 어떻게 알고 대응하는가?

## Deployment Guide

### 언제 누구를 투입하는가

| 의사결정 상황 | 필수 투입 | 선택 투입 |
|--------------|----------|----------|
| **SRS/요구사항 리뷰** | 전원 (5명) | — |
| **DB 스키마 설계** | 김건축, 최회계 | 이운영 |
| **API 설계** | 김건축, 강사장 | 박법무 |
| **결제/정산 로직** | 김건축, 최회계, 박법무 | 이운영, 강사장 |
| **개인정보 처리** | 박법무 | 김건축 |
| **배치/크론 설계** | 이운영, 김건축 | — |
| **장애 대응 계획** | 이운영 | 김건축 |
| **파트너 화면/UX** | 강사장 | 최회계 |
| **약관/정책 변경** | 박법무, 강사장 | 최회계 |
| **세금/정산서 설계** | 최회계, 박법무 | 강사장 |
| **신규 기능 기획** | 김건축, 강사장 | 상황에 따라 |
| **인시던트 포스트모템** | 이운영, 김건축 | 박법무 |

### 리뷰 프로토콜

1. **투입 대상 결정**: 위 표에 따라 필수/선택 인원 결정
2. **컨텍스트 제공**: 리뷰 대상 문서 + 현재 코드베이스 상태 + 관련 법령/정책
3. **독립 리뷰**: 각 전문가가 자기 관점에서 독립적으로 검토
4. **출력 형식**: 아래 표준 형식 사용
5. **종합**: 전체 이슈를 우선순위 매트릭스로 통합

### 출력 형식 (표준)

각 리뷰어는 다음 카테고리로 이슈를 분류한다:

```
### [이름] — [역할]

#### 빠진 내용 (Missing)
- [M-n] ...

#### 모순 (Contradictions)
- [C-n] ...

#### 모호한 부분 (Ambiguities)
- [A-n] ...

#### 위험 요소 (Risks)
- [R-n] ...

#### 추가 제안 (Proposals)
- [P-n] ...
```

### 우선순위 매트릭스 (종합)

모든 리뷰어의 이슈를 하나의 테이블로 통합한다:

```
| ID | 내용 | 심각도 | 발견자 | 조치 |
|----|------|--------|--------|------|
| M-1 | ... | Critical/High/Medium/Low | 김건축 | ... |
```

**심각도 기준**:
- **Critical**: 서비스 장애, 법적 제재, 금전 사고 직결
- **High**: 운영 리스크, 데이터 무결성, 감사 실패 가능
- **Medium**: 사용자 불만, 비효율, 기술 부채 누적
- **Low**: 개선 권장, 미래 확장성
