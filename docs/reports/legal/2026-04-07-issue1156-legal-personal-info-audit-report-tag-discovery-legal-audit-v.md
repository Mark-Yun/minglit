## 2. Tag Discovery(#1149) 법률 검토 🔴

Tag Discovery Phase 1 MVP가 2026-04-07 머지되었으나, 아래 법률/개인정보 이슈가 식별됨.

### C1: 관심 태그 데이터에 대한 개인정보 수집 고지 누락 🔴 CRITICAL

**현황**: 유저가 관심 태그를 선택할 때 개인정보 수집·이용에 대한 고지/동의 절차가 없음.
**법률 근거**: 개인정보보호법 제15조(수집·이용 동의), 제22조(동의 방법)
**위험**: 관심사 데이터는 개인의 성향·취향을 드러내는 **민감정보에 준하는 개인정보**. 수집 시 반드시 고지 필요.
**조치 필요**:
- 개인정보처리방침에 "관심 태그" 수집 항목 추가
- 앱 동의서(signup consent)의 수집 항목에 "관심 태그" 반영 여부 확인 (PR #1146에서 추가됨 — 순서 확인 필요)
- 태그 선택 UI에서 수집 목적 안내 문구 표시

### C2: 관심 태그 보유기간·파기 정책 미정의 🔴 CRITICAL

**현황**: `user_interest_tags` 테이블에 보유기간/파기 정책이 문서화되지 않음.
**법률 근거**: 개인정보보호법 제21조(파기), 제30조(처리방침 기재사항)
**위험**: 회원 탈퇴 시 `user_interest_tags`가 DB cascade로 삭제되나, 아카이빙/감사 추적 없음.
**조치 필요**:
- 개인정보처리방침에 관심 태그 보유기간 명시
- 탈퇴 시 `process-pending-deletions`에서 관심 태그 아카이빙 또는 삭제 로그 추가 검토

### H1: 파트너 태그 생성 시 민감정보 태그 방지 수단 부재 🟡 HIGH

**현황**: 파트너가 `tags` 테이블에 자유롭게 태그를 생성 가능. 인종, 건강, 성적 지향 등 민감정보에 해당하는 태그 생성 가능.
**법률 근거**: 개인정보보호법 제23조(민감정보 처리 제한)
**위험**: 파트너가 "암_생존자", "LGBTQ+" 등 태그 생성 → 유저가 선택 → 민감정보 수집에 해당 가능
**조치 필요**:
- 태그 생성 가이드라인/금지 목록 수립
- 중장기: 태그 승인 워크플로우 또는 금칙어 필터

### H2: 태그 사용 통계의 2차 활용 범위 미정의 🟡 HIGH

**현황**: `tags.usage_count`, `tag_usage_daily` 테이블에서 태그 인기도를 추적. 집계 데이터이나 2차 활용(마케팅, 제3자 제공 등) 범위가 정의되지 않음.
**법률 근거**: 개인정보보호법 제18조(목적 외 이용·제공 제한)
**조치 필요**:
- 태그 통계 데이터의 이용 범위를 내부 정책으로 정의 (서비스 개선 목적에 한정 등)

### M1: 비로그인 사용자의 태그 메타데이터 접근 🟢 MEDIUM

**현황**: `get_featured_tags()`, `search_tags()` RPC가 비로그인(anon) 사용자에게도 호출 가능.
**위험**: 태그 이름/사용횟수만 노출되므로 직접적 개인정보 유출 없으나, 프론트엔드 로그와 결합 시 간접 프로파일링 가능성.
**조치**: 현 수준에서는 수용 가능하나, 향후 태그에 개인정보성 데이터가 포함될 경우 재검토 필요.

## 3. 2026년 개인정보보호법 개정 영향 평가 📋

2026년 2월 12일 국회 통과, 9월 11일 시행 예정인 개정법의 밍글릿 영향:

### 3-1. 유출 통지 기산점 변경 — 영향 있음 ⚠️

**변경**: "유출 확인 시" → "유출 **가능성 인지** 시"로 앞당겨짐
**영향**: 현재 유출 대응 프로세스가 있다면 기산점 기준을 업데이트해야 함.
**조치**: 유출 대응 매뉴얼/프로세스 확인 및 업데이트 필요 (→ `needs-security`)

### 3-2. 개인정보보호책임자(CPO) 요건 강화 — 확인 필요

**변경**: 일정 규모 이상 사업자는 개인정보보호 경력 2년 포함 4년 이상 경력자를 CPO로 지정
**영향**: 밍글릿의 사업 규모에 따라 해당 여부 판단 필요
**조치**: `report-exec` — 사업 규모 기준 해당 여부 확인 필요

### 3-3. ISMS-P 인증 의무화 — 2027년 7월 시행

**변경**: 매출/처리 규모 기준 초과 시 ISMS-P 인증 의무
**영향**: 현재 규모에서는 비해당 가능성 높으나, 성장에 따라 모니터링 필요
**조치**: 중장기 모니터링 항목으로 관리
