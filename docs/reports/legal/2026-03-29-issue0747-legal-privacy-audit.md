### 🔍 발견 사항

#### [Critical] CI/DI 평문 저장

**법적 근거**: 개인정보보호법 제29조 (안전조치의무), 개인정보의 안전성 확보조치 기준 제7조 (개인정보의 암호화)
**현재 상태**: `supabase/migrations/20260301000002_02_schema_core.sql:17-18`에서 CI/DI가 `text` 타입으로 평문 저장. Vault/pgcrypto 미적용.
**위험**: CI는 주민등록번호를 대체하는 본인확인 연계정보로, 개인정보보호법상 **고유식별정보에 준하는 암호화 대상**. 유출 시 과징금 + 형사처벌 가능. 2026년 9월 시행 예정인 개정법에서는 **매출액 10%까지 징벌적 과징금** 부과 가능.
**권장 조치**: 
1. `pgcrypto` 또는 Supabase Vault를 활용한 CI/DI 암호화 저장
2. CI/DI 조회 시 복호화는 서비스 역할(service_role)에서만 수행
3. DI의 unique 제약은 해시값으로 대체 (`di_hash text unique`, 원문은 암호화 저장)

#### [Critical] 회원 탈퇴(계정 삭제) API 미구현

**법적 근거**: 개인정보보호법 제36조 (개인정보의 정정·삭제), 제37조 (개인정보의 처리정지), 정보통신망법 제30조
**현재 상태**: `auth.users` 삭제 시 `on delete cascade`로 연쇄 삭제는 설정되어 있으나 (`schema_core.sql:10`), **삭제를 트리거하는 Edge Function이 존재하지 않음**. 앱 내 개인정보 페이지(`privacy_page.dart`)도 "준비 중" 플레이스홀더 상태.
**위험**: 개인정보처리방침 제6조에서 "앱 내 [설정 > 계정 관리] 메뉴를 통해 동의 철회(탈퇴) 가능"이라고 명시했으나, **실제로 탈퇴 기능이 없어 허위 고지**에 해당. Apple/Google 앱스토어 정책에서도 계정 삭제 기능을 필수로 요구.
**권장 조치**:
1. `user-delete-account` Edge Function 구현 (auth.admin.deleteUser 호출)
2. 법정 보존 기간 데이터 분리 저장 로직 (전자상거래법 5년 등)
3. 앱 UI에 탈퇴 플로우 구현

#### [High] 개인정보처리방침 - 해외 이전 고지 누락

**법적 근거**: 개인정보보호법 제28조의8 (개인정보의 국외 이전), 2025년 3월 시행 개정법
**현재 상태**: `apps/landing_user/src/app/privacy/page.tsx`의 제4조 "처리 위탁"에서 Supabase, Vercel은 기재되어 있으나, **해외 이전임을 명시하지 않음**. 또한 아래 서비스가 **아예 누락**:
- **Sentry** (에러 모니터링 — 미국 소재, `logger.ts`에서 사용)
- **Axiom** (로그 수집 — 미국 소재, `axiom_logger.ts`에서 사용)
- **Statsig** (분석/실험 — 미국 소재, 다수 Edge Function에서 사용)
- **OpenAI** (임베딩 생성 — 미국 소재, `profile-update` 등에서 사용)
**위험**: 2025년 3월 시행 개정 개인정보보호법에서 국외 이전 시 이전받는 자의 국가, 이전 목적, 이전 항목 등을 정보주체에게 고지하도록 강화됨.
**권장 조치**:
```
| 수탁자 | 국가 | 위탁 업무 | 이전 항목 |
|--------|------|----------|----------|
| Supabase (미국) | 미국 | 서버 운영, DB 호스팅 | 전체 개인정보 |
| Vercel (미국) | 미국 | 웹 호스팅 | 접속 로그 |
| Sentry (미국) | 미국 | 에러 모니터링 | 에러 로그(개인정보 포함 가능) |
| Axiom (미국) | 미국 | 로그 수집 | 서비스 로그(개인정보 포함 가능) |
| Statsig (미국) | 미국 | 서비스 분석 | 이용자 ID, 이벤트 데이터 |
| OpenAI (미국) | 미국 | 프로필 임베딩 생성 | 프로필 텍스트 |
```

#### [High] 환불 정책 — 약관과 코드 불일치

**법적 근거**: 전자상거래법 제17조 (청약철회), 제18조 (청약철회의 효과)
**현재 상태**: 
- **약관 (terms/page.tsx:71-74)**: "3일 전 전액 / 2~1일 전 50% / 당일 불가"
- **코드 (user-cancel-order/index.ts)**: `gracePeriodHours=2` (결제 후 2시간), `cutoffDays=7` (이벤트 7일 전)
- **DB (refund_policy_binary.sql)**: Vault에 정책을 바이너리로 저장, `get_current_policy` RPC로 조회
**위험**: 약관상 환불 기준과 실제 코드 동작이 다름. 소비자가 약관을 믿고 3일 전 취소했는데 코드가 다른 기준을 적용하면 **전자상거래법 위반** + 소비자 분쟁 발생 가능.
**권장 조치**: 약관 문구와 코드 로직을 일치시키거나, DB에 저장된 최신 정책이 약관에 정확히 반영되도록 동기화 체계 구축

#### [High] 앱 내 개인정보 동의 수집 흐름 미구현

**법적 근거**: 개인정보보호법 제15조 (개인정보의 수집·이용), 제22조 (동의를 받는 방법)
**현재 상태**: 회원가입 시 **명시적 동의 수집 UI 없음**. 본인인증(Portone) 진행 시에도 별도 동의 절차 없이 CI/DI/이름/생년월일/성별/휴대폰번호를 수집·저장. 마케팅 동의는 가입 시 수집하지 않고, 설정에서만 변경 가능.
**위험**: 개인정보보호법 제22조에 따라 서비스 제공에 필수인 정보와 선택 정보를 구분하여 동의를 받아야 하며, 필수 동의를 거부해도 서비스 이용이 가능해야 함(선택 항목 한정).
**권장 조치**:
1. 회원가입 시 개인정보 수집·이용 동의 UI 구현 (필수/선택 분리)
2. 본인인증 전 CI/DI 수집에 대한 별도 동의 수집
3. 마케팅 동의를 가입 시 선택적으로 수집 (현재 settings에서만 가능)
4. 동의 이력(일시, 버전) DB 저장

**법적 근거**: 개인정보보호법 제29조 (안전조치의무)
**현재 상태**:

- Axiom, Sentry 모두 해외 서비스 → 로그에 개인정보 포함 시 **의도치 않은 국외 이전**
**권장 조치**: 로그 출력 전 개인정보 필드(name, phone, birth_date, ci, di) 마스킹 유틸리티 적용
