# 06. UX Writing — UX 라이팅 가이드

밍릿 앱의 텍스트 작성 규칙입니다.

> **토스 원칙 참고**: 존댓말 통일, 간결체, 이모지 최소화 원칙을 따릅니다.
> (출처: 토스 디자인 시스템 TDS — UX Writing 가이드)

---

## 1. 톤 앤 매너

### 기본 원칙

| 원칙 | 설명 | 예시 |
| :--- | :--- | :--- |
| 존댓말 통일 | ~해요 체 사용, ~합니다 체 지양 | "신청이 완료됐어요" (O) / "신청이 완료되었습니다" (X) |
| 간결체 | 불필요한 단어 제거 | "카드 정보를 확인해주세요" (O) / "카드 정보를 한번 확인해 주시기 바랍니다" (X) |
| 이모지 최소화 | 핵심 정보에만 최소한으로 사용 | 텍스트에 이모지 남발 금지 |
| 사용자 중심 | 시스템 관점이 아닌 사용자 관점 | "결제에 실패했어요" (O) / "Payment Error 500" (X) |

> (출처: 토스 디자인 시스템 TDS — 톤앤매너 원칙. 코드/에셋 복사 아님, 원칙만 참고)

## 2. 버튼 라벨

### 규칙

- **동사형** 사용: 명확한 행동을 나타내는 동사로 시작
- **구체적** 표현: "확인", "다음" 같은 모호한 라벨 지양

### 예시

| 상황 | 좋은 예 | 나쁜 예 |
| :--- | :--- | :--- |
| 이벤트 신청 | "신청하기" | "확인" |
| 환불 요청 | "환불 요청하기" | "다음" |
| 파티 생성 | "파티 만들기" | "완료" |
| 결제 진행 | "결제하기" | "진행" |
| 삭제 | "삭제하기" | "예" |
| 취소 (다이얼로그) | "취소" | "아니오" |

### 버튼 쌍 규칙

| 유형 | Primary | Secondary |
| :--- | :--- | :--- |
| 확인/취소 | "[행동]하기" | "취소" |
| 파괴적 행동 | "[행동]하기" (error 색상) | "돌아가기" |
| 선택지 | "[선택A]" | "[선택B]" |

## 3. 에러 메시지

### 규칙

- **원인 + 해결 방법**을 함께 제공
- 기술적 용어 사용 금지 (HTTP 코드, 예외 이름 등)

### 예시

| 상황 | 메시지 |
| :--- | :--- |
| 결제 실패 | "결제에 실패했어요. 카드 정보를 확인해주세요." |
| 네트워크 오류 | "인터넷 연결이 불안정해요. 잠시 후 다시 시도해주세요." |
| 서버 오류 | "일시적인 문제가 발생했어요. 잠시 후 다시 시도해주세요." |
| 권한 없음 | "이 기능을 사용하려면 본인인증이 필요해요." |
| 입력 오류 | "올바른 이메일 형식으로 입력해주세요." |
| 중복 신청 | "이미 신청한 이벤트예요." |

### 구조

```text
[원인 설명] + [해결 방법/안내]
```

## 4. 빈 상태 메시지

### 규칙

- 현재 상태를 알려주고 **다음 행동을 유도**
- 부정적 어투 지양 ("없습니다" 대신 "아직 ~가 없어요")

### 예시

| 상황 | 메시지 | 행동 유도 |
| :--- | :--- | :--- |
| 이벤트 없음 (유저) | "아직 참여한 이벤트가 없어요" | "둘러보러 가볼까요?" + 버튼 |
| 파티 없음 (파트너) | "아직 만든 파티가 없어요" | "첫 파티를 만들어보세요" + 버튼 |
| 알림 없음 | "새로운 알림이 없어요" | (행동 유도 불필요) |
| 검색 결과 없음 | "검색 결과가 없어요" | "다른 검색어로 시도해보세요" |
| 정산 내역 없음 | "아직 정산 내역이 없어요" | "이벤트를 진행하면 정산 내역이 여기에 나타나요" |

## 5. 토스트 / Snackbar

### 규칙

- **결과 알림** 용도로만 사용
- **짧고 명확하게** (1줄 이내)
- 행동 완료 후 피드백에 사용

### 예시

| 상황 | 메시지 |
| :--- | :--- |
| 신청 완료 | "신청이 완료됐어요" |
| 저장 완료 | "저장했어요" |
| 복사 완료 | "클립보드에 복사했어요" |
| 삭제 완료 | "삭제했어요" |
| 신청 취소 | "신청을 취소했어요" |

### 사용하지 않는 경우

- 에러 알림 (에러는 인라인 또는 다이얼로그로 표시)
- 긴 설명이 필요한 경우
- 사용자 행동 없이 자동 발생하는 알림

## 6. 확인 다이얼로그

### 규칙

- **되돌릴 수 없는 행동**에만 사용 (삭제, 취소, 탈퇴 등)
- 결과를 명확하게 설명
- 파괴적 행동의 Primary 버튼은 `MinglitColors.error` (`#EF4444`) 색상 사용

### 예시

| 상황 | 제목 | 본문 | Primary | Secondary |
| :--- | :--- | :--- | :--- | :--- |
| 이벤트 취소 | "정말 취소할까요?" | "환불은 영업일 기준 3일 소요돼요." | "취소하기" (error) | "돌아가기" |
| 파티 삭제 | "파티를 삭제할까요?" | "파티에 포함된 이벤트와 신청 내역도 모두 삭제돼요." | "삭제하기" (error) | "돌아가기" |
| 로그아웃 | "로그아웃할까요?" | (본문 불필요) | "로그아웃" | "취소" |
| 회원 탈퇴 | "정말 탈퇴할까요?" | "모든 데이터가 삭제되며 복구할 수 없어요." | "탈퇴하기" (error) | "돌아가기" |

### 사용하지 않는 경우

- 되돌릴 수 있는 행동 (수정, 저장 등)
- 단순 정보 전달 (알림, 안내)

## 7. 숫자/날짜 표기

### 규칙

| 항목 | 형식 | 예시 |
| :--- | :--- | :--- |
| 금액 | 천 단위 쉼표 + "원" | "50,000원" |
| 날짜 | "M월 d일 (요일)" | "3월 25일 (화)" |
| 날짜 + 시간 | "M월 d일 (요일) HH:mm" | "3월 25일 (화) 19:00" |
| 기간 | "M월 d일 ~ M월 d일" | "3월 25일 ~ 3월 30일" |
| 인원수 | "N명" | "12명" |
