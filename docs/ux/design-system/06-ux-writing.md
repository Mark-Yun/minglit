# 06. UX Writing — UX 라이팅 가이드

밍릿 앱의 텍스트 작성 규칙입니다.

> **참고**: 토스 디자인 시스템(TDS)의 라이팅 원칙을 기반으로, 소셜 이벤트 플랫폼에 맞게 적용했습니다.

---

## Layer 1: 핵심 가치

### 명확함 (Clear)

하나의 문장 = 하나의 메시지. 여러 의미로 해석될 수 있는 표현을 피해요.

### 간결함 (Concise)

빼도 의미가 변하지 않는 단어는 빼요.

### 친근함 (Casual)

문서가 아닌 대화처럼 써요. 소리 내어 읽었을 때 자연스러운지 확인해요.

---

## Layer 2: 보이스 & 톤 규칙

### 1. 해요체 통일

모든 상황에서 ~해요 체를 사용해요. 에러, 법적 문구, 시스템 메시지도 예외 없이.

| 사용 | 지양 |
| :--- | :--- |
| 신청이 완료됐어요 | 신청이 완료되었습니다 |
| 카드 정보를 확인해주세요 | 카드 정보를 확인해 주시기 바랍니다 |

### 2. 능동태 우선

수동태는 아래 3가지 경우에만 허용:

| 허용 케이스 | 예시 |
| :--- | :--- |
| 서비스 종료/만료 | 이벤트가 종료됐어요 |
| 사용자 영향 메시지 | 신청이 취소됐어요 |
| 데이터 보호 안심 | 정보는 암호화되어 저장돼요 |

### 3. 긍정 프레이밍

부정어 대신 긍정으로 전환:

| 지양 | 사용 |
| :--- | :--- |
| 신청할 수 없어요 | 본인인증을 완료하면 신청할 수 있어요 |
| 결과가 없어요 | 다른 검색어로 시도해보세요 |

### 4. 존칭 최소화

과도한 존칭 제거:

| 지양 | 사용 |
| :--- | :--- |
| 참여하고 계신 | 참여 중인 |
| 확인해 주시겠어요? | 확인해주세요 |

### 5. 감정 인식 (숨겨진 감정 찾기)

모든 인터랙션에는 감정적 맥락이 있어요. 특히 소셜 이벤트 앱에서는:

- 이벤트 신청 = 설렘 + 사회적 불안
- 매칭 결과 = 기대 + 긴장
- 환불 = 실망 + 아쉬움

| 상황 | 기계적 | 감정 인식 |
| :--- | :--- | :--- |
| 이벤트 신청 완료 | 신청이 완료됐어요 | [파티 이름]에 함께하게 됐어요! |
| 매칭 성공 | 매칭이 완료됐어요 | 서로 마음이 통했어요 💜 |
| 환불 완료 | 환불 처리가 완료됐어요 | 환불이 완료됐어요. 다음에 더 좋은 이벤트에서 만나요 |

## Layer 3: 컴포넌트별 라이팅 규칙

### 6. 버튼 라벨

규칙:

- 동사형 `~하기` 사용
- 구체적 행동 표현 ("확인", "다음" 지양)
- 다음 화면을 예측할 수 있게 (TDS Principle 1: Predictable Hint)

| 상황 | 좋은 예 | 나쁜 예 | 이유 |
| :--- | :--- | :--- | :--- |
| 이벤트 신청 | 신청하기 | 확인 | 탭 후 어떤 일이 일어나는지 예측 가능 |
| 환불 요청 | 환불 요청하기 | 다음 | |
| 파티 생성 | 파티 만들기 | 완료 | |
| 결제 진행 | 결제하기 | 진행 | |
| 삭제 | 삭제하기 | 예 | |
| 취소 (다이얼로그) | 돌아가기 | 아니오 | |
| 다이얼로그 닫기 | 닫기 | 취소 | "취소"는 거래 취소와 혼동 |

버튼 쌍 규칙:

| 유형 | Primary | Secondary |
| :--- | :--- | :--- |
| 확인/취소 | [행동]하기 | 닫기 / 돌아가기 |
| 파괴적 행동 | [행동]하기 (error 색상) | 돌아가기 |
| 선택지 | [선택A] | [선택B] |

### 7. 에러 메시지

6가지 원칙:

1. **최고의 에러는 나타나지 않는 에러** — UX로 에러 자체를 제거할 수 있는지 먼저 검토
2. **적절한 컴포넌트 사용** — 심각도에 맞는 UI (토스트 vs 인라인 vs 다이얼로그)
3. **자력 해결 경로 제공** — [상황] + [원인] + [해결 방법]
4. **사용자 언어로 작성** — 기술 용어 금지
5. **해결 마찰 최소화** — 해결에 필요한 행동을 버튼으로 제공
6. **부정적 감정 최소화** — 비난이 아닌 안내

구조:

```text
[상황 설명] + [원인] + [해결 방법/안내]
```

| 상황 | 메시지 | 컴포넌트 |
| :--- | :--- | :--- |
| 결제 실패 | 결제에 실패했어요. 카드 정보를 확인해주세요. | 다이얼로그 |
| 네트워크 오류 | 인터넷 연결이 불안정해요. 잠시 후 다시 시도해주세요. | 인라인 |
| 서버 오류 | 일시적인 문제가 발생했어요. 잠시 후 다시 시도해주세요. | 인라인 |
| 권한 없음 | 이 기능을 사용하려면 본인인증이 필요해요. | 다이얼로그 + 버튼 |
| 입력 오류 | 올바른 이메일 형식으로 입력해주세요. | 인라인 (필드 아래) |
| 중복 신청 | 이미 신청한 이벤트예요. | 토스트 |
| 이벤트 마감 | 아쉽지만 모집이 마감됐어요. 다음 이벤트를 기대해주세요. | 다이얼로그 |
| 본인인증 실패 | 본인인증이 안 됐어요. 다시 시도하거나 고객센터에 문의해주세요. | 다이얼로그 + 버튼 |

### 8. 빈 상태 메시지

규칙:

- 현재 상태를 알려주고 다음 행동을 유도
- 부정적 어투 지양 ("없습니다" → "아직 ~가 없어요")
- 감정 인식: 빈 상태 ≠ 에러, 시작의 기회

| 상황 | 메시지 | 행동 유도 |
| :--- | :--- | :--- |
| 이벤트 없음 (유저) | 아직 참여한 이벤트가 없어요 | 새로운 이벤트를 둘러볼까요? + 버튼 |
| 파티 없음 (파트너) | 아직 만든 파티가 없어요 | 첫 파티를 만들어보세요 + 버튼 |
| 알림 없음 | 새로운 알림이 없어요 | (행동 유도 불필요) |
| 검색 결과 없음 | 검색 결과가 없어요 | 다른 검색어로 시도해보세요 |
| 정산 내역 없음 | 아직 정산 내역이 없어요 | 이벤트를 진행하면 정산 내역이 여기에 나타나요 |
| 매칭 결과 없음 | 아직 매칭 결과가 없어요 | 이벤트가 끝나면 결과를 알려드릴게요 |
| 티켓 없음 | 아직 티켓이 없어요 | 이벤트에 참여하면 티켓이 생겨요 |

### 9. 토스트 / Snackbar

규칙:

- **결과 알림** 용도로만 사용
- **짧고 명확하게** (1줄 이내)
- 행동 완료 후 피드백에 사용

| 상황 | 메시지 |
| :--- | :--- |
| 신청 완료 | 신청이 완료됐어요 |
| 저장 완료 | 저장했어요 |
| 복사 완료 | 클립보드에 복사했어요 |
| 삭제 완료 | 삭제했어요 |
| 신청 취소 | 신청을 취소했어요 |

사용하지 않는 경우:

- 에러 알림 (에러는 인라인 또는 다이얼로그로 표시)
- 긴 설명이 필요한 경우
- 사용자 행동 없이 자동 발생하는 알림

### 10. 확인 다이얼로그

규칙:

- **되돌릴 수 없는 행동**에만 사용 (삭제, 취소, 탈퇴 등)
- 결과를 명확하게 설명
- 파괴적 행동의 Primary 버튼은 `MinglitColors.error` (`#EF4444`) 색상 사용

| 상황 | 제목 | 본문 | Primary | Secondary |
| :--- | :--- | :--- | :--- | :--- |
| 이벤트 취소 | 정말 취소할까요? | 환불은 영업일 기준 3일 소요돼요. | 취소하기 (error) | 돌아가기 |
| 파티 삭제 | 파티를 삭제할까요? | 파티에 포함된 이벤트와 신청 내역도 모두 삭제돼요. | 삭제하기 (error) | 돌아가기 |
| 로그아웃 | 로그아웃할까요? | (본문 불필요) | 로그아웃 | 닫기 |
| 회원 탈퇴 | 정말 탈퇴할까요? | 모든 데이터가 삭제되며 복구할 수 없어요. | 탈퇴하기 (error) | 돌아가기 |

사용하지 않는 경우:

- 되돌릴 수 있는 행동 (수정, 저장 등)
- 단순 정보 전달 (알림, 안내)

## Layer 4: 상황별 가이드

### 11. 로딩 상태 문구

규칙:

- 시스템이 사용자를 위해 무언가를 하고 있다는 느낌
- 구체적인 작업 이름 사용 (단순 "로딩중" 지양)
- 3초 이상 걸리면 진행 상황 컨텍스트 제공

| 상황 | 지양 | 사용 |
| :--- | :--- | :--- |
| 일반 데이터 로드 | 로딩 중... | 잠깐만요 |
| 결제 처리 | 처리 중입니다 | 결제를 확인하고 있어요 |
| 본인인증 | 인증 처리 중 | 본인인증을 확인하고 있어요 |
| 이벤트 목록 | 불러오는 중 | 이벤트를 찾고 있어요 |
| 매칭 결과 | 로딩 중 | 매칭 결과를 확인하고 있어요 |
| 첫 진입 설정 | 준비 중 | 거의 다 됐어요 |

### 12. 성공 상태 문구

구조:

```text
[구체적 결과] + [감정 인정 or 다음 행동 안내]
```

규칙:

- 무엇이 완료됐는지 구체적으로 (단순 "완료" 지양)
- 노력이 필요한 행동 후에는 감정 인정
- 능동태 사용

| 상황 | 지양 | 사용 |
| :--- | :--- | :--- |
| 이벤트 신청 | 신청이 완료되었습니다 | [이벤트명]에 신청했어요! 승인되면 알려드릴게요 |
| 결제 완료 | 결제 처리가 완료되었습니다 | [금액]원 결제가 완료됐어요 |
| 파티 생성 (파트너) | 파티가 생성되었습니다 | 파티가 만들어졌어요! 이벤트를 추가해볼까요? |
| 환불 완료 | 환불 처리 완료 | 환불이 완료됐어요. 영업일 기준 3일 내에 입금돼요 |
| 본인인증 완료 | 인증이 완료되었습니다 | 본인인증이 완료됐어요 |
| 매칭 성공 | 매칭이 완료됐어요 | 서로 마음이 통했어요! |
| 파트너 신청 승인 | 승인 처리가 완료되었습니다 | 파트너 신청이 승인됐어요. 이제 파티를 만들 수 있어요! |

### 13. 권한 요청 문구

2-layer 구조:

1. **사전 안내 화면** (앱 제어): 왜 필요한지 설명
2. **OS 권한 다이얼로그** (시스템 제어): 커스텀 불가

규칙:

- 앱 첫 실행 시 한꺼번에 요청하지 않음 — 기능 사용 시점에 요청
- 필수/선택 명확히 구분
- 거부 후에는 설정 딥링크 제공, OS 다이얼로그 재호출 금지

구조:

```text
[기능]을 위해 [권한]이 필요해요
→ [구체적 혜택 한 줄]
→ (필수) 또는 (선택) 표기
```

| 권한 | 사전 안내 문구 | 요청 시점 |
| :--- | :--- | :--- |
| 위치 | 근처 이벤트를 찾으려면 위치 정보가 필요해요 | "가까운 거리" 필터 첫 탭 시 |
| 카메라 | 프로필 사진을 업로드하려면 카메라 접근이 필요해요 | 프로필 편집에서 사진 촬영 선택 시 |
| 갤러리 | 프로필 사진을 선택하려면 갤러리 접근이 필요해요 | 프로필 편집에서 갤러리 선택 시 |
| 알림 | 이벤트 승인, 매칭 결과 등 중요한 소식을 알려드려요 | 첫 이벤트 신청 완료 직후 |

거부 후 복구:

```text
설정에서 [권한]을 허용하면 [기능]을 사용할 수 있어요
→ [설정으로 이동] 버튼
```

### 14. 인풋 플레이스홀더

규칙:

- 질문형 또는 예시형 사용 — 명사 라벨 지양
- 사용자 관점에서 작성
- 형식 제약이 있으면 힌트에 포함

| 필드 | 지양 | 사용 |
| :--- | :--- | :--- |
| 검색 | 검색 | 어떤 이벤트를 찾고 있나요? |
| 이메일 | 이메일 입력 | example@email.com |
| 전화번호 | 전화번호 | 010-0000-0000 |
| 파티 이름 | 파티 이름 입력 | 어떤 파티인가요? (예: 금요일 와인 모임) |
| 파티 설명 | 설명 입력 | 파티에 대해 소개해주세요 |
| 가격 | 금액 입력 | 0 |
| 장소 검색 | 장소 | 장소 이름이나 주소를 검색해보세요 |
| 거절 사유 | 사유 입력 | 거절 사유를 작성해주세요 |

### 15. 푸시 알림 문구

규칙:

- Predictable Hint: 알림만 보고 내용이 나에게 관련 있는지 판단 가능해야
- 이모지, 낚시 표현 금지 (`지금 당장`, `놓치면 끝`, `마지막 기회`)
- 강요 아닌 안내

구조:

```text
Title: [핵심 정보 한 줄]
Body:  [왜 나에게 관련 있는지] + [행동 유도, optional]
```

| 상황 | Title | Body |
| :--- | :--- | :--- |
| 신청 승인 | [이벤트명] 신청이 승인됐어요 | 이벤트 상세를 확인해보세요 |
| 신청 거절 | [이벤트명] 신청 결과를 확인해주세요 | — |
| 이벤트 리마인더 | [이벤트명]이 내일이에요 | 참가자 [N]명이 기다리고 있어요 |
| 매칭 결과 | 매칭 결과가 나왔어요 | 확인해볼까요? |
| 새 신청 (파트너) | 새로운 신청이 [N]건 도착했어요 | [이벤트명]을 확인해보세요 |
| 정산 완료 (파트너) | [금액]원이 정산됐어요 | [이벤트명] 정산이 완료됐어요 |
| 이벤트 변경 | [이벤트명] 정보가 변경됐어요 | 일시/장소 변경 사항을 확인해주세요 |
| 이벤트 취소 | [이벤트명]이 취소됐어요 | 환불은 영업일 기준 3일 내에 처리돼요 |

### 16. 법적/약관 문구

규칙:

- 법적 필요성이 보이스 일관성을 깨뜨리지 않아요 — 해요체 유지
- 어려운 법률 용어 대신 쉬운 말
- 긴 약관은 핵심 요약을 위에 배치

| 상황 | 지양 | 사용 |
| :--- | :--- | :--- |
| 동의 체크박스 | 개인정보 수집 및 이용에 동의합니다 | 개인정보 수집 및 이용에 동의해요 |
| 약관 화면 제목 | 이용약관 동의 | 시작하기 전에 확인해주세요 |
| 데이터 안내 | 본 서비스는 위치정보를 수집합니다 | 위치 정보를 활용해 가까운 이벤트를 찾아드려요 |
| 결제 동의 | 결제에 동의하시겠습니까? | [금액]원을 결제할까요? |
| 데이터 보호 | 개인정보는 안전하게 보호됩니다 | 정보는 암호화되어 저장돼요 |

### 17. 숫자/날짜 표기

#### 금액

| 형식 | 예시 | 비고 |
| :--- | :--- | :--- |
| 기본 | 50,000원 | 천 단위 쉼표, "원" 붙임 |
| 대단위 | 1만 원, 100만 원 | 본문에서 6자리 이상은 한글 단위 |
| 범위 | 3만~5만 원 | 물결표 양쪽 공백 없음 |
| 무료 | 무료 | "0원" 대신 "무료" |

#### 날짜/시간

| 형식 | 예시 | 사용처 |

| 기간 | 3월 25일 ~ 3월 30일 | 이벤트 기간 |
| 상대 시간 | 방금, 5분 전, 어제, 3일 전 | 알림, 채팅 (7일 이내) |
| 절대 시간 | 3월 20일 | 알림, 채팅 (7일 초과) |

#### 퍼센트

| 변동 | +3%, -1.2% | 부호 포함 |
| 수수료 | 3.5% | 소수점 필요 시 표기 |

#### 전화번호

| 형식 | 예시 |

## Layer 5: 용어 사전

밍릿 앱에서 통일하여 사용하는 도메인 용어입니다.

### 핵심 도메인 용어

| 용어 | 정의 | 사용 맥락 | 지양 표현 |
| :--- | :--- | :--- | :--- |
| 파티 | 파트너가 운영하는 모임/공간 단위 | 파티 목록, 파티 상세 | 모임, 장소, 매장 |
| 이벤트 | 파티 안에서 열리는 개별 일정 | 이벤트 목록, 이벤트 상세, 이벤트 신청 | 행사, 일정, 세션 |
| 파트너 | 파티를 운영하는 사업자 | 파트너 앱 전반 | 운영자, 호스트, 업주, 사장님 |
| 신청 | 사용자가 이벤트에 참여를 요청하는 행위 | 신청하기, 신청 목록 | 예약, 등록, 접수 |
| 티켓 | 이벤트 참여를 증명하는 디지털 증서 | 티켓 목록, QR 티켓 | 입장권, 예약증 |
| 정산 | 이벤트 수익을 파트너에게 지급하는 과정 | 정산 내역, 정산 완료 | 수익 배분, 대금 지급 |
| 매칭 | 이벤트 참여자 간 상호 선택 기능 | 매칭 투표, 매칭 결과 | 소개팅, 연결 |
| 본인인증 | 실명/나이/성별 확인 (Layer 1) | 본인인증 완료, 본인인증 필요 | 신원 확인, 실명 인증 |
| 자격 인증 | 파트너가 요구하는 추가 자격 확인 (Layer 2) | 자격 인증 제출, 자격 인증 승인 | 서류 제출, 자격 확인 |

### UI 용어 통일

| 사용 | 지양 | 이유 |
| :--- | :--- | :--- |
| 닫기 | 취소 (다이얼로그 dismiss) | "취소"는 거래 취소와 혼동 |
| 돌아가기 | 취소 (파괴적 행동 secondary) | |
| 확인했어요 | 확인합니다 | 해요체 |
| 동의해요 | 동의합니다 | 해요체 |
| ~이 안 됐어요 | 에러가 발생했습니다 | 사용자 언어 |
| 확인하고 있어요 | 처리 중입니다 | 능동태 |
| ~할 수 있어요 | ~해야 해요 | 긍정 프레이밍 |
