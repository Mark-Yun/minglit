# 에러 시나리오 테스트 케이스

> 목적: 핵심 플로우에서 발생할 수 있는 에러/예외 상황이 적절히 처리되는지 검증.
> 각 시나리오는 정상 플로우(CUJ)의 실패 분기를 독립적으로 테스트한다.

---

## 우선순위 정의

| 등급 | 의미 | 기준 |
|------|------|------|
| **P1** | 핵심 경로 에러 | 결제/체크인/인증 실패 — 유저/파트너 이탈 직결 |
| **P2** | 보조 경로 에러 | 탐색/관리 기능 에러 — 불편하지만 서비스 이용 가능 |

---

## P1 에러 시나리오

### ERR-01: QR 토큰 발급 실패/만료 [P1] — app_user

> 관련: CUJ-U02 Step 2, PR #1206
> 코드: `TicketQRScreen` → `TicketWalletRepository.getTicket()` → `TicketQRViewer`

#### 사전 조건
- 로그인 + 본인인증 완료 유저
- 승인된 이벤트 신청 1건 (status: approved)
- 이벤트가 당일 (체크인 가능 시간)

#### 시나리오 스텝

| # | 시나리오 | 화면 | 액션 | 기대 결과 |
|---|----------|------|------|-----------|
| ERR-01-A | 토큰 미존재 | 티켓 QR (`TicketQRScreen`) | QR 표시 진입 — SecureStorage에 토큰 없음 | 에러 상태 표시 + "QR 코드를 불러올 수 없습니다" + 재시도 버튼 |
| ERR-01-B | 토큰 만료 | 티켓 QR | QR 표시 진입 — `expiresAt` 과거 시간 | 만료 안내 메시지 + 토큰 재발급 유도 (또는 자동 갱신) |
| ERR-01-C | 토큰 서명 불일치 | 체크인 현장 (파트너 스캔) | 파트너가 유저 QR 스캔 | `CheckinResult.invalid` → "유효하지 않은 QR 코드" |
| ERR-01-D | 네트워크 오류 시 토큰 접근 | 티켓 QR | 오프라인 상태에서 QR 표시 | SecureStorage에 캐시된 토큰으로 QR 정상 표시 (오프라인 지원) |
| ERR-01-E | 다른 이벤트 QR 스캔 | 체크인 현장 | 이벤트 A 체크인에서 이벤트 B QR 스캔 | `CheckinResult.invalid` + "이 이벤트의 QR이 아닙니다" |

#### 검증 포인트
- [ ] SecureStorage 접근 실패 시 앱 크래시 없이 에러 UI 표시
- [ ] 만료 토큰 감지 후 재발급 플로우가 존재하는가
- [ ] 오프라인에서도 캐시된 토큰으로 QR 표시 가능한가
- [ ] 유효하지 않은 QR 스캔 시 파트너 앱에서 명확한 에러 피드백

### ERR-02: QR 스캔 카메라 권한 거부 [P1] — app_partner

> 관련: CUJ-P03 Step 2, CUJ-P03-V1
> 코드: `QRScannerScreen` → `MobileScannerController` → `checkin_controller.dart`

#### 사전 조건
- PARTNER 상태
- 당일 이벤트 존재 (승인된 신청자 있음)

#### 시나리오 스텝

| # | 시나리오 | 화면 | 액션 | 기대 결과 |
|---|----------|------|------|-----------|
| ERR-02-A | 최초 권한 요청 거부 | QR 스캐너 (`QRScannerScreen`) | 카메라 권한 다이얼로그에서 "거부" | 권한 필요 안내 + 설정 이동 버튼 |
| ERR-02-B | 영구 거부 (Don't ask again) | QR 스캐너 | 카메라 권한 영구 거부 상태에서 진입 | "카메라 권한이 필요합니다" + 시스템 설정 열기 버튼 |
| ERR-02-C | 권한 있지만 카메라 하드웨어 오류 | QR 스캐너 | 카메라 초기화 실패 | 에러 메시지 + 재시도 버튼 |
| ERR-02-D | 스캔 중 권한 철회 | QR 스캐너 | 스캔 진행 중 설정에서 권한 제거 | 카메라 중지 + 권한 재요청 안내 |

#### 검증 포인트
- [ ] MobileScanner 라이브러리의 권한 거부 시 콜백이 UI에 정확히 반영되는가
- [ ] 시스템 설정으로 이동 후 앱 복귀 시 카메라가 자동 재활성화되는가
- [ ] 권한 거부 상태에서 수동 체크인 대안이 제공되는가 (이름 검색 등)
- [ ] 앱 크래시 없이 모든 권한 상태를 graceful하게 처리하는가

### ERR-03: 파트너 신청 보완 요청 재제출 [P1] — app_partner

> 관련: CUJ-P01-V1, `needsCorrection` 상태
> 코드: `PartnerApplyStatusPage` → `PartnerApplyPage` → `PartnerApplyController` → `PartnerApplicationRepository`

#### 사전 조건
- 로그인 상태
- 파트너 신청 상태: `needsCorrection`
- 관리자가 보완 사유(`adminComment`) 작성 완료

#### 시나리오 스텝

| # | 시나리오 | 화면 | 액션 | 기대 결과 |
|---|----------|------|------|-----------|
| ERR-03-A | 보완 요청 확인 | 신청 상태 (`/apply/status`) | 앱 진입 | `needsCorrection` 상태 표시 + `adminComment` 내용 표시 + "수정하기" 버튼 |
| ERR-03-B | 수정 위저드 진입 | 신청 상태 | "수정하기" 탭 | `/apply` 위저드로 이동 — 기존 작성 데이터 프리필 |
| ERR-03-C | 데이터 프리필 검증 | 신청 위저드 (`/apply`) | 각 스텝 확인 | 5개 스텝 모두 이전 제출 데이터가 정확히 채워져 있음 |
| ERR-03-D | 부분 수정 후 재제출 | 신청 위저드 | 보완 요청된 필드만 수정 → 제출 | 상태 `needsCorrection` → `pending` 변경 → `/apply/status`로 이동 ("심사 중") |
| ERR-03-E | 재제출 실패 (서버 오류) | 신청 위저드 Step 5 | 제출 시 서버 오류 | 에러 메시지 + 재시도 버튼 — 작성 데이터 유실 없음 |
| ERR-03-F | 위저드 중간 이탈 | 신청 위저드 Step 3 | 앱 종료 후 재진입 | 자동 저장된 데이터로 이어서 작성 가능 |

#### 검증 포인트
- [ ] `adminComment`가 신청 상태 페이지에 정확히 표시되는가
- [ ] 프리필 시 이미지/서류 파일도 복원되는가 (SecureStorage/서버 참조)
- [ ] `status IN ('draft', 'needs_correction')` 조건에서만 수정 가능한가 (RLS 정책)
- [ ] 재제출 후 `onboardingStateProvider` invalidate → 라우터 리다이렉트 정상 동작
- [ ] 보완 요청 2회 이상 반복 시에도 플로우가 정상 동작하는가
