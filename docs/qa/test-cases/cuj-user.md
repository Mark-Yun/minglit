# 유저 앱 (app_user) CUJ 테스트 시나리오

> CUJ = Critical User Journey
>
> 목적: 핵심 유저 플로우가 end-to-end로 정상 동작하는지 검증.
> 각 시나리오는 여러 화면을 걸쳐 하나의 완결된 비즈니스 목표를 달성하는 과정을 테스트한다.

---

## 우선순위 정의

| 등급 | 의미 | 기준 |
|------|------|------|
| **P0** | 핵심 수익 경로 | 결제/매칭 — 실패 시 서비스 가치 없음 |
| **P1** | 필수 사용자 경험 | 가입/인증/알림 — 실패 시 유저 이탈 |
| **P2** | 보조 기능 | 설정/관리 — 실패 시 불편하지만 서비스 이용 가능 |

---

## CUJ-U01: 회원가입 → 본인인증 → 이벤트 탐색 → 결제 → 신청 완료 [P0]

> 밍글릿의 핵심 수익 경로. 유저가 이벤트를 발견하고 티켓을 구매하는 전체 플로우.

### 사전 조건
- 신규 유저 (계정 없음)
- 유효한 이벤트 1건 이상 존재 (status: scheduled, 마감 전)
- PG 결제 가능 상태

### 시나리오 스텝

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|
| 1 | 홈 (`/`) | 앱 진입 | 이벤트 목록 표시 | 네트워크 오류 → 에러 화면 + 재시도 |
| 2 | 홈 | 이벤트 카드 탭 | 이벤트 상세로 이동 | - |
| 3 | 이벤트 상세 (`/events/:id`) | "신청하기" 버튼 탭 | GUEST → `/login?from=/events/:id/apply` | - |
| 4 | 로그인 (`/login`) | 소셜 로그인 (카카오/구글/애플) | OAuth 플로우 → `/auth/callback` → 신청 위저드로 복귀 | OAuth 실패 → 에러 메시지 + 재시도 |
| 5 | 신청 위저드 (`/events/:id/apply`) | 티켓 선택 스텝 | 티켓 옵션 표시 → 선택 | 매진 → "매진되었습니다" 안내 |
| 6 | 신청 위저드 | 본인인증 스텝 | `/certification` → 본인인증 진행 | 인증 실패 → 재시도 안내 |
| 7 | 신청 위저드 | 결제 스텝 | PG 결제 화면 → 결제 완료 | 결제 실패 → "결제에 실패했습니다" + 재시도 |
| 8 | 신청 위저드 | 신청 완료 | 완료 화면 표시 + 신청 정보 요약 | - |

### 검증 포인트
- [ ] 로그인 후 `from` 파라미터로 신청 위저드에 정확히 복귀하는가
- [ ] 본인인증 완료 상태가 서버에 저장되는가
- [ ] 결제 완료 후 DB에 payment + application 레코드 생성되는가
- [ ] 구매 내역(`/purchase-history`)에 결제 항목이 나타나는가

### 변형 시나리오

| 변형 | 차이점 | 추가 검증 |
|------|--------|-----------|
| U01-V1: 기존 유저 재구매 | Step 4 스킵 (이미 로그인), Step 6 스킵 (이미 본인인증) | 스텝 자동 스킵 정상 동작 |
| U01-V2: 결제 중 앱 종료 | Step 7에서 앱 종료 후 재진입 | 미완료 결제 상태 처리 (pending → timeout) |
| U01-V3: 무료 이벤트 신청 | 가격 0원 티켓 | 결제 스텝 스킵, 바로 신청 완료 |

## CUJ-U02: 이벤트 참가 → 체크인 → 매칭 투표 → 매칭 결과 확인 [P0]

> 이벤트 당일 유저 경험. 체크인 → 매칭이 밍글릿의 핵심 가치.

### 사전 조건
- 로그인 + 본인인증 완료 유저
- 승인된 이벤트 신청 1건 (status: approved)
- 이벤트가 당일 (체크인 가능 시간)

### 시나리오 스텝

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|
| 1 | 구매 내역 (`/purchase-history`) | 해당 이벤트 항목 탭 | 이벤트 상세 또는 티켓 화면 | - |
| 2 | 이벤트 상세 | 체크인 QR 표시 | QR 코드 생성 + 표시 | QR 생성 실패 → 에러 |
| 3 | — (파트너가 QR 스캔) | 체크인 처리 | 체크인 완료 알림 수신 | - |
| 4 | 이벤트 상세 | 매칭 투표 화면 진입 | 참가자 프로필 카드 표시 | 참가자 0명 → "아직 참가자가 없습니다" |
| 5 | 매칭 투표 | 참가자 프로필에 투표 (좋아요/패스) | 투표 결과 저장 | 네트워크 오류 → 재시도 |
| 6 | 매칭 투표 | 모든 투표 완료 | "투표 완료" 안내 | - |
| 7 | — (매칭 로직 실행 후) | 매칭 결과 알림 수신 | 알림 센터에 결과 표시 | - |
| 8 | 알림 센터 (`/notifications`) | 매칭 결과 알림 탭 | 매칭 상대 정보 표시 | 매칭 실패 → "아쉽게도 매칭되지 않았습니다" |

### 검증 포인트
- [ ] 체크인 후 유저의 attendance 상태가 `checked_in`으로 변경
- [ ] 투표가 서버에 정확히 기록되는가
- [ ] 양쪽 모두 좋아요 시 매칭 성립되는가
- [ ] 매칭 알림이 양쪽 유저 모두에게 전달되는가

### 변형 시나리오

| 변형 | 차이점 | 추가 검증 |
|------|--------|-----------|
| U02-V1: 투표 시간 초과 | 매칭 투표 마감 시간 경과 | 미투표 처리 로직 |
| U02-V2: 체크인 없이 매칭 | 체크인 스킵 | 매칭 투표 접근 차단 |

## CUJ-U03: 마이페이지 → 구매 내역 → 환불 신청 [P0]

> 결제 후 환불 경로. 환불 정책 준수 검증 포함.

### 사전 조건
- 로그인 유저
- 환불 가능한 구매 건 1건 이상 (환불 정책 기간 내)

### 시나리오 스텝

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|
| 1 | 마이페이지 (`/my`) | "구매 내역" 탭 | `/purchase-history`로 이동 | - |
| 2 | 구매 내역 | 환불 대상 항목 선택 | 구매 상세 표시 | - |
| 3 | 구매 상세 | "환불 신청" 버튼 탭 | 환불 정책 안내 + 확인 다이얼로그 | 환불 기간 초과 → "환불 불가" 안내 |
| 4 | 환불 확인 | 확인 탭 | 환불 처리 → PG 취소 요청 | PG 취소 실패 → 에러 + 고객센터 안내 |
| 5 | 구매 내역 | 환불 완료 확인 | 해당 항목 상태 "환불 완료" 표시 | - |

### 검증 포인트
- [ ] 환불 정책(기간, 조건)이 정확히 적용되는가
- [ ] PG 취소 요청이 정상 처리되는가 (payment status → refunded)
- [ ] 환불 후 이벤트 신청 상태가 `cancelled`로 변경되는가
- [ ] 환불 금액이 정확한가 (수수료 공제 등)

### 변형 시나리오

| 변형 | 차이점 | 추가 검증 |
|------|--------|-----------|
| U03-V1: 부분 환불 | 환불 정책에 따라 부분 금액만 환불 | 정확한 부분 환불 금액 계산 |
| U03-V2: 이벤트 당일 환불 | 이벤트 시작 임박 시 환불 | 환불 불가 또는 제한 정책 적용 |
| U03-V3: 무료 이벤트 취소 | 가격 0원 이벤트 | PG 없이 신청 취소만 처리 |

## CUJ-U04: 검색 → 필터 → 이벤트 발견 → 신청 [P1]

> 유저가 능동적으로 이벤트를 찾는 탐색 경로.

### 사전 조건
- 앱 진입 (GUEST 또는 로그인 상태)
- 검색 가능한 이벤트 다수 존재

### 시나리오 스텝

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|
| 1 | 홈 (`/`) | 검색 아이콘 탭 | `/search`로 이동 | - |
| 2 | 검색 (`/search`) | 키워드 입력 | 검색 결과 표시 | 결과 없음 → 빈 상태 + 다른 키워드 제안 |
| 3 | 검색 | 필터 적용 (날짜, 지역, 카테고리) | 필터된 결과 | 필터 조합으로 결과 없음 → 필터 완화 제안 |
| 4 | 검색 결과 | 이벤트 카드 탭 | `/events/:id`로 이동 | - |
| 5 | 이벤트 상세 | 신청하기 | CUJ-U01의 Step 3부터 합류 | - |

### 검증 포인트
- [ ] PGroonga 검색이 한글 형태소 분석 정상 동작하는가
- [ ] 필터 조합이 정확히 AND 조건으로 적용되는가
- [ ] 검색 결과 → 이벤트 상세 → 뒤로가기 시 검색 상태 유지

- 앱 진입 (GUEST 또는 로그인)
- 큐레이션 데이터 존재

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |

### 검증 포인트

- [ ] 파트너 차단 시 해당 파트너 이벤트가 홈/큐레이션에서 숨겨지는가
