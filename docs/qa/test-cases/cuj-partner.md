# 파트너 앱 (app_partner) CUJ 테스트 시나리오

> CUJ = Critical User Journey
>
> 목적: 핵심 파트너 플로우가 end-to-end로 정상 동작하는지 검증.
> 파트너 앱은 이벤트 운영 도구이므로 "생성 → 관리 → 정산"이 핵심 경로.

---

## 우선순위 정의

| 등급 | 의미 | 기준 |
|------|------|------|
| **P0** | 핵심 비즈니스 경로 | 이벤트 운영의 기반 — 실패 시 파트너 서비스 불가 |
| **P1** | 필수 파트너 경험 | 가입/인증/심사 — 실패 시 파트너 온보딩 불가 |
| **P2** | 보조 관리 기능 | 멤버 관리/알림 — 실패 시 불편하지만 운영 가능 |

## CUJ-P01: 파트너 가입 → 파티 생성 → 이벤트 생성 → 티켓 설정 [P0]

> 파트너가 서비스에 등록하고 첫 이벤트를 개설하는 전체 플로우.
> 파트너 수 = 이벤트 수 = 유저 유입의 기반.

### 사전 조건
- 소셜 로그인 가능한 계정
- 사업자등록증 등 서류 준비

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|
| 1 | 로그인 (`/login`) | 소셜 로그인 | 로그인 성공 → 파트너 미등록 → `/welcome` | OAuth 실패 → 에러 |
| 2 | 웰컴 (`/welcome`) | "시작하기" 탭 | `/apply`로 이동 | - |

## CUJ-P02: 신청 관리 → 심사 (승인/거절) [P0]

> 유저 신청을 관리하는 핵심 운영 플로우.

### 관련 spec

- `apps/mds/docs/public/specs/event_application_manage_page/index.md` — 5 states (Default 대기중 / Approved tab / Rejected tab / Empty / Loading + Error). 화면 구조: AppBar('신청관리') + 3개 TabBar(대기중/승인됨/거절됨) + 이벤트별 그룹 리스트. **대기중 탭**은 행 인라인 거절/승인 버튼 + 하단 "전체 승인" CTA. **승인됨/거절됨 탭**은 행 본체 탭으로 신청 상세(`EventApplicationDetailRoute`)로 push. 진입: bottom-nav "신청관리" 탭 또는 `/applications`.
- `apps/mds/docs/public/specs/event_application_detail_page/index.md` — 신청 상세 (승인됨/거절됨 탭에서만 진입). Fix #1860 참조.

### 사전 조건
- PARTNER 상태
- 유저가 신청한 이벤트 1건 이상 (status: pending)

### 시나리오 스텝

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|

| 4 | 신청 관리 — 승인됨/거절됨 탭 | 행 본체 탭 | `EventApplicationDetailRoute` (shared-axis 전환)로 push → 유저 프로필 + 인증 정보 표시 | - |
| 5 | 신청 상세 | 뒤로가기 또는 액션 | 신청 관리로 복귀, 상태 반영 | - |

## CUJ-P03: 이벤트 운영 → 체크인 관리 [P0]

> 이벤트 당일 현장 운영 플로우.

### 사전 조건
- PARTNER 상태
- 당일 이벤트 존재 (승인된 신청자 있음)

### 시나리오 스텝

| Step | 화면 | 액션 | 기대 결과 | 실패 시 |
|------|------|------|-----------|---------|
| 1 | 대시보드 (`/`) | 체크인 탭 탭 | `/checkin`으로 이동 | - |
| 2 | 체크인 (`/checkin`) | 이벤트 카드 탭 (단일 이벤트 시 자동 진입) | 카메라 권한 요청 → `QRScannerScreen` 진입 (`Navigator.push` — 라우트 미등록). 단일 이벤트면 `CheckinPlaceholderPage`에서 직접 스캐너 렌더링, 복수 이벤트면 이벤트 카드(`InkWell`) 탭으로 진입. 카메라 프리뷰 + 스캔 영역 오버레이 표시 | 권한 거부 → 수동 입력 안내 |
| 3 | `QRScannerScreen` 진입 직후 | — | **요약 카드**: 전체 진행률 `N/M` + progress bar + 남은 인원 표시. **하단**: "엔트리 그룹별 현황" 축소 헤더 (엔트리 그룹 있는 경우) — (#1779 강화) | stats 로딩 실패 → 카드 "불러오기 실패 · 재시도" 노출, 카메라는 정상 동작 |
| 4 | `QRScannerScreen` (스캔 중) | 유저 QR 코드 스캔 | **성공**: 초록색 피드백 + 유저명/엔트리 그룹/N번째 입장 오버레이 (`_ResultFeedbackOverlay`) → 요약 카드 카운트 즉시 +1. **실패**: 빨간색 피드백 + 에러 메시지 ("유효하지 않은 코드" / "다른 이벤트 QR" / "이미 HH:mm 체크인됨") | 네트워크 오류 → 재시도 안내 |
| 5 | `QRScannerScreen` | 연속 스캔 | 여러 유저를 연속으로 스캔 — 성공/실패 피드백 + 요약 카드 / 그룹 카운트 매번 갱신 | - |
| 6 | `QRScannerScreen` 하단 시트 | 엔트리 그룹 헤더 pull-up 또는 탭 | 바텀시트 확장 → 그룹별 `라벨 · N/M · progress bar` 리스트. 90% 이상 그룹은 error 색상 progress bar | 시트 로드 실패 → "불러오기 실패" 메시지 |
| 7 | `QRScannerScreen` | [수동 체크인 열기] 버튼 탭 | 참가자 리스트 시트 오픈 → 이름 검색 → 체크인 토글. QR 인식 실패 케이스 fallback | stats 로드 실패 시 빈 리스트 + 에러 메시지 |
| 8 | `QRScannerScreen` | [플래시 토글] 버튼 탭 | 후면 카메라 플래시 on/off | 하드웨어 미지원 기기 → 버튼 disabled |
| 9 | `QRScannerScreen` | 뒤로가기 | 체크인 목록으로 복귀. 스캔된 체크인 내역 반영 | - |
