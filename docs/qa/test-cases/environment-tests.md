# 디바이스/환경 특수 상태 테스트 케이스

> 목적: 디바이스 상태, 네트워크 조건, 앱 생명주기 등 환경 변수에 따른 앱 동작을 검증.
> 정상 플로우(CUJ)에서 다루지 않는 비정상 환경 조건을 독립적으로 테스트한다.

---

## 우선순위 정의

| 등급 | 의미 | 기준 |
|------|------|------|
| **P1** | 핵심 경로 환경 이슈 | 딥링크/세션 — 유저 진입 실패 직결 |
| **P2** | 보조 환경 이슈 | 네트워크/상태 복원 — 불편하지만 재시도로 해결 |

---

## P1 환경 시나리오

### ENV-01: 딥링크 Cold Start — 인증 상태별 분기 [P1] — app_user

> 관련: CUJ-U06
> 코드: `main.dart` → `NotificationService.initialize()` → `_fcm.getInitialMessage()` → `goRouter.go()`

#### 사전 조건
- FCM 푸시 알림 수신 가능한 디바이스
- 앱 완전 종료 상태 (terminated)

#### 시나리오 스텝

| # | 시나리오 | 인증 상태 | 딥링크 | 기대 결과 |
|---|----------|-----------|--------|-----------|
| ENV-01-A | GUEST → 공개 화면 | GUEST (세션 없음) | `/events/event-123` | 앱 실행 → 이벤트 상세 직행 |
| ENV-01-B | GUEST → 보호 화면 | GUEST | `/my` | 앱 실행 → `/login?from=/my` 리다이렉트 |
| ENV-01-C | AUTH → 보호 화면 | AUTH (로그인, 미인증) | `/purchase-history` | 앱 실행 → Supabase 세션 복원 → 구매 내역 |
| ENV-01-D | VERIFIED → 보호 화면 | VERIFIED | `/events/event-123/apply` | 앱 실행 → 세션 복원 → 신청 위저드 |
| ENV-01-E | 만료 세션 → 보호 화면 | 세션 만료 | `/my` | 앱 실행 → 세션 갱신 시도 → 실패 시 `/login?from=/my` |
| ENV-01-F | 유효하지 않은 딥링크 | AUTH | `/invalid/path` | 앱 실행 → 홈(`/`)으로 fallback |

#### 검증 포인트
- [ ] `_fcm.getInitialMessage()`가 cold start 시 정확히 딥링크를 전달하는가
- [ ] Supabase 세션 복원이 딥링크 네비게이션보다 먼저 완료되는가 (race condition)
- [ ] GoRouter `redirect()`가 인증 상태에 따라 정확히 분기하는가
- [ ] 딥링크 경로에 잘못된 파라미터 (존재하지 않는 eventId 등) 시 에러 처리

### ENV-02: 딥링크 Cold Start — 인증 상태별 분기 [P1] — app_partner

> 관련: 파트너 앱 딥링크
> 코드: `main.dart` → `NotificationService` → `goRouter.go()`

#### 사전 조건
- 앱 완전 종료 상태

#### 시나리오 스텝

| # | 시나리오 | 온보딩 상태 | 딥링크 | 기대 결과 |
|---|----------|------------|--------|-----------|
| ENV-02-A | GUEST → 알림 딥링크 | GUEST | `/applications/app-123` | 앱 실행 → `/login` 리다이렉트 |
| ENV-02-B | NEEDS_APP → 보호 화면 | NEEDS_APP | `/more/parties` | 앱 실행 → `/welcome` 리다이렉트 |
| ENV-02-C | PENDING → 보호 화면 | PENDING | `/settlement` | 앱 실행 → `/apply/status` 리다이렉트 |
| ENV-02-D | PARTNER → 정상 진입 | PARTNER | `/applications/app-123` | 앱 실행 → 신청 상세 직행 |

#### 검증 포인트
- [ ] 파트너 앱 4단계 온보딩 상태별 리다이렉트가 정확한가
- [ ] 딥링크 목적지가 리다이렉트 후 저장되어 로그인/온보딩 완료 후 복귀하는가

---

### ENV-03: 백그라운드 → 포그라운드 세션 만료 [P1] — app_user / app_partner

> 관련: Supabase 세션 관리
> 코드: Supabase SDK 자동 세션 갱신

#### 사전 조건
- 로그인 상태에서 앱을 백그라운드로 이동
- 충분한 시간 경과 (세션 만료 또는 리프레시 토큰 만료 시뮬레이션)

#### 시나리오 스텝

| # | 시나리오 | 앱 | 액션 | 기대 결과 |
|---|----------|-----|------|-----------|
| ENV-03-A | 단기 백그라운드 (세션 유효) | app_user | 5분 백그라운드 → 포그라운드 복귀 | 세션 자동 갱신 → 정상 사용 |
| ENV-03-B | 장기 백그라운드 (세션 만료, 리프레시 유효) | app_user | 1시간+ 백그라운드 → 복귀 | 리프레시 토큰으로 자동 갱신 → 정상 사용 |
| ENV-03-C | 초장기 백그라운드 (리프레시 만료) | app_user | 리프레시 토큰 만료 후 복귀 | 로그인 화면으로 리다이렉트 + "세션이 만료되었습니다" |
| ENV-03-D | 보호 화면에서 세션 만료 | app_user | `/my`에서 세션 만료 후 API 호출 | 401 → 자동 갱신 시도 → 실패 시 로그인 리다이렉트 |
| ENV-03-E | 파트너 앱 세션 만료 | app_partner | 장기 백그라운드 후 복귀 | 동일한 세션 갱신/만료 처리 |

#### 검증 포인트
- [ ] Supabase `onAuthStateChange` 리스너가 세션 만료를 감지하는가
- [ ] API 호출 시 401 응답 → 자동 토큰 갱신 → 재요청 체인이 동작하는가
- [ ] 세션 만료 시 현재 화면의 미저장 데이터가 유실되지 않는가 (위저드 등)
- [ ] 로그인 리다이렉트 시 `from` 파라미터로 원래 화면 복귀가 보장되는가

## P2 환경 시나리오

### ENV-04: 딥링크 Warm Start — GoRouter 상태 복원 [P2] — app_user

> 관련: 앱이 백그라운드에 있는 상태에서 딥링크 수신

#### 시나리오 스텝

| # | 시나리오 | 현재 화면 | 딥링크 | 기대 결과 |
|---|----------|-----------|--------|-----------|
| ENV-04-A | 홈에서 딥링크 | `/` | `/events/event-123` | 이벤트 상세로 이동 — 뒤로가기 시 홈 |
| ENV-04-B | 검색에서 딥링크 | `/search` (검색 결과 있음) | `/events/event-456` | 이벤트 상세로 이동 — 뒤로가기 시 검색 상태 유지 |
| ENV-04-C | 위저드 중간에서 딥링크 | `/events/:id/apply` Step 3 | `/notifications` | 알림 센터로 이동 — 위저드 상태는? |
| ENV-04-D | 중첩 네비게이션에서 딥링크 | `/my/privacy` | `/events/event-789` | 이벤트 상세로 이동 — 네비게이션 스택 정리 |

#### 검증 포인트
- [ ] `FirebaseMessaging.onMessageOpenedApp` 리스너가 warm start 딥링크를 정확히 전달하는가
- [ ] GoRouter 네비게이션 스택이 딥링크 후 일관된 상태인가
- [ ] 위저드 중간에 딥링크로 이탈 시 미저장 데이터 경고가 표시되는가

---

### ENV-05: 네트워크 오프라인 → 온라인 복구 [P2] — app_user / app_partner

> 관련: 전체 앱 네트워크 의존 기능

#### 시나리오 스텝

| # | 시나리오 | 앱 | 화면 | 액션 | 기대 결과 |
|---|----------|-----|------|------|-----------|
| ENV-05-A | 홈 오프라인 | app_user | 홈 (`/`) | 비행기 모드 → 풀투리프레시 | 에러 표시 + 재시도 버튼 |
| ENV-05-B | 홈 온라인 복구 | app_user | 홈 (에러 상태) | 네트워크 복구 → 재시도 | 데이터 정상 로드 |
| ENV-05-C | 결제 중 오프라인 | app_user | 신청 위저드 결제 스텝 | 결제 진행 중 네트워크 끊김 | PG 결제 처리 중단 + 에러 안내 |
| ENV-05-D | 체크인 중 오프라인 | app_partner | QR 스캐너 | QR 스캔 후 서버 통신 실패 | 오프라인 큐잉 또는 에러 안내 |
| ENV-05-E | 폼 작성 중 오프라인 | app_partner | 파티 생성 위저드 | 제출 시 네트워크 없음 | 에러 + 데이터 보존 + 재시도 |
| ENV-05-F | 대시보드 오프라인 | app_partner | 홈 대시보드 | 앱 진입 시 오프라인 | 캐시된 데이터 표시 또는 에러 |

#### 검증 포인트
- [ ] 네트워크 복구 시 자동 재시도 또는 수동 재시도 UX가 일관적인가
- [ ] 폼 데이터가 네트워크 오류로 유실되지 않는가
- [ ] 결제 같은 크리티컬 플로우에서 네트워크 오류 시 중간 상태 처리가 안전한가
