Purpose 파트너가 한 페이지에서 파티를 만들고, 티켓과 반복 일정까지 한 번에 정한다. 기본 정보(이름·소개·이미지·장소) → 티켓 템플릿(이름·가격·성별/나이 조건·수량) → 반복 규칙(없음/매주/격주/매월 + 시간)을 위에서 아래로 채우고, 우측 sticky 요약에서 입력을 확인하며 "파티 만들기" 한 번으로 완료한다. 기존 파티의 수정도 같은 폼 — 기존 값이 채워진 채 열리고 "변경 저장"으로 마친다.
User journey Entry points: 파티·이벤트 허브(web_partner_party_events)의 "새 파티 만들기" / 파티 수정 진입 · 홈(오늘 할 일)의 신규 파트너 empty CTA "파티·이벤트 만들러 가기" · 회차 수정(web_partner_event_edit)의 "티켓 구성은 파티에서 관리" 링크 (→ 편집 모드 섹션 ②) · URL 직접 진입.
Exit points: 생성 성공 → 생성 완료 뷰 → 파티·이벤트 허브 · 편집 저장 성공 → 파티·이벤트 허브 복귀 + 저장 피드백 · 작성 중 사이드바/뒤로 이동 → 브라우저 이탈 확인 후 떠남(입력 소실) · 비로그인 → 파트너 로그인.
Background 모바일은 좁은 화면 때문에 6단계 위저드였지만, 1280 데스크톱은 전체 폼을 한 화면 흐름으로 펼치고 우측 sticky 요약이 위저드의 "검토 단계" 역할을 상시 수행하는 쪽이 빠르다 (콘솔 도구 문법). web-mvp pivot(docs/architecture/web-mvp-pivot.md §5)으로 커스텀 자격심사(입장 그룹의 verification 요구)가 deprecated 되면서 모바일 Step 4(입장 규칙)는 사라지고, 입장 그룹이 가지던 성별·나이 조건은 티켓의 기본 속성으로 내려와 티켓 템플릿 테이블의 컬럼이 됐다. 반복 규칙은 모바일에서 생성 후 별도 화면이었지만, 정기 모임 파트너의 첫 셋업 동선을 줄이기 위해 생성 폼의 한 섹션으로 흡수 — 백엔드의 "매일 자동 생성 · 최대 30일 선행" 규칙을 생성 시점에 미리 안내한다. 모바일 Step 3(최소 확정 인원·연락 수단·성비 균형)과 Step 1의 공개 범위·태그는 웹 MVP 제외 확정 (2026-06-07 결정 — History v1.1 · Reference "결정 기록" 참조).
Frequency 파트너당 파티 생성 1~수 회. 대부분 입점 직후 1회 셋업 — 이후에는 회차(이벤트)·티켓 관리 화면을 더 자주 사용.

항목 편집 시 동작
이름 · 소개 · 이미지 · 장소 (섹션 ①) 자유 수정 — 저장 시 파티를 참조하는 모든 화면(허브 · 회차 · 유저웹 상세)에 반영.

반복 규칙 (섹션 ③) 주기/요일/시간 변경 및 일시 정지 가능 — 기존 자동 생성 회차는 유지되고, 변경 후 생성분부터 새 규칙 적용. 영구 종료(취소)는 비가역 — destructive 확인 다이얼로그 (recurrence_management_screen 상속).
헤더 / CTA 라벨 타이틀 "새 파티 만들기" → "파티 수정" (breadcrumb에 파티명) · CTA "파티 만들기" → "변경 저장" — 그 외 폼 구조 동일.
저장 / 이탈 "변경 저장" 전까지 서버 반영 없음 — 작성 중 이탈 확인은 생성과 동일. 저장 성공 시 파티·이벤트 허브 복귀 + 저장 피드백 (반복 규칙을 새로 켠 경우만 자동 생성 예고 뷰 경유).

Global edge cases

  • 네트워크 끊김 — 제출 시에만 서버를 만나는 화면이라 작성 중에는 영향 없음. 제출 중 끊기면 생성 중 state의 실패 에지케이스로 — 입력 보존 + 안내.
  • 이미지 업로드 — 큰 파일은 업로드 진행 표시(슬롯 안 스피너), 실패 시 해당 슬롯만 "다시 시도" 표시. 허용 형식/용량 초과는 선택 즉시 안내.
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 입력란 테두리·오류 tint·배너 tint 모두 토큰 전환, primary → color-partner-dark-primary.
  • 접근성 — 모든 입력란은 label과 프로그램적으로 연결. 검증 오류 발생 시 오류 박스가 스크린리더에 즉시 공지되고, 오류 필드는 "오류" 상태로 읽힘. 티켓 테이블은 컬럼 헤더가 각 셀과 연결. 모든 인터랙티브 요소에 visible focus ring.
  • reduced motion — prefers-reduced-motion 시 smooth scroll → 즉시 점프, 행 추가/배너 expand 애니메이션 0ms, 스피너는 유지(진행 정보).
  • SEO / 공유 — 비공개 콘솔 화면. noindex — og 메타 불필요.
  • 초광폭 (≥1920px) — 콘솔 셸 1440px 캡 중앙 정렬 (web_foundation_responsive 도구 화면 규칙).
  • 수정(Edit) 모드 — 이 spec에 통합 (v1.1) — 같은 폼 prefill 재사용, 규칙은 위 "편집 모드 규칙" 표와 States의 "편집 모드 (prefill)" 참조.
