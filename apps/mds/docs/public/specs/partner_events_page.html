Overview

Status 🚧 디자인중 — 4 states · 단순 vertical list (filter / sort 미구현). PartnerDetailPage "더 보기"에서 확장된 풀 리스트.
Appapp_user
Categorypartner · events list

Hierarchy Parent: PartnerDetailPage ("진행중인 이벤트 → 더 보기" 탭으로 진입)
Children: MinglitEventCard (vertical cell · showPartnerOverlay: false · 4 visible state — 별도 spec)
Purpose 한 파트너가 운영하는 모든 이벤트를 시간순으로 한 화면에 펼쳐 보여준다. PartnerDetailPage의 가로 스크롤(약 1.5장 노출)은 발견·미리보기 용도이고, 이 화면은 "이 파트너의 이벤트 목록 전체를 천천히 훑어보기" — 사용자의 결정/탐색 단계를 받쳐주는 보조 화면.
User journey Entry points: PartnerDetailPage "진행중인 이벤트 → 더 보기" TextButton 탭 — 사실상 단일 진입점. 딥링크 /partners/:partnerId/events 도 가능 (URL 공유 / 외부 링크).
Exit points: 카드 탭 → partnerCoordinator.pushEventDetail(event.id) → EventDetailRoute · 뒤로 가기 → PartnerDetailPage 복귀.
Background PartnerDetailPage의 가로 ListView는 (screenW − 48) × 0.65 카드를 사용해 한 화면에 1.5~2장만 노출 — "더 많은 이벤트가 있을 수 있다"는 affordance만 줌. 이 화면은 그 "더 많은 이벤트"를 풀폭 vertical list로 풀어주는 자리. UI는 ListView.builder + MinglitEventCard 단순 조합 — 별도 filter / sort / pagination 없음. partnerEventsProvider는 5분 캐시 (ref.keepAlive() + Timer) — 재진입 시 즉시 표시.
Frequency관심 파트너에 대해 이벤트 사이클당 0~1회 — PartnerDetail에서 카드를 다 보고 더 둘러보고 싶을 때만 진입.

Global edge cases

  • partnerName이 빈 문자열 — AppBar title이 " 이벤트"(앞뒤 빈 칸)로 노출될 수 있음. PartnerDetailPage 진입 경로에선 사실상 발생 안 함 (partner.name 보장) · 딥링크에선 발생 가능 — sanitize 미구현.
  • provider 캐시 공유 — PartnerDetailPage와 같은 partnerEventsProvider(partnerId: ...)를 watch — 한쪽에서 데이터를 받으면 다른 쪽도 즉시 반영 (5분 keepAlive 동안).
  • 대용량 list — pagination 없음. partner가 운영 이력이 길면 한 번에 큰 list가 내려옴 (ListView.builder lazy 렌더링이 그나마 mitigation). repository에서 limit 거는지 verify 필요 (uncertain).
  • 접근성 — AppBar BackButton은 Material 기본 a11y. 카드 자체 Semantics는 child spec 참고 (Fix #996, #1558 — 만석/종료 announce 포함).
  • showPartnerOverlay: false — partner 컨텍스트(이미 AppBar에 partner 이름 노출)에서 카드 좌상단 partner overlay를 중복 노출하지 않음. PartnerDetailPage 가로 list와 동일 정책.
