Notification Settings Screen

Overview

Status 디자인완료 — 6 state · kit-shared (user + partner) · 토글 2개만 노출하는 minimal settings
App app_user + app_partner — shared. 두 앱 모두 NotificationSettingsRoute가 동일한 NotificationSettingsScreen(kit-shared)을 그대로 push. 분기 props 없음.
Category settings · notification · toggle-list
Route / Surface NotificationSettingsRoute · widget: NotificationSettingsScreen (shared/packages/minglit_kit)
Path /my/notification-settings (user) · /more/notification-settings (partner)
Hierarchy Parent: user — MyPage 알림 설정 tile · partner — MorePage 알림 설정 tile
Children: —
Purpose 앱이 보낼 알림 카테고리(서비스 알림 · 마케팅 정보 수신)에 대한 사용자의 동의를 켜고 끄는 단일 설정 화면. 데이터 소스는 user_settings 테이블(service_notification · marketing_consent 두 컬럼). 실제 OS 푸시 권한과는 별개 — DB 기반 opt-in/out flag.
User journey Entry: MyPage / MorePage "알림 설정" tile → context.push(NotificationSettingsRoute().location).
Exit: AppBar back / 시스템 back → 직전 화면 복귀. 별도 명시적 저장 버튼 없음 — 토글 변경마다 즉시 optimistic update + 서버 호출.
Background 토글 단위 즉시 저장 모델. NotificationSettingsController.updateSetting은 (1) optimistic state 갈아끼우기 → (2) server repository.updateSettings(userId, {key: value}) → (3) 실패 시 previous state로 revert + AsyncError로 화면 전환. 따라서 서버 실패는 빨간 에러 화면으로 전환되어 사용자가 인지함 (Notification list와는 다른 정책).
Frequency 매우 낮음 — 가입 직후 1회 또는 마케팅 푸시가 거슬릴 때 산발적. 일반적으로 세션당 ≤ 1회.

States

6 state. baseline = Default(서비스 ON · 마케팅 OFF — 가장 흔한 신규 사용자 기본값). MinglitAsyncValueWidget 3-way + data 안에서 settings null fallback + Permission-denied(현재 미구현 · Phase 2 가상 변형).

State 종류 식별 기준: MinglitAsyncValueWidget의 (loading / error / data) + data 안에서 settings == null 분기 + 두 토글의 on/off 시각 변주 (코드 분기 아님 — 시각적 베리언트). Permission-denied는 OS 권한 차단을 표시할 가상의 banner — 현재 코드에 없음.

Cross-cutting interactions

사용자 액션화면에 보이는 결과
뒤로 가기 (시스템 back · AppBar back) 직전 화면(MyPage / MorePage) 복귀. Material default pop transition (200ms 우→좌 slide). 별도 unsaved-state 경고 없음 — 이미 토글마다 즉시 저장되므로 dirty state가 존재하지 않음.
다크 모드 토글 scaffold / Switch off track / Divider / 텍스트 전부 dark 토큰 swap. Switch on track은 brand primary 그대로 유지.
SwitchListTile tap haptic Material default — InkWell ripple + light haptic. tile 전체 영역(title/subtitle 포함)이 hit target.
토글 빠른 연타 매번 optimistic state + 서버 호출. debounce 미부착 — 마지막 호출이 최종 서버 상태가 되지만 중간 호출에서 실패 시 그 시점의 previous state로 revert → AsyncError 발생할 수 있음(race).

Global edge cases

  • Update 실패 → AsyncError 화면 전환 — 토글 한 번 실패가 화면 전체를 에러 갈래로 보내므로 사용자에겐 가혹한 UX. SnackBar + state baseline 유지가 권장 (Phase 2 후보).
  • OS 푸시 권한과 DB flag 분리 — 본 화면의 토글은 DB flag만 변경한다. OS 권한 차단 여부는 표시되지 않음 — 사용자가 "토글 켰는데 알림이 안 와요"로 문의할 가능성. Permission-denied banner 도입 검토.
  • 마케팅 동의 audit trail 부재 — 동의/철회 시각이 별도 컬럼으로 기록되지 않음. 법적 audit 요구가 있다면 marketing_consent_updated_at 컬럼 추가 필요.
  • Default 값 보장 — settings row가 없는 신규 사용자도 controller가 UserSettings(userId, updatedAt: now) default를 만들어 반환하므로 빈 화면을 보지 않음(코드 20-25행). 단 첫 토글 변경 시 INSERT가 발생하는데, repository updateSettings가 upsert인지 update인지에 따라 동작이 갈림 — 검증 필요.
  • kit-shared 단일 위젯 — user/partner 분기 props 없음. theme.colorScheme.primary만 다르므로 Switch active track 색만 차이. 동작/문구/구조는 100% 동일.
  • 자동 retry 부재 — Error 갈래에서 retry 버튼이 없음. 사용자는 화면을 떠났다 다시 진입해야 controller rebuild가 일어남. _DefaultErrorView는 retry CTA 미포함.
