Purpose 파트너가 체크인 탭을 누르는 순간 오늘 진행 예정 이벤트 수에 따라 자동 분기한다 — 0개면 안내, 1개면 즉시 QR 스캐너, 2개 이상이면 선택 리스트. 이름은 "Placeholder"지만 실제로는 dispatcher 화면. 단순 진입 마찰을 줄여 가장 흔한 1-event 케이스에서 별도 선택 없이 바로 스캔 가능.
User journey Entry points: PartnerHome BottomNav 체크인 탭 탭.
Exit points: 1개 이벤트 → QRScannerScreen(다크 테마) push. 2+ → 카드 탭 → QRScannerScreen push. 0개 → 탭 변경으로만 이탈.
Background 파트너가 운영일에 체크인 탭을 누를 때 가장 잦은 시나리오는 "오늘 1 이벤트". 매번 선택 화면을 거치게 하면 마찰이 커서 1개일 때는 자동 routing. "오늘" 정의는 시작 3시간 전 ~ 종료 1시간 후 윈도우 (todayEventsProvider). FutureProvider 기반이라 partnerId 변경 시 자동 invalidate.
Frequency운영일에 매 진입마다 (체크인 시작/중간 중)

두 단계 dispatcher: ① currentPartnerInfoProvider → ② todayEventsProvider → events.length 분기 (0 / 1 / 2+). state별 layout이 완전히 다름.

모든 state는 simpleAppBar('체크인') + body. body 형태가 state별로 갈림 — Empty(중앙 정렬 컬럼) / Selection(상단 헤더 + ListView) / 1-event는 자체 화면 push라 본 페이지 잔영 없음.

Global edge cases

  • 네트워크 끊김 — events fetch fail → "이벤트를 불러올 수 없습니다" 평문 텍스트. retry CTA 없음 (디자인 부채).
  • 오늘 윈도우 경계 — start - 3h ~ end + 1h 윈도우. 자정 이후도 같은 "오늘"로 잡힐 수 있음 (현재 정의: now 기준 윈도우 inclusion).
  • 다크 모드 — 본 페이지는 light/dark 자동 (colorScheme). 단, 1-event 분기는 항상 dark theme 강제 (Theme override).
  • 접근성 — Empty/Error 메시지는 SemanticsLabel 자동(Text). icon은 decorative — Semantics excludeSemantics 권장 (현재 미적용).
