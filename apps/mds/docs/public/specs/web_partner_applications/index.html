Purpose 유저의 결제·신청이 파트너 승인을 받아 참가로 확정되는 화면. 웹 MVP에서 유저는 결제까지 마친 상태로 대기 목록에 들어오고, 파트너가 승인하면 명단에 오르며 거절하면 전액이 자동 환불된다. 같은 화면의 참가자 명단 모드에서 확정자 명단을 보고 인쇄해 현장 입장 확인(이름 대조)에 쓴다.
User journey Entry points: 사이드바 "신청 관리" (대기 badge) · 홈 대기 카드 / 이벤트 카드의 "대기 N건 검토" (해당 이벤트 + 대기 탭으로 딥링크) · 홈 이벤트 카드의 "참가자 명단" (해당 이벤트 + 명단 모드로 딥링크) · 신청 도착 알림 메일의 링크 · URL 직접 진입/북마크.
Exit points: 명단 인쇄(브라우저 인쇄) · 이벤트 선택 바 → 다른 이벤트 · 사이드바 → 홈/파티·이벤트/정산 · 비로그인이면 파트너 로그인으로.
Background web-mvp pivot(docs/architecture/web-mvp-pivot.md)으로 신청 심사가 승인/거절만으로 축소됐다 — 커스텀 자격 요구·제출물 심사·입장그룹 배치 심사는 범위 외. 모바일에서 cross-event hub / 단일 이벤트 목록 / 신청 상세 3개 화면 + carousel로 나뉘었던 흐름을, 데스크톱 넓은 화면에 맞춰 이벤트 선택 → 좌측 목록 → 우측 상세 master-detail 한 장으로 합쳤다. 웹 MVP는 결제 선행 모델 — 대기 신청은 이미 결제가 끝난 상태라 거절 = 환불 이벤트다. 그래서 승인은 가볍게(원클릭 · 일괄 승인), 거절은 한 박자 무겁게(확인 다이얼로그 + 환불 고지 + 사유) 설계했다. QR 체크인이 deprecated되면서 입장 확인은 확정자 명단 인쇄 + 현장 이름 대조로 단순화 — 명단 모드가 그 받침이다.
Frequency 모집 중 이벤트가 있는 파트너는 하루 수회 — 알림 메일/홈 대기 카드가 트리거. 이벤트 당일엔 명단 모드로 1회 이상 (인쇄).

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. web_partner는 데스크톱 우선 (web_foundation_responsive surface priority) — Desktop(≥1280) blueprint가 1차 산출물.

Sub-anatomy ① — 사이드바 (콘솔 셸)

콘솔 셸 사이드바의 SSOT는 web_partner_home Sub-anatomy ① — 여기서 재정의하지 않는다. 이 화면에서의 차이만: active 항목이 "신청 관리" (primary 10% tint + primary text), badge는 전 이벤트 대기 신청 합계 (이벤트 선택 바의 "대기 N"은 선택한 이벤트만). 이 화면 안에서 신청을 처리하면 badge 수가 다음 갱신에서 줄어든다.

새로고침 / URL 직접 진입 주소의 이벤트·필터 탭·모드로 그대로 복원 — 홈 "대기 N건 검토"(이벤트+대기 탭) · "참가자 명단"(이벤트+명단 모드) 딥링크가 이 규칙 위에 선다. 주소에 이벤트가 없으면 기본 선택 규칙 (Sub-anatomy ③). 일괄 선택 상태는 복원하지 않음.

Global edge cases

  • 네트워크 끊김 — 패널 영역만 "다시 시도" 안내로 교체 (사이드바·헤더 유지). 승인/거절/일괄 처리 중 끊기면 해당 액션만 실패 안내 + 입력 보존.
  • 처리 중 화면 이탈 — 승인/거절 요청을 보낸 뒤 다른 화면으로 가도 처리는 계속됨. 돌아오면 재조회로 갱신된 상태가 보인다.
  • 환불 비동기 — 거절 직후 환불은 "진행 중"이며 완료까지 시간이 걸릴 수 있음. 거절 탭의 환불 상태 칩(진행 중 / 완료 / 실패)이 SSOT — 실패 건은 운영자 처리 대상이라는 카피 명시.
  • 다크 모드 — 우측 상단 Dark 토글로 확인. primary → color-partner-dark-primary · success/error/warning 칩은 다크 채도 보정.
  • 접근성 — tab 순서: 사이드바 → 모드 세그먼트 → 이벤트 선택 바 → 필터 → 목록 (행마다 체크박스 → 행 본체) → 상세 (정보 → 거절 → 승인). 다이얼로그는 포커스 트랩 + esc 닫기 + 첫 포커스는 첫 사유 칩. 체크박스는 신청자 이름과 연결되어 읽힘 ("김지연 선택"). 모든 인터랙티브 요소 visible focus ring (데스크톱 우선 surface 필수 검토).
  • reduced motion — prefers-reduced-motion 시 shimmer 정지 · 다이얼로그/선택 bar 등장 0ms · hover transition 0ms.
  • SEO / 공유 — 비공개 콘솔 화면. noindex — og 메타 불필요. 신청자 개인정보가 있는 화면이라 외부 공유 진입점 없음.
  • 초광폭 (≥1920px) — 콘솔 셸 1440px 캡 중앙 정렬 (도구 화면 규칙). 목록 380px 고정, 상세만 넓어짐.
  • 이벤트 시작 후의 대기 신청 — 없음: 시작 시점에 자동 만료(자동 거절 + 전액 환불)되므로 시작 후 대기 탭은 0건으로 수렴. 만료 처리가 비동기로 늦으면 잠깐 남아 보일 수 있으나 파트너가 처리할 필요 없음 — 갱신 시 거절 탭으로 이동.
