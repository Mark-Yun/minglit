Deletion Info Page

Overview

Status 디자인완료 — wizard step 2/4 · 2 state (with/without reason)
Appapp_user
Categoryaccount · privacy · destructive · wizard-step · disclosure
Route / Surface DeletionInfoRoute — DeletionInfoPage({reasonCode, reasonText}) (둘 다 옵셔널)
Path/my/privacy/delete/info · query: ?reasonCode=&reasonText=
Hierarchy Parent: DeletionReasonPage — coordinator.pushInfo()로 push.
Children: DeletionVerifyPage (다음 단계, "계속 진행" → coordinator.pushVerify())
Purpose 탈퇴 wizard의 두번째 단계 — 삭제되는 정보 / 법정 보존 정보 / 7일 유예 기간을 사용자에게 명시적으로 보여주는 disclosure 화면. ReasonPage에서 받은 사유는 상단에 요약 표시한다 (사유 미선택이면 그 카드 자체가 빠짐).
User journey Entry points: ReasonPage의 두 CTA — "다음"(reason 동반) · "선택하지 않고 계속하기"(reason 없이).
Exit points: ① "계속 진행" 탭 → DeletionVerifyPage push (사유는 그대로 query로 전달) · ② 뒤로 가기 → ReasonPage 복귀 (선택 상태는 유지 — coordinator.push라 stack에 남아있음).
Background 개인정보 처리방침 컴플라이언스로, 탈퇴 직전 "어떤 데이터가 어떻게 되는지"를 분명히 안내해야 한다 — 삭제 대상 / 법정 보존 대상 / 7일 grace period(복구 가능)를 세 분리된 시각 블록으로 제시. 유예 기간 카드만 error tint로 강조 — 사용자에게 "이게 끝이 아니다, 7일 복구 창이 있다"는 신호 + 동시에 "30일 재가입 제한"이라는 약한 deterrent.
Frequency매우 낮음 — 탈퇴 wizard 진입 시 1회.

States

2 state — baseline = reason 동반(상단 chip 노출). reason 없이 진입한 경우는 chip만 빠진 단순 변형. fetch 없음 → loading/error 없음.

State 종류 식별 기준: ① reason 동반 (route param이 valid · buildWithdrawalReason 결과 != null) — chip 노출 · ② reason 없음 / 무효 — chip 미노출. 이 widget은 ConsumerWidget · 내부 state 없음 · provider read만(coordinator). 상기 두 가지 외 분기 없음.

Default · 사유 동반 🎯 baseline · reason != null

Global edge cases

  • Loading / Error mini-table 없음 — 위젯이 fetch하지 않음. 안내 텍스트는 const literal.
  • 다크 모드 — color-secondaryContainer의 다크 변형, color-error의 다크 alias 모두 자동 swap. 정보 카드와 grace warning의 contrast가 유지되는지 design token 검증 필요.
  • 접근성 — bullet은 의미 정보가 없으므로 screen reader가 무시(Icon default semantic). 본문 텍스트만 announce.
  • 긴 detail — reason.detail 200자 한계 시 chip이 7-8줄까지 늘어날 수 있음 — ListView가 자연 스크롤 처리.
  • 딥링크 진입 — query 없이 직접 /my/privacy/delete/info 진입하면 reason=null로 정상 렌더 — ReasonPage step skip 시나리오 동일.
