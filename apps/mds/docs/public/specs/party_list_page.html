Overview

Status ✅ 디자인완료 — 4 state · 파트너 파티 운영 진입 hub
App app_partner
Category party · list / management
Route / Surface PartyListRoute · widget: PartyListPage (ConsumerWidget · Scaffold + ListView.separated)
Path /more/parties
Hierarchy Parent: PartnerHomePage (더보기 탭 → "파티 관리" 메뉴 또는 EventActionCardEmpty / TodoSummaryChips → 파티 리스트)
Children: PartyDetailRoute (카드 탭), PartyCreateRoute (AppBar + 액션), CheckinRoute (QR 스캔 액션 — Fix #540 route-based push) · PartyListItem (internal widget — no separate spec, 카드 atom)
Purpose 파트너가 자신의 파티(이벤트의 상위 컨테이너)를 한 번에 둘러보고 운영할 곳으로 들어가는 진입 화면. 각 카드에서 파티 이미지 · 상태 배지 · 위치 / 정원 / 조건 / 인증 요구 chip을 한눈에 보고, 탭하여 PartyDetailPage(3-tab 운영 콘솔)로 push.
User journey Entry points: PartnerHomePage 더보기 탭의 "파티 관리", Onboarding 직후 "첫 파티 만들기" 후 복귀, EventActionCardEmpty의 파티 선택 시트(_PartySelectionSheet)에서 "전체 보기".
Exit points: 카드 탭 → PartyDetailRoute · AppBar "+" → PartyCreateRoute · QR 아이콘 → CheckinRoute · 뒤로가기 → MorePage.
Background 파티는 파트너 운영의 최소 단위로, 한 파티 안에 여러 이벤트 인스턴스(반복/일회성)가 들어간다. 이 화면은 비-edge-to-edge 카드 리스트(radius-card 미적용 · RoundedRectangleBorder()) + 1px outlineVariant 좌우 풀폭 divider로, "한 화면에 가능한 많은 파티를 빠르게 훑기"를 최우선한 정보 밀도 디자인. 카드 자체는 머리(타이틀)와 16:9 이미지 본문으로 분리된 듀얼 레이아웃이며, 본문 위에 status 배지와 chip group을 floating으로 얹는다.
Frequency 운영 중인 파트너가 매일 1회 이상 진입. 파티가 0개일 때는 onboarding 직후 한 번 빈 화면을 거친다.

Global Behavior

cross-cutting interactions · 모션 토큰 · 전역 에지케이스.

Cross-cutting interactions

  • Forward navigation — 카드 탭 → PartyDetailRoute(partyId) push (Coordinator가 root GoRouter 통해 push — Fix #1680로 shell-branch boundary 안전). 신규 생성 → PartyCreateRoute.
  • QR action (Fix #540) — AppBar QR 버튼이 직접 CheckinRoute으로 이동. 기존엔 qr→checkin cross-feature import가 있었으나 route-based로 정리됨. shell의 CheckinBranch 탭과 동일 destination(스택은 분리).
  • Like (MinglitSocialButton) — SocialTargetType.party · SocialInteractionType.like. 페이지 전환 없이 inline toggle. 데이터는 partyListProvider가 watch하지 않으므로 like 상태가 다음 refetch까지 stale일 수 있음 (button 자체가 자체 provider 보유).
  • Status badge 색상 — theme.colorScheme.tertiary/outline/secondary 사용. partner theme에서 secondary/tertiary는 user theme과 공유(MinglitColors.secondary/tertiary) — primary만 indigo로 분리.
  • 이미지 fallback chain — imageUrl != null ? Image.network(errorBuilder → placeholder) : 즉시 placeholder. 네트워크 에러 시 카드 자체는 정상 표시되며, 본문만 검정 + party_mode 아이콘.
  • List padding — only(bottom: spacing-large)로 마지막 카드와 화면 끝 사이 24px 여백 확보 (FAB가 없으므로 system gesture overlap 방지 목적은 약함, 시각적 breathing room).

Global edge cases

  • 다중 partner 보유 — controller는 myPartners.first만 사용. 한 사용자가 여러 partner를 관리하는 경우 UI에서 partner 선택 수단이 없음 (현재 0/1 partner 가정). multi-partner 지원 시 AppBar에 dropdown 필요.
  • Provider 영속성 — partyListProvider는 @riverpod family가 아니라서 화면 이탈 시 disposal 정책에 따라 재진입 시 refetch될 수 있음 (autoDispose 설정 의존). create/edit 후 복귀하면 새 데이터 반영 필요.
  • Status enum drift — party.status는 string ('active' / 'closed' / 'draft' / 미정의). 새 status가 백엔드에 추가되어도 클라이언트가 fallback(원시 문자열 + primary 색)으로 안전 처리.
  • List 길이 — 50+ 파티 운영하는 power partner 케이스 미보호. ListView.separated가 lazy 렌더하나 image network call이 누적될 수 있음. 향후 검색/필터 추가 후보.
  • Pull-to-refresh 부재 — 현재 RefreshIndicator 없음. 새로고침은 화면 재진입 또는 like/edit 액션으로만. 데이터 즉시성을 원하는 사용자에 약점.
  • Theming — MinglitTheme.partnerTheme이 root Material에 적용되어 모든 child가 partner indigo primary를 받음. user app과 다르므로 cross-app 컴포넌트 재사용 시 색 검증 필수.
