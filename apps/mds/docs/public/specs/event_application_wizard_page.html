Event Application Wizard

Overview

Status ✅ 디자인완료 — 2 step + verification 분기 + 결제 PG + 에러/제출 = 7 state
App app_user
Category event · admission · application
Route / Surface EventApplicationRoute · widget: EventApplicationWizardPage + _VerificationStep + _PaymentStep + _StepIndicator + _Footer
Path /events/:eventId/apply (optional ?ticketId= query)
Hierarchy Parent: EventDetailPage (apply CTA에서 진입)
Children: — (2 step은 internal — Column + step content swap, 별도 sub-route 없음). 성공 시 PaymentSuccessScreen으로 pushReplacement.
Purpose 이벤트 참여 신청을 인증(verification) → 결제(payment) 2단계 위저드로 안내한다. 티켓에 연결된 EntryGroup이 요구하는 인증 폼(텍스트 / 파일 업로드)을 채운 뒤 최종 결제 금액을 확인하고 신청을 제출한다. 무료 티켓은 결제 단계에서도 즉시 확정, 유료 티켓은 Iamport WebView로 PG 결제를 진행한다.
User journey Entry points: EventDetailPage의 EventBottomTicketBar에서 티켓 선택 후 "신청하기" 탭 → ?ticketId= 쿼리로 진입.
Exit points: 신청 성공 → PaymentSuccessScreen으로 교체 (뒤로 못 돌아옴) → "내 티켓 보기" / "이벤트 상세로 돌아가기" 분기. 결제 실패 → confirm 다이얼로그 → 다시 시도 또는 닫기 (page 유지). 닫기 버튼(X) → EventDetail 복귀.
Background 밍글릿 이벤트는 신뢰 모델의 두 축인 identity(OAuth)와 qualification(직업/소속/특정 자격)을 구분한다. 이 화면은 qualification 인증을 받는 마지막 게이트다 — 파트너가 정의한 verification form을 사용자가 채워서 제출하면 파트너 측 EventApplicationManagePage에서 심사한다. 결제는 인증과 별개로 진행되지만 wizard에서 묶어 흐름을 단순화한다. 반려 시 100% 환불, 심사 최대 24시간이라는 정책이 결제 카드 하단에 명시된다.
Frequency 이벤트 신청 시마다. 한 이벤트에 한 번 (티켓 단위) 신청 가능.

States

시각 변형 7종 (verification baseline + no-verif · validation error · payment · submitting · PG WebView · error dialog). baseline = Step 1 Verification, 나머지 additive diff.

State 종류 식별 기준: state.step enum (verification · payment) + state.status (initial · submitting · success · error) + verification 요구 분기 (requiredVerificationIds.isEmpty) + 결제 분기 (Free vs Paid). Success state는 별도 mockup이 아니라 PaymentSuccessScreen으로 pushReplacement — 이 spec 범위 밖.

· dialog 외부 탭 → barrierDismissible 기본값 따름 (showMinglitConfirm 구현) — 보통 닫힘
· 다시 시도 후 또 실패 → 같은 dialog 재표시 (loop 없음, 매번 사용자 결정)
컴포넌트 + showMinglitConfirm(title · message · confirmLabel="다시 시도" · cancelLabel="닫기") — Material Dialog 위에 wizard scrim · radius-card · padding spacing-large
↔ wizard body는 scrim(rgba(0,0,0,0.45)) 아래로 dimmed · 입력 무반응
토큰 + color-primary (다시 시도 confirm btn) · color-text-secondary (닫기 cancel btn) · radius-card (16) (다이얼로그) · spacing-large (24) (다이얼로그 padding) · scrim 0.45 opacity (Material default)

Global edge cases

  • initialTicketId 누락 진입 — selectedTicket null 상태 · "티켓 정보가 없습니다." / "티켓을 먼저 선택해주세요." 텍스트로 fallback. 정상 흐름이 아니므로 footer 버튼은 의미 없음 (eventDetail로 돌아가야 함).
  • 여러 verification 요구 — 코드상 verifs.first만 표시한다. 다중 verification은 미구현 (TODO). 일단 한 개 인증으로만 처리 가능.
  • 업로드 중 페이지 이탈 — MinglitFilePicker가 백그라운드 업로드 진행. 완료 시 ref가 살아 있다면 state 갱신 시도 (mounted check 무시). 보통은 무해.
  • EF 비동기 결과의 race — submitting 중 X로 종료 → ref.listen 콜백이 unmounted context에 닿을 수 있음. context.mounted 가드로 PaymentSuccessScreen push만 스킵. status 갱신은 controller 자체 (스킵 안 됨).
  • 다크 모드 — 페이지 전체가 ColorScheme 토큰 사용 → 자동 swap. dialog/snackbar/Iamport WebView도 자체 다크 대응 (Iamport 외).
