Children: — · 완료(승인 대기) 화면은 이 spec 의 state 로 포함 (별도 spec 아님)
Purpose 티켓을 결제하고 참여 신청을 제출하는 화면. 주문 내용(이벤트·티켓·금액)을 확인하고, 약관·환불 정책에 동의한 뒤 외부 결제창으로 결제를 마친다. 핵심 메시지는 승인 대기 모델 — 결제는 참여 확정이 아니라 신청의 시작이며, 파트너 승인 시 확정 · 거절 시 전액 자동 환불임을 결제 전·후 모두에서 명확히 전달한다.
User journey Entry points: 이벤트 상세(/events/:id)에서 티켓 선택 후 "신청하기" · URL 직접 진입은 티켓 파라미터가 유효할 때만 (없으면 이벤트 상세로 돌려보냄) · 비로그인 진입은 로그인 후 복귀.
Exit points: ① 결제 완료 → 완료 화면(승인 대기) → "구매내역 보기" (/my/purchases — TBD) · ② 로고/브라우저 back → 이벤트 상세 복귀 (결제 취소로 간주) · ③ 결제 실패 → 이 화면 유지 (재시도).
Background web-mvp pivot — "이벤트 탐색 → 상세 → 구매·신청" 퍼널의 마지막 화면. 모바일의 4-step 위저드는 파트너 커스텀 자격심사(파트너 인증)가 deprecated 되면서 step 가치가 사라져, 웹은 단일 페이지 + 우측 sticky 주문 요약의 데스크톱 커머스 관례로 재설계. 본인인증 미완 사용자만 결제 전 본인인증 카드가 인라인으로 삽입된다 (별도 step 아님). 환불 정책 고지는 전자상거래법(제15조·제17조)상 결제 전 의무 노출 — wizard 의 3그룹 구조와 refund-policy-v2 정책(파트너 귀책 100% / grace / cutoff)을 그대로 따른다. 1280px 데스크톱 주 캔버스 (Mark 지시 2026-06-07) — 모바일 variant 는 후속 pass.
Frequency 구매 의도 발생 시 1회 — 트래픽은 낮지만 매출이 발생하는 결정 화면.

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. 이 화면은 Desktop (≥1280) variant 가 주 blueprint — breakpoint variants 표 참조.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 이 화면은 Desktop-first 예외 화면 — 1280 baseline 으로 먼저 설계하고 Mobile blueprint 는 후속 pass 에서 추가한다 (History 참조).

Variant Breakpoint 이 화면에서의 차이
Desktop (주 variant) ≥ 1280px 헤더(로고 + 아바타 — 검색 제외) + 2-컬럼: 좌 본문 컬럼(승인 안내 → 주문 정보 → 본인인증(조건부) → 동의) + 우 주문 요약 카드 sticky (360px). 컨테이너 1200px 캡 중앙 정렬 · gutter 32px — 아래 blueprint 가 이 variant.
Tablet 768–1279px 별도 blueprint 없음 — Desktop 레이아웃 축소: 주문 요약 카드가 sticky 를 풀고 본문 컬럼 최하단으로 합류 (1-col) · 카드 폭 100%.
Mobile < 768px 후속 pass 에서 작성 (TBD) — 1col + 하단 고정 결제 바 예상. 이번 pass 는 1280 baseline 만 (Mark 지시 2026-06-07).

Global edge cases

  • 네트워크 끊김 — 결제 진행/확인 요청 실패 시 결제 실패 snackbar 패턴으로 안내 (자동 재시도 없음 — 사용자 액션 필요). 주문 정보 로드 실패는 안내 + "다시 시도" (이벤트 상세 데이터 재요청).
  • 결제 결과 race — 결제 완료 직후 화면을 닫거나 새로고침해도 신청 생성은 서버 검증(이중 검증·멱등)이 보장 — 재진입 시 완료 화면으로 복원 (모바일 wizard 의 race 안전 처리 상속).
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 배경/카드/divider/텍스트 토큰 전환 · 승인 대기 칩의 warning tone, 환불 보장 노트의 success tint 는 양 모드 유지 · 외부 결제창 내부는 영향 없음.
  • 접근성 — 키보드 tab 순서: 로고 → 아바타 → (본인인증 하기) → 전체 동의 → 개별 동의 ×3 → "보기" 링크 → 티켓 변경 → "결제 진행" CTA. 체크박스는 스페이스로 토글 · CTA 비활성 사유는 항상 helper 텍스트로 노출 (색만으로 전달 금지) · 완료 화면 제목은 화면 전환 시 포커스 이동.
  • reduced motion — prefers-reduced-motion 시 완료 culmination 애니메이션 생략(final 정적 표시) · 체크/CTA transition 0ms.
  • SEO / 공유 — 보호 페이지: noindex · og 공유 비대상 (공유는 이벤트 상세가 담당).
  • 초광폭 (≥1920px) — 1200px 캡 유지, 잉여 폭은 배경 (foundation 규칙).
