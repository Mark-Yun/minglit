Notification List Screen

Overview

Status 디자인완료 — 5 state · kit-shared (user + partner)
App app_user + app_partner — shared between user / partner. 두 앱 모두 NotificationCenterRoute가 동일한 NotificationListScreen(kit-shared)을 그대로 push 한다. 분기 props 없음.
Category notification · feed · async-list
Route / Surface NotificationCenterRoute · widget: NotificationListScreen (shared/packages/minglit_kit)
Path /notifications (user · partner 동일)
Hierarchy Parent: user — HomePage AppBar 알림 아이콘 · partner — PartnerHomePage AppBar 알림 아이콘
Children: — (tile 탭 시 deep_link로 임의 route push — 별도 spec)
Purpose 푸시 / 인앱 알림 히스토리를 한곳에서 보고, 읽음 처리·전체 읽음·개별 삭제·deep-link 이동을 수행하는 단일 list 화면. 데이터 소스는 user_notifications 테이블 (page size 20).
User journey Entry points: HomePage / PartnerHomePage AppBar 알림 아이콘 (미읽음 배지) · 외부 push 알림 → 직접 진입 (deep-link).
Exit points: tile 탭 → deep_link 검증 후 context.push(trimmed) · 우→좌 swipe → tile 삭제 (페이지 유지) · AppBar "모두 읽음" → 전부 read 처리 후 새로고침 · 뒤로 가기 → Home 복귀.
Background 알림 read-state 복원이 핵심. 미읽음(is_read=false)은 primary 5% 틴트 + bold title로 시각 분리, 읽음은 평문. 읽음 처리는 optimistic update — tile 탭 즉시 UI에 반영하고 서버 실패는 swallow + log (Fix #1955) 해서 절대 크래시하지 않는다. swipe-to-dismiss 역시 optimistic — 화면에서 즉시 제거.
Frequency 활성 사용자 일 1-3회 (push 알림 도착 빈도 / 읽지 않은 알림 누적 시).

States

5 state. baseline = Default(read + unread mixed). MinglitAsyncValueWidget이 loading/error 자동 처리 — 단 NotificationListScreen은 error builder를 inline override해 "에러: $err" plain Text로 표시한다 (코드 137행).

State 종류 식별 기준: MinglitAsyncValueWidget의 3-way (loading / error / data) + data 안에서 notifications.isEmpty 분기. All-read는 data 갈래의 시각적 변주(unread 0건) — 별도 분기 코드는 없다.

Global edge cases

  • Optimistic update vs server failure — markAsRead / deleteNotification / markAllAsRead 모두 서버 에러를 swallow + log (Fix #1955). 클라이언트는 항상 성공처럼 동작하지만 다음 refresh 시 stale state로 되돌아갈 수 있음 — race condition 알아두기.
  • Unread badge 동기화 — Home AppBar 미읽음 배지(99+ 캡)는 notificationListProvider에서 계산. 이 화면에서 markAsRead/markAllAsRead 시 동일 provider state 업데이트 → 배지 즉시 갱신 (cross-screen consistency).
  • Pagination 부재 — getNotifications(limit: 20, offset: 0) 단일 호출, scroll-to-load 없음. 21번째 알림 이후는 보이지 않음 — Phase 2에서 무한 스크롤 / "이전 알림 더 보기" 후보.
  • RefreshIndicator 위치 한정 — data 갈래 한정. Empty/Loading/Error에서는 풀-다운이 동작하지 않으므로 사용자가 retry하려면 화면을 떠났다 다시 진입 (의도되지 않은 UX 결함).
  • kit-shared 단일 위젯 — user/partner 분기 props 없음. Theme.of(context).colorScheme.primary만 다르므로 unread tint와 spinner 색만 차이가 남. 동작/문구/구조는 100% 동일.
  • 실시간 갱신 부재 — Supabase realtime subscription 미부착. push 알림 도착 후 이 화면을 보고 있어도 list가 자동 업데이트되지 않음 — 사용자가 직접 풀-다운 / 다시 진입해야 함.
