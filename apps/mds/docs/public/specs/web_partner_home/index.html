Hierarchy Parent: — (top-level web_partner 콘솔 홈 — 로그인 후 기본 착지)
Children: 사이드바 셸 + 오늘 할 일 위젯은 internal — 별도 spec 없음. 사이드바가 연결하는 화면들(파티·이벤트 / 신청 관리 / 정산)은 각각 별도 web spec으로 작성 예정.
Purpose 파트너가 로그인하면 "지금 처리할 일"부터 보인다. 대기 중 신청 수 · 오늘과 임박한 이벤트 · 최근 정산 상태를 한 화면에 요약하고, 각 항목에서 해당 작업 화면으로 1클릭 진입한다. 신청 대기 건이 최우선 — 이벤트 카드에서도 신청 관리로 바로 들어간다.
User journey Entry points: 파트너 로그인 직후 기본 착지 · 사이드바 "홈" 클릭 · URL 직접 진입/북마크 · 알림 메일의 링크.
Exit points: 대기 신청 카드 / 이벤트 카드의 신청 버튼 → 신청 관리 · 이벤트 카드 → 파티·이벤트(상세/명단) · 정산 카드 → 정산 · 사이드바 4메뉴 · 비로그인이면 파트너 로그인으로.
Background web-mvp pivot으로 파트너 코어가 "이벤트/파티 관리 → 신청 승인/거절 → 참가자 명단 → 정산 조회"로 축소됐다 (docs/architecture/web-mvp-pivot.md §4). 모바일 파트너 홈 v2(알림 센터형 피드)의 "오늘 신경 쓸 것만 보여준다" 철학은 유지하되, 데스크톱 운영 환경에 맞게 좌측 사이드바 + 메인 대시보드 도구형 레이아웃으로 재구성. 모바일의 6개 시급도 카테고리 중 체크인(LIVE)·온보딩 계열을 덜어내고, 남는 코어를 요약 카드 3장(대기 신청 · 오늘·임박 이벤트 · 최근 정산) + 이벤트 카드 리스트로 평탄화했다. 파트너 입점은 운영자 수동이므로 신규 파트너에게도 온보딩 위저드 없이 단순 empty + CTA만 보여준다.
Frequency 파트너 세션마다 진입하는 첫 화면. 모집 중 이벤트가 있으면 하루 수회 — 신청 대기 확인이 주 목적.

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. web_partner는 데스크톱 우선 (web_foundation_responsive surface priority) — Desktop(≥1280) blueprint가 1차 산출물.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 이 화면은 운영 도구이므로 콘텐츠 캡 1440px까지 허용(풀-와이드 도구 화면 규칙). 1280 viewport 기준: 사이드바 240px 고정 + 메인 컬럼 fluid.

Global edge cases

  • 네트워크 끊김 — 메인 콘텐츠 영역만 "다시 시도" 안내로 교체 (사이드바는 유지). 진입 중 끊기면 Loading의 실패 에지케이스와 동일.
  • 다크 모드 — 우측 상단 Dark 토글로 확인. surface/배경/텍스트 토큰 전환 + primary → color-partner-dark-primary. pulse·강조 로직은 색만 바뀌고 동일.
  • 접근성 — tab 순서: 사이드바(브랜드 제외 메뉴 4 → 계정) → 인사 헤더 건너뜀 → 요약 카드 3 → 이벤트 카드별 (제목 → 버튼들). 모든 카드형 클릭 타깃에 visible focus ring. 수치는 라벨과 함께 읽히도록 (예: "대기 중 신청 7건").
  • reduced motion — prefers-reduced-motion 시 pulse·shimmer 정지 (도트는 고정 표시), hover transition 0ms.
