Route / Surface DeletionCompleteRoute — DeletionCompletePage (no params)

Hierarchy Parent: DeletionVerifyPage — coordinator.goComplete()로 stack 교체.
Children: — (terminal screen — "확인" 탭 시 home으로 go + signOut + success snackbar)
Purpose 탈퇴 요청 wizard의 마지막 단계 — 요청이 정상 접수되었음을 확인하고 사용자에게 작별을 인사한다. 7일 grace period 정보를 한 번 더 상기시켜 사용자가 마음을 바꿀 수 있는 마지막 mental anchor를 제공.
User journey Entry points: VerifyPage에서 confirm + requestDeletion 성공 → coordinator.goComplete() (go — wizard stack 교체).
Exit points: ① "확인" 탭 → appCoordinator.goToHome() + signOut() + showMinglitSuccess('탈퇴 요청이 접수되었어요.') · ② 시스템 back → 사실상 의미 없음(다음 frame에서 home/login으로 redirect됨).
Background 탈퇴는 destructive irreversible 액션이라 confirmation 화면을 별도 step으로 분리 — 사용자가 "내가 정말 했구나"를 인지할 수 있는 시각적 closure가 필요. 큰 success icon + 짧은 메시지 + 7일 복구 안내(reassurance) 패턴은 LoginPage signup-success 등 다른 wizard 종료 화면과 동일 톤. "확인" 탭 시 즉시 home으로 가지만 Future.delayed(Duration.zero)로 signOut을 lazy 호출 — context after dispose 에러 방지(다른 destructive flow와 동일 패턴).
Frequency매우 낮음 — 계정당 ≤ 1회 (탈퇴 요청 성공 시).

States

2 state — baseline = 진입 직후(success hero) · "확인" 탭 후 transition(snackbar 보임 + go to home + signOut). 데이터 fetch 없음.

State 종류 식별 기준: ① 진입 직후 — coordinator.goComplete()로 stack 교체된 직후. 사용자는 hero를 보고 안내문을 읽음 (baseline) · ② "확인" 탭 후 — _finish() 시퀀스(goToHome → Future.delayed(0) → signOut → showMinglitSuccess) 진행. 화면 자체는 home으로 바뀌지만 success snackbar가 잠시 표시됨. 위젯은 ConsumerWidget · 내부 state 없음 · provider read만 (appCoordinator + authController.notifier).

Global edge cases

  • Loading / Error mini-table 없음 — 위젯 자체는 fetch하지 않고, _finish 안에서 throw해도 catch 처리 없이 그대로 propagate (사용자는 home으로 가있고 SnackBar만 안 보임).
  • 다크 모드 — scaffold/text/icon 모두 dark 토큰 swap. primary purple은 그대로.
  • 접근성 — title은 headlineSmall로 screen reader가 강조해서 announce. icon은 의미 정보 없는 것으로 처리됨 (Icon default semantics).
  • 화면 회전 — Spacer 기반 layout이라 자연 대응. hero가 vertical center 유지.
  • signOut 실패 — _finish 안에서 signOut이 throw해도 catch 없음 — 화면은 이미 home으로 갔으므로 사용자에게 보이는 변화 없음. 다음 protected request에서 token 유효 여부에 따라 자연 보정.
