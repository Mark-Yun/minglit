Event Create

Overview

Status ✅ 디자인완료 — 2 tab + recurrence on/off + submit/error/init = 6 state
App app_partner
Category party · event · create (new occurrence)
Route / Surface EventCreateRoute · widget: EventCreatePage + EventCreateOperationTab + EventCreateInfoTab (TabBar 2-tab)
Path /more/parties/:partyId/events/create
Hierarchy Parent: PartyDetailPage (Tab1 "이벤트 관리" → "회차 만들기" 버튼에서 진입)
Children: — (섹션별 편집은 MaterialPageRoute로 push되는 별도 화면 — PartyBasicInfoEditScreen, PartyCapacityContactEditScreen, PartyLocationEditScreen, TicketTemplateManageScreen. 같은 partyId scope을 공유.)
Purpose 파트너가 기존 파티에서 새 회차(이벤트)를 생성한다. 진입 시 부모 파티의 기본 정보 / 정원 / 연락처 / 입장 그룹 / 티켓 템플릿이 자동 prefill되며 (Event.createFromParty + Ticket.createFromTemplate), 파트너는 일정·반복 규칙·티켓 등 운영 정보만 보강하면 된다.
User journey Entry points: PartyDetailPage 이벤트 관리 탭의 "회차 만들기" CTA — partyId 전달.
Exit points: 생성 성공 → context.pop() + 성공 스낵바("새로운 회차가 성공적으로 생성되었습니다.") → PartyDetailPage 복귀. 실패 → handleMinglitError 스낵바 (page 유지). back 버튼 → 변경사항 confirm 다이얼로그 없이 즉시 pop.
Background 밍글릿 파티 모델은 party (정기 모임 컨테이너) + event (한 번의 회차)로 분리된다. 매 회차마다 동일한 정보(타이틀/소개/장소/티켓)를 다시 입력하지 않도록 부모 파티의 template을 instance로 복사해서 시작한다. 반복 일정이 켜진 경우 recurrence_rule이 함께 생성되어 매주/격주/매월 자동 회차 생성 잡(server-side)이 활성화된다. 단, 화면 자체에는 eventId edit 모드 없음 — 항상 신규 생성.
Frequency 한 파티당 회차마다 1회. 정기 파티(반복 사용)에선 1주~1달에 한 번씩 진입.

Global edge cases

  • partyId가 잘못된 값 — partyDetailProvider future가 throw → initWithParty 미호출, 빈 상태로 머무름. 명시적 에러 표시 없음 (drift 후보).
  • 제출 중 back 누름 — 별도 가드 없음. submit future는 백그라운드에서 계속 진행되며 state.status 갱신은 mounted 가드로 차단. 이미 만들어진 event는 server-side에 남는다.
  • recurrence + location 동시 신규 생성 — locationRepository.createLocation 실패 시 event 자체도 생성 안됨 (await chain). 그러나 createEvent 성공 후 recurrenceRule.create 실패 시 event는 남고 rule만 빠지는 부분 성공 가능 — 사용자에겐 일반 에러 토스트만.
  • "입장 조건" 섹션 — onTap이 빈 함수라 탭해도 아무 일 없음. edit 아이콘은 그대로 보여 사용자에게 혼동 줄 수 있음 (drift 후보 — isEditable=false 권장).
  • InfoTab 공개 설정 카드 — horizontal margin이 0이라 다른 EditableSection과 정렬이 안 맞음 (세 번째 섹션의 padding 이후 edge-to-edge로 카드가 붙음).
  • localization — title은 l10n.eventCreate_title, Tab1 라벨은 하드코딩 "운영 및 티켓", Tab2 라벨은 l10n.partyDetail_tab_info로 일관성 부족 (drift 후보).
