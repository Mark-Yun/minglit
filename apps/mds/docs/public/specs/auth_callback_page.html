Purpose 외부 OAuth 페이지(Google · Apple · Kakao)에서 돌아온 사용자를 Supabase 세션 처리 후 원래 가려던 화면(또는 홈)으로 자동 redirect 한다. 사용자에게 보이는 시간은 보통 100~500ms — Supabase SDK가 hash fragment를 파싱하는 동안만.
User journey Entry points: OAuth provider의 redirect URL 응답 (사용자가 OAuth 페이지에서 인증 승인 후 자동 진입). 직접 URL 진입은 사실상 의미 없음.
Exit points: 인증 성공 → auth_return_url SharedPreferences 값 (또는 /). 10초 timeout 또는 callback 실패 → "로그인 화면으로 돌아가기" 버튼 → LoginRoute.
Background OAuth 흐름은 외부 브라우저로 이탈 후 deep-link/URL scheme으로 돌아오기 때문에 앱 내에 명시적 "복귀 처리" 화면이 필요. 사용자는 잠깐의 로딩만 인지 — 사실상 내부 로직 화면. Supabase의 onAuthStateChange가 SIGNED_IN 이벤트를 emit하는 순간 자동 redirect. 10초 timeout은 hash fragment 손상 / 서버 응답 지연에 대비한 안전망.
Frequency OAuth 로그인 시도 시마다 1회 — 보통 사용자가 인지 못함 (수백 ms).

States

3 states — _isProcessing(true/false) + Supabase auth 이벤트 도착 여부. 사용자 인지 가능 시간이 짧지만 timeout 분기는 명시적 표시.

State 종류 식별: _isProcessing 플래그 + currentUserProvider 결과 + 10초 Timer. Processing(스피너) → Redirecting("인증 성공! 이동 중...") → 또는 Timeout(에러 아이콘 + 재시도 버튼).

Global Behavior

Cross-cutting interactions

사용자 액션화면에 보이는 결과
OS back / 시스템 back swipe OS 기본 동작 — 이 화면은 라우트 stack에 push되지만 보통 사용자가 인지하기 전에 redirect됨. timeout 시점이라면 LoginRoute로 명시적 이동 권장.
외부 OAuth 페이지에서 거부 / 닫기 OS의 deep-link/redirect가 callback URL을 호출하지 않음 → 이 화면 자체에 진입 안 함 (앱이 background에 머무름).
앱 백그라운드 → foreground 복귀 Supabase SDK가 hash fragment를 한 번 더 시도. _isProcessing이 살아 있으면 그대로 대기, 사라졌으면 timeout state.

Global edge cases

  • 네트워크 끊김 — Supabase가 토큰 교환 실패 → auth 이벤트 미발생 → 10초 후 Timeout state. 사용자에게 명시적 "네트워크" 메시지는 X (의도적 단순화).
  • 다크 모드 — Scaffold/메시지가 토큰 기반 → 자동 swap. 에러 아이콘은 color-error 라이트/다크 토큰 사용. 스피너는 color-primary.
  • 접근성 — 메시지가 stub 한국어 한 줄 — TalkBack/VoiceOver가 자동 읽음. 스피너는 자체 의미 없음(decorative). 에러 아이콘에 별도 semanticLabel 없음 → 옆 메시지가 의미 전달.
  • 이미 로그인된 채 재진입 — initState의 currentUserProvider != null 체크가 즉시 redirect. 화면 잠깐도 안 보임.
