Hierarchy Parent: — (top-level screen, push from HomePage AppBar 검색 아이콘)
Children: MinglitEventCard (결과 리스트 cell — 별도 spec)
Purpose 이벤트(파티/클래스/모임)를 키워드로 즉시 검색해 EventDetail로 진입할 수 있게 한다. home 추천 피드에서 노출되지 않는 long-tail 이벤트를 사용자가 능동적으로 찾는 보조 도구. PGroonga 기반 한글 형태소 검색을 백엔드에서 수행 (search-and-recommendation.md).
User journey Entry points: HomePage AppBar 돋보기 아이콘 · 외부 딥링크 /search.
Exit points: ① 검색 결과 카드 탭 → EventDetailPage · ② AppBar back → 이전 화면 (보통 Home).
중간 경로: 빈 입력 상태에서 추천 키워드 chip 탭 → 자동 입력 + 즉시 fetch.
Background PGroonga 한글 검색 인덱스를 활용 — 추천 피드에 안 뜨는 기간/소규모 이벤트도 발견 가능해야 한다는 PM 요구. 매 keystroke fetch는 네트워크 비용 + 백엔드 부하가 크므로 500ms debounce 후 1회 fetch. 비어있는 검색어(query.isEmpty) 진입 시 추천 키워드 chip 4종을 노출해 cold-start UX 보강 (#997, #1381).
Frequency 능동 사용자 기준 세션당 0~3회 — 추천 피드가 우선 소비되는 구조라 보조 도구.

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
키 입력 (TextField onChanged) 매 keystroke 마다 _debounce?.cancel() + 500ms timer 시작. timer 만료 시 searchQueryProvider.update(value.trim()) 1회 호출 → searchResultsProvider가 재계산되어 fetch.
clear 아이콘 탭 (suffixIcon) _controller.clear() + searchQueryProvider.clear() 동시 호출. body는 즉시 Empty(baseline)로 복귀. 진행 중 fetch가 있어도 query가 비어 더는 사용되지 않음.
back (AppBar / 시스템) 이전 화면 복귀. dispose()에서 _debounce?.cancel() + _controller.dispose(). searchQueryProvider는 dispose에서 clear하지 않음 — Riverpod ≥3 dispose 중 state 변경 금지 (Fix #226). 대신 다음 진입 시 initState microtask로 clear.
다크 모드 토글 scaffold/AppBar bg → color-dark-background, MinglitChip / 안내 텍스트 / spinner는 토큰 기반 자동 swap.

Global edge cases

  • 진입 시 잔여 query 정리 — initState에서 Future.microtask(() => searchQueryProvider.clear()) 호출 (Fix #226 — Riverpod 3 dispose 안전성). dispose에서 clear하면 unsafe state mutation.
  • debounce timer 누수 방지 — chip 탭 시 + dispose 시 _debounce?.cancel() 명시.
  • 공백만 입력 — value.trim()으로 공백을 제거한 키워드를 query에 반영 → 빈 문자열이면 Empty로 자동 복귀.
  • fetch race — 짧은 간격 keyword 변경 시 이전 fetch가 늦게 도착해도 Riverpod이 가장 최근 query 기준 결과만 노출 (provider invalidation).
  • retry 없음 — Error state에서 사용자가 직접 keyword를 다시 입력해야 재시도. 자동 retry 없음.
