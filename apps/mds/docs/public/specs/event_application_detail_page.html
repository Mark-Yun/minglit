Event Application Detail

Overview

Status ✅ 디자인완료 — 6개 state · pending_review/approved/rejected/paid + loading + error
App app_partner
Category application · detail · review
Route / Surface EventApplicationDetailRoute · widget: EventApplicationDetailPage
Path /applications/event/:applicationId
Hierarchy Parent: EventApplicationManagePage (탭 목록에서 행 탭으로 진입)
Children: — (거절 사유 다이얼로그는 state 5로 이 spec 안에서 다룸)
Purpose 파트너가 한 이벤트 신청을 깊게 검토하는 단일 화면. 신청자 프로필·결제 정보·상태를 한 페이지에서 확인하고, 심사 중인 건은 같은 화면에서 승인 또는 거절 처리한다.
User journey Entry points: EventApplicationManagePage의 "승인됨"/"거절됨" 탭에서 신청 행 탭 (Fix #1860 — 기존엔 행 자체 탭 동선 부재).
Exit points: 승인/거절 처리 성공 → 스낵바 "처리가 완료되었습니다." → Navigator.pop()로 자동 복귀 / 뒤로 가기 → 신청 목록 / 처리 실패 시 handleMinglitError 다이얼로그 (화면은 유지).
Background 이벤트 신청 워크플로우는 pending_review → (approved | rejected) → 결제 시 paid로 이동. 파트너가 status별 분기를 한 화면에서 바라보면서 단일 신청을 깊게 검토(거절 사유 작성·결제 금액 확인·신원 정보 검증)할 수 있도록 설계. 승인/거절 액션은 status가 pending_review일 때만 노출되어 부주의한 재처리를 방지.
Frequency 이벤트 운영 기간 중 신청 도착마다. 인기 이벤트는 시간당 다회 진입.

States

시각 변형 6종. baseline = pending_review (심사 액션 노출), 나머지는 additive diff.

State 종류 식별 기준: application.status (pending_review · approved · rejected · paid) + async lifecycle (Loading · Error) + 거절 다이얼로그 modal overlay. status enum은 _StatusBadge switch에서 4값을 매핑하며, fallback은 status string 그대로 outline 색으로 표시.

Global edge cases

  • 네트워크 끊김 — 진입 직후라면 Loading → Error로 전환 (재시도 CTA 없음). 심사 처리 중이라면 controller가 AsyncError → handleMinglitError 다이얼로그.
  • 다크 모드 — 우측 상단 Dark 토글로 확인. Partner primary는 color-partner-dark-primary(#9b7bec)로 자동 전환. 배지 bg는 각 색상의 alpha 비율 그대로 유지.
  • 알 수 없는 status — _StatusBadge switch fallback이 status 문자열 그대로 + colorScheme.outline으로 표시. 백엔드가 새 status 추가 시 디자인 업데이트 전까지 임시 노출.
  • 접근성 — CircleAvatar의 이니셜은 단일 글자 — screen reader는 name을 별도 Text로 읽음. 거절/승인 버튼은 Material 기본 시맨틱 (semantics label = label text).
  • 모델-UI drift — refund_status·paid_at·payment_id는 모델에 존재하지만 page는 미렌더. Refunded/Canceled 케이스 가시성은 후속 개선 후보.
