Sub-anatomies — required per region

Top-level blueprint은 화면 골조만 보여줌. 각 numbered region이 internal composition을 가지면 그 region마다 별도 Sub-anatomy 섹션을 반드시 작성 — 이게 빠지면 다른 사람/agent가 이 spec만 보고 그 영역을 정확히 재현 못 함. 구조는 평면 PARALLEL — Sub-anatomy ①, Sub-anatomy ②, ③ ... 같은 level에서 나열만. 깊이를 늘리지 않음 (sub-sub-anatomy 만들지 말 것).

States

각 state의 시각 mockup + state-specific 사양 — 6 aspect rows (조건 · 사용자 액션 · 에지케이스 · 컴포넌트 · 토큰 · 노트). 첫 state mockup만 spec-mode annotation 표시. Dark mode toggle로 다크 변형 확인.

States gallery

각 state는 독립된 미니 테이블 — header(state name + tag) → 좌측 mockup(rowspan=6) + 우측 6 aspect rows (조건 / 사용자 액션 / 에지케이스 / 컴포넌트 / 토큰 / 노트). 여러 mini-table이 vertical stack으로 쌓임. cross-cutting 동작은 아래 Global Behavior 섹션에.

📋 Aspect 행 작성 룰
· 조건 — provider 값 / route param / user state / async status 기준 명시 (예: provider.isLoading, admissionState == eligible)
· 사용자 액션 — 이 state에서 가능한 모든 탭/스와이프/입력 (액션 N개면 N행으로 반복). disabled/무반응이면 "탭 무반응" 한 행
· 에지케이스 — 이 state 한정 변형. 없으면 "—". (cross-cutting edge는 Global Behavior로)
· 컴포넌트 — 첫 state는 풀 리스트. 2번째 state부터 변경분만: + X (추가) · − X (제거) · ↔ X → Y (교체) · 동일 (변경 없음) · — (해당 없음)
· 토큰 — 컴포넌트와 동일 룰. 첫 state는 풀 리스트, 이후 변경분만
· 노트 — free-form designer/dev memo (결정 근거, TODO, 의문점). 없으면 "—"

State 종류 식별 — Default/Empty/Loading/Error는 default placeholder. 화면별로 실제 provider state · route param · user state 기준으로 enumerate. 예: wizard → Step1/Step2/Submit/Success · event-detail → admission state별 (eligible/soldOut/applied/rejected/...).

Global Behavior

화면 전반에 걸친 cross-cutting 동작만 — motion timing, async lifecycle, screen-wide edge cases. state-specific 동작은 위 States section의 각 state mini-table에 있음.

Cross-cutting interactions

판단 기준 — 이 액션이 모든 state(또는 다수 state)에서 동일하게 가능하면 cross-cutting. 특정 state에서만 가능하면 그 state의 mini-table로. 회색지대일 때는: "Default state에서만 enabled, 다른 state는 무반응" → state-specific (Default mini-table에). "모든 state에서 항상 가능" → cross-cutting.

사용자 액션 화면에 보이는 결과
뒤로 가기 (OS back / AppBar back) [이전 화면으로 — 모든 state에서 동일]
Pull-to-refresh (있다면) [provider refresh — loading → data 재진입]
