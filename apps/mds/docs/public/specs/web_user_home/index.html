Purpose 이벤트를 발견하는 첫 화면. 방문자(로그인 여부 무관)가 진행 예정 이벤트를 그리드로 훑어보고, 관심 이벤트의 상세 페이지(→ 구매·신청)로 진입한다. 본인인증을 마친 사용자는 "참가 가능한 이벤트만" 체크로 자기 자격에 맞는 이벤트만 추릴 수 있다. 웹 MVP 의 제품 코어 "이벤트 탐색 → 상세 → 구매·신청" 퍼널의 출발점.
User journey Entry points: URL 직접 진입 (/) · 검색엔진/SNS 유입 (비로그인 다수) · 로그인 직후 복귀 · 상세 페이지에서 로고/back 으로 복귀.
Exit points: ① 카드 클릭 → 이벤트 상세 (/events/:id) · ② 검색 필드 클릭 → 검색 화면 (/search) · ③ "로그인" 클릭 → 로그인 화면 (성공 시 이 화면으로 복귀) · ④ 아바타 클릭 → 마이페이지.
Background web-mvp pivot — 제품 코어를 "이벤트 탐색 → 상세 → 구매·신청"으로 좁힌 첫 유저웹 화면. 모바일 홈의 매칭/태그추천/NowBar/AI피드 계열 요소는 deprecated 로 모두 제외하고, 헤더 + 카드 그리드의 커머스형 목록 구조로 재설계 — 필터는 "참가 가능한 이벤트만" 체크박스 하나로 최소화 (지역/날짜/정렬은 MVP 비범위 — Mark 피드백 2026-06-07). 모바일과 달리 비로그인 공개 열람을 허용 — 검색엔진/SNS 유입이 첫 방문의 대부분이고, 로그인 요구는 보호 액션(구매·신청·마이페이지) 시점으로 미룬다. 1280px 데스크톱을 주 캔버스로 설계 (Mark 지시 2026-06-07) — 모바일 variant 는 후속 pass.
Frequency 방문마다 1회 이상 — 유저웹의 기본 랜딩이자 탐색 허브.

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. 이 화면은 Desktop (≥1280) variant 가 주 blueprint — breakpoint variants 표 참조.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 이 화면은 Desktop-first 예외 화면 — 1280 baseline 으로 먼저 설계하고 Mobile blueprint 는 후속 pass 에서 추가한다 (History 참조).

Variant Breakpoint 이 화면에서의 차이
Desktop (주 variant) ≥ 1280px 헤더(로고 + 검색 필드 + 아바타) + 참가 가능 체크박스 행(조건부) + 12col 그리드에서 카드 4col × 3장/행 · 컨테이너 1200px 캡 중앙 정렬 · gutter 32px — 아래 blueprint 가 이 variant.
Tablet 768–1279px 별도 blueprint 없음 — Desktop 레이아웃 축소: 카드 2col (gap spacing-medium (16px)) · 검색 필드 폭 축소 (≈280px) · 체크박스 행 동일 (조건부 노출 규칙 포함).
Mobile < 768px 후속 pass 에서 작성 (TBD) — 카드 1col · 검색은 헤더 아이콘으로 축약 예정. 이번 pass 는 1280 baseline 만 (Mark 지시 2026-06-07).

Sub-anatomy ② — EligibilityFilter (조건부)

그리드 좌상단의 "참가 가능한 이벤트만" 체크박스 하나 — 이 화면의 유일한 필터. 로그인 + 본인인증 프로필을 가진 사용자에게만 노출되고, 체크하면 본인 프로필 (나이·성별 등) 기준으로 참가 자격이 되는 이벤트만 그리드에 남는다. 비로그인 / 프로필 미완성 사용자에게는 체크박스를 그리지 않으며 — 바가 비므로 필터 행 자체를 생략하고 그리드가 위로 당겨진다. 지역/날짜/정렬 필터는 web MVP 비범위 (Mark 피드백 2026-06-07 — History 1.1).

Motion & timing

duration 은 MDS motion 토큰 (micro 100 / fast 200 / medium 350 / slow 500) — 웹 구현은 CSS transition-duration / Tailwind duration-N 으로 같은 ms 소비. prefers-reduced-motion 대응은 Global edge cases 참조.

첫 화면 진입 (서버 렌더) 없음 (0ms) SSR 즉시 표시 — 진입 모션 없음
"참가 가능" 체크 토글 → 목록 교체 medium (350ms) 그리드 crossfade — 스켈레톤 경유 시에도 동일

Global edge cases

  • 네트워크 끊김 — 첫 로드 실패는 Error state. 무한 스크롤 추가 로드 실패는 하단 스피너 제거 후 조용히 실패 (모바일 behavior 상속).
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 배경/표면/텍스트/divider 토큰 전환 · 카드 이미지 위 overlay 는 dark scrim 고정이라 모드 무관 · active 칩의 primary 강조 유지.
  • 접근성 — 키보드 tab 순서: 로고 → 검색 → 로그인/아바타 → 참가 가능 체크박스(노출 시) → 카드 순. 카드 전체가 단일 링크 + visible focus ring. 200% 줌에서 가로 스크롤 없이 사용 가능 (그리드가 하위 tier 컬럼 수로 reflow — foundation 규칙).
  • reduced motion — prefers-reduced-motion 시 카드 hover 모션·목록 crossfade transition 0ms · skeleton shimmer 정지 (정적 표시).
  • SEO / 공유 — public 페이지: title/og 메타 + 이벤트 목록 서버 렌더 (비로그인 공개 열람과 한 쌍의 결정). 체크 query 가 붙은 URL 을 공유받은 사람에게 자격 정보가 없으면 query 는 무시되고 전체 목록.
  • 초광폭 (≥1920px) — 1200px 캡 유지, 잉여 폭은 배경 (foundation 규칙 — 카드 4col 로 늘리지 않음).
