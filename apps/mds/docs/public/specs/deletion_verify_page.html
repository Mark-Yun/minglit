Route / Surface DeletionVerifyRoute — DeletionVerifyPage({reasonCode, reasonText})
Path/my/privacy/delete/verify · query: ?reasonCode=&reasonText=
Hierarchy Parent: DeletionInfoPage — coordinator.pushVerify로 push.
Children: DeletionCompletePage (success — coordinator.goComplete) · in-place confirm dialog (showMinglitConfirm) — wizard 마지막 mental gate.
Purpose 탈퇴 요청 직전 본인 확인 — 비밀번호 사용자는 현재 비밀번호 입력으로, 소셜 사용자는 다음 단계의 reauth flow 안내로 가벼운 검증 추가. 탈퇴는 destructive + 되돌리기 어려운 액션이라 password / reauthenticate라는 사실상 두번째 인증을 명시적으로 통과하게 한다.
User journey Entry points: InfoPage "계속 진행" 탭 → coordinator.pushVerify(reason).
Exit points: ① "탈퇴 요청" 탭 + (비밀번호 검증 통과) + confirm dialog "탈퇴 요청" → controller.requestDeletion → CompletePage(go) · ② confirm dialog "돌아가기" 또는 barrier dismiss → 본 화면 그대로 유지 · ③ 비밀번호 빈 필드 / 잘못된 비밀번호 → 화면 머무름(error 표시) · ④ 뒤로 가기 → InfoPage 복귀.
Background 탈퇴 행위가 stranger / device 탈취 시나리오에서 악용되지 않도록 본인 확인을 강제. 비밀번호 사용자에겐 그 자리에서 password reauth(controller.reauthenticate(password)), 소셜 사용자는 controller가 별도 reauth flow를 수행하도록 위임 (현재 widget 안에서는 reauth(null)만 호출 — Phase 2에서 OAuth re-popup 예정). 확인 dialog를 한 번 더 끼워 넣어 "버튼 잘못 누름" 사고를 막는다(Fix 패턴 — 다른 destructive flow와 동일 톤).
Frequency매우 낮음 — 탈퇴 wizard 진입 시 1회.

Global edge cases

  • 네트워크 끊김 — reauthenticate / requestDeletion이 timeout/network error로 throw → State 6(snackbar) 진입. 화면은 그대로 유지.
  • 다크 모드 — scaffold/Card/TextField/dialog 모두 dark 토큰 자동 swap. password obscure dot의 색은 onSurface 기반.
  • 접근성 — TextField는 obscure로 screen reader가 비밀번호 텍스트를 읽지 않음. errorText는 accessibility node에 안내.
  • 키보드 자동 포커스 — 진입 직후 자동 focus 없음 (autofocus 미설정). 사용자가 탭해야 키보드 등장 — 의도된 mental gate.
  • Disposed during async — _submitDeletion 내부 모든 await 후 !context.mounted 체크 — race window 안전.
