Sub-anatomies — required per region

Top-level blueprint은 화면 골조만 보여줌. 각 numbered region이 internal composition을 가지면 그 region마다 별도 Sub-anatomy 섹션을 반드시 작성. 구조는 평면 PARALLEL — Sub-anatomy ①, ②, ③ ... 같은 level 나열, 깊이 금지. breakpoint 간 internal composition이 다르면 해당 Sub-anatomy 안에 variant를 함께 기술 (별도 Sub-anatomy로 분리하지 않음).

States

각 state의 시각 mockup + state-specific 사양 — 6 aspect rows (조건 · 사용자 액션 · 에지케이스 · 컴포넌트 · 토큰 · 노트). States는 breakpoint와 무관하게 공유 — variant별로 복제하지 않음. mockup은 surface의 기본 breakpoint로 (web_user → Mobile 375px · web_partner → Desktop).

States gallery

각 state는 독립된 미니 테이블 — header(state name + tag) → 좌측 mockup(rowspan=6) + 우측 6 aspect rows (조건 / 사용자 액션 / 에지케이스 / 컴포넌트 / 토큰 / 노트). cross-cutting 동작은 아래 Global Behavior 섹션에.

📋 Aspect 행 작성 룰
· 조건 — 데이터 로드 상태 / URL param / 로그인·권한 상태 기준을 디자인 언어로 명시 (예: "이벤트 데이터 로드 완료", "비로그인 방문")
· 사용자 액션 — 이 state에서 가능한 모든 클릭/탭/입력/호버 (액션 N개면 N행으로 반복). disabled/무반응이면 "클릭 무반응" 한 행
· 에지케이스 — 이 state 한정 변형. 없으면 "—". (cross-cutting edge는 Global Behavior로)
· 컴포넌트 — 첫 state는 풀 리스트. 2번째 state부터 변경분만: + X (추가) · − X (제거) · ↔ X → Y (교체) · 동일 (변경 없음) · — (해당 없음)
· 토큰 — 컴포넌트와 동일 룰. 토큰 이름은 MDS 체계 (color-primary · spacing-medium 등) — 구현은 CSS variable var(--color-primary) / Tailwind text-[var(--color-primary)] 형태로 소비
· 노트 — free-form designer/dev memo. 없으면 "—"

State 종류 식별 — Default/Empty/Loading/Error는 default placeholder. 화면별로 실제 데이터 상태 · URL param · 사용자 상태 기준으로 enumerate. Behavior Source 모바일 spec의 state enumeration 을 출발점으로 삼되, 웹 전용 state(예: 비로그인 public view)를 추가.

Global Behavior

화면 전반에 걸친 cross-cutting 동작만 — motion timing, async lifecycle, screen-wide edge cases. state-specific 동작은 States section의 각 mini-table에. 모바일 spec에서 상속한 behavior 는 Behavior Source 기준 — 여기엔 웹에서 달라지는 점만 추가.

Motion & timing

임시값 사용 금지 — duration은 MDS motion 토큰에서 선택. 토큰 이름은 모바일과 동일 체계 (micro/fast/medium/slow) — 웹 구현은 CSS transition-duration / Tailwind duration-[N] 로 같은 ms 값을 소비 (예: fast (200ms) → transition: ... 200ms 또는 duration-200). prefers-reduced-motion 대응은 Global edge cases 에 명시.

✅ Authoring checklist (web)

spec 작성 완료 전 항목별 self-check. 모든 ✓를 채울 수 있어야 published-ready.

  • Head meta — feature-status · features · surface 3개 meta 채움. surface는 Overview의 Surface 행과 일치
  • Header — Title (h1)만
  • Overview — Status · Surface · Category · Route · Behavior Source · Hierarchy · Purpose · Entry/Exit · Background · Frequency 모두 채움 (해당 없으면 "—")
  • Behavior Source — 상속하는 모바일 spec 경로 + 무엇을 상속하고 무엇이 달라지는지 1줄. web-native 화면이면 명시적으로 "—"
  • History — Initial row + 의미 있는 변경 row (최신 → 오래된 순)
  • Responsive Layout — variants — Mobile (<768) blueprint 필수. Desktop (≥1280)은 구조가 다를 때만 별도 blueprint, 동일하면 표에 "Mobile과 동일" 명시. Tablet은 따라가는 variant 1줄
  • Layout — Sub-anatomy — internal composition을 가진 모든 region마다 1 섹션 (평면 나열). breakpoint별 차이는 같은 Sub-anatomy 안에 기술
  • States — breakpoint 공유 — States 테이블은 variant별로 복제하지 않음. mockup은 surface 기본 breakpoint로
  • States — 종류 enumerate — placeholder 그대로 쓰지 않고 실제 데이터/사용자/URL 상태 기준 enumerate. Behavior Source 의 state 목록과 대조
  • States — mini-table 6 rows — 모든 state가 (조건 / 사용자 액션 / 에지케이스 / 컴포넌트 / 토큰 / 노트) 6행 채움
  • States — 첫 state 풀 리스트, 2번째+ additive diff — + X / − X / ↔ X → Y / 동일 / — 5종 prefix만
  • Global Behavior — 웹 cross-cutting — 브라우저 back / 새로고침·URL 진입 / 비로그인 접근 검토됨
  • Global Behavior — Motion — 모든 duration이 motion token 이름 + ms로 표기. 임시값 금지. reduced-motion 검토
  • 토큰 표기 통일 — 토큰 이름은 MDS 체계 (spacing-medium (16px) 형태). 구현 참조는 CSS variable / Tailwind 관점 (var(--spacing-medium))

  • Screen registry — src/lib/screen-definitions.ts 의 해당 surface 배열 (WEB_USER_SCREENS / WEB_PARTNER_SCREENS) 에 등록
