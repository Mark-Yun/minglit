웹에서 달라지는 점: 모바일의 생성(2-tab)·수정 별도 화면을 단일 폼 페이지 하나로 통합(생성/수정 모드 분기) · 가격·티켓은 이 화면에서 편집하지 않음 — 파티의 티켓 템플릿이 회차 티켓으로 복사되는 모델이라 읽기 전용 "티켓 구성" 요약만 보여주고 편집은 web_partner_party_create로 위임 (가격 인상 시 신규 신청자만 적용 규칙도 파티 spec 관심사로 이동) · 반복 규칙은 파티(web_partner_party_create)에서 설정하고, 자동 생성된 회차가 이 화면으로 편집 진입 — 이 화면은 단일 회차만 · 입장 조건 편집은 범위 밖 · 이벤트 취소는 별도 화면 대신 이 화면의 위험 구역 + 확인 다이얼로그로 통합 · 변경 사유 바텀시트 → 다이얼로그.
Hierarchy Parent: 콘솔 셸 "파티·이벤트" 영역 — web_partner_party_events (목록 허브)에서 진입.
Children: 취소 확인 다이얼로그 · 핵심 변경 확인 다이얼로그는 이 spec 내부 — 별도 spec 없음.
Purpose 파트너가 한 번의 회차를 열고, 이미 연 회차를 안전하게 고친다. 생성 시엔 파티를 고르면 장소·정원·티켓 구성이 미리 채워져 일시만 정하면 되고, 수정 시엔 신청자 보호 규칙(핵심 필드 경고·제한 + 자동 알림)이 화면에 그대로 드러난다. 이벤트 취소는 전액 자동 환불 + 신청자 알림을 고지하는 확인 다이얼로그를 거치는 불가역 액션.
User journey Entry points: 파티·이벤트 목록의 "회차 만들기"(생성) / 이벤트 카드·상세의 "수정"(수정) · 홈 empty CTA "파티·이벤트 만들러 가기"에서 파티 생성 후 이어짐 · URL 직접 진입/북마크.
Exit points: 저장 성공 → 파티·이벤트 목록(또는 이벤트 상세)으로 복귀 + 성공 안내 · 취소 확정 → 목록으로 복귀 + "이벤트가 취소되었어요" 안내 · 뒤로가기/브라우저 back → 변경사항 있으면 버림 확인 후 이탈.
Background 모바일은 생성(EventCreatePage 2-tab)과 수정(EventEditPage)이 별도 화면이지만, 웹 MVP는 PRD 원칙 "생성 화면을 편집 모드로 재사용 — 학습 비용 0"을 그대로 적용해 하나의 폼 페이지에 생성/수정 모드를 두었다. 티켓 템플릿·반복 규칙은 파티(web_partner_party_create)의 책임으로 정리하고 — 백엔드도 파티 ticket_templates → 회차 tickets 복사 모델 — 이 화면은 회차의 본질인 파티 선택(생성) → 일시 → 장소 → 정원 → 기본 정보로 폼을 평탄화했다. 티켓 구성은 읽기 전용 요약으로만 보여준다 (편집 진입 링크 제공). 취소는 운영팀 수동 환불을 없애는 코어 플로우라(전액 자동 환불 강제 — Eventbrite 패턴) 별도 화면 없이 이 화면의 위험 구역에서 2단계 확인으로 처리한다.
Frequency 정기 파티 기준 1주~1달에 1회 생성 + 이벤트당 1~3회 수정. 주 케이스: 만든 직후 오타·정보 보강(다수) · 확정자 발생 후 긴급 일시·장소 변경(소수, 통지 의무) · 인원 미달 취소(드묾).

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. web_partner는 데스크톱 우선 (web_foundation_responsive surface priority) — Desktop(≥1280) blueprint가 1차 산출물.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 콘솔 셸(1440px 캡 · 사이드바 240px 고정)은 web_partner_home이 SSOT. 폼 본문은 메인 영역 안에서 max-width 720px 좌측 정렬 — 긴 줄 길이로 입력 폼이 늘어지지 않게.

Sub-anatomy ① — 사이드바 (콘솔 셸)

이 spec에서 재정의하지 않음. 콘솔 셸의 blueprint · spacing · 토큰 SSOT는 web_partner_home Sub-anatomy ①. 이 화면에서 다른 점은 단 하나 — active 메뉴가 "홈"이 아닌 "파티·이벤트"이고, 신청 관리 badge 등 나머지 동작은 셸 공통 규칙을 따른다.

Sub-anatomy ③ — 폼 필드 카드 (FormFieldCard)

다크 모드 surface/필드 배경이 다크 토큰으로 전환, partner primary는 color-partner-dark-primary (#9b7bec)로 매핑. error·warning 톤은 다크 변형 유지.

Motion & timing

duration은 MDS motion 토큰 — 웹 구현은 CSS transition-duration / Tailwind로 같은 ms 값을 소비.

Transition Duration (token) Curve / notes

Global edge cases

  • 네트워크 끊김 — 저장/취소 실행 중 끊기면 실패 안내 + 입력값 유지 (재시도 가능). 수정 진입 로드 실패는 폼 자리에 "다시 시도" 안내 (셸은 유지).
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 필드/배너/위험 구역의 tint 들은 모두 토큰 기반 (primary/error의 % 혼합)이라 색만 전환되고 구조 동일.
  • 접근성 — tab 순서: 사이드바 → 뒤로 링크 → 폼 필드 순서대로 → 저장 → 위험 구역. 모든 필드에 라벨 연결, 에러는 필드와 함께 읽히게. 다이얼로그는 포커스 트랩 + Esc 닫기, 열릴 때 타이틀로 포커스 이동. 빨강 실행 버튼은 체크박스와 disabled 상태가 보조기기에도 전달되게.
  • reduced motion — prefers-reduced-motion 시 다이얼로그 진입 모션·hover transition 0ms. spinner는 유지 (진행 표시는 정보).
  • SEO / 공유 — 비공개 콘솔 화면. noindex — og 메타 불필요.
  • 동시 수정 충돌 — 두 세션이 같은 이벤트를 수정하면 늦게 저장한 쪽에 실패 안내 + 새로고침 권장 (확정자 수 검증 포함 서버가 단일 진실 — Behavior Source 상속).
  • 초광폭 (≥1920px) — 콘솔 셸 1440px 캡 중앙 정렬 (셸 공통). 폼은 그 안에서도 720px 캡.
