Purpose 내 구매를 확인하고 환불을 요청하는 화면. 좌측 목록에서 구매 건을 고르면 우측 패널에 이벤트 정보 · 신청 상태 타임라인 · 결제 내역 · 환불 정책 적용 상태가 한 번에 보인다. 환불이 가능한 기간이면 패널에서 바로 환불을 요청하고, 불가능하면 그 이유가 같은 자리에 보인다. 파트너 거절 등 자동 환불은 별도 액션 없이 상태로만 표시된다.
User journey Entry points: 헤더 아바타 → 마이 영역 → 구매 내역 · 결제 완료 직후 redirect · 알림/메일의 "환불 처리" 링크 → URL 직접 진입 (선택 건이 URL 에 있으면 해당 상세가 곧장 열림).
Exit points: ① 상세 패널의 이벤트 정보 클릭 → 이벤트 상세 (/events/:id) · ② 로고 클릭 → 홈 (/) · ③ 비로그인 진입 → 로그인 화면 (완료 후 이 화면 복귀).
Background web-mvp pivot — "이벤트 탐색 → 상세 → 구매·신청" 퍼널의 사후 관리 화면. 환불 정책은 법적 필수 코어 (전자상거래법 청약철회 — refund-policy-v2 PRD)라 웹 MVP 에 포함. 모바일의 목록 → 상세 → 심사 상태 3-뎁스를 데스크톱 폭(1280)을 활용해 master-detail 1-화면으로 압축 — 목록을 떠나지 않고 건별 상태·환불 가능 여부를 비교 확인할 수 있다. QR/체크인 계열은 2차 축소로 deprecated — 입장은 현장 명단 확인이므로 안내 문구만 남긴다. 1280px 데스크톱을 주 캔버스로 설계 (모바일 variant 는 후속 pass).
Frequency 결제 직후 1회 + 환불 결심 시 — 분기당 0-2회. 빈도는 낮지만 돈이 걸린 액션(환불)이 일어나는 곳.

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. 이 화면은 Desktop (≥1280) variant 가 주 blueprint — breakpoint variants 표 참조.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 이 화면은 Desktop-first 예외 화면 — 1280 baseline 으로 먼저 설계하고 Mobile blueprint 는 후속 pass 에서 추가한다 (History 참조).

Variant Breakpoint 이 화면에서의 차이
Desktop (주 variant) ≥ 1280px 헤더(web_user_home 와 동일) + 페이지 타이틀 + master-detail 2-컬럼 — 좌측 구매 목록 (12col 중 4col) · 우측 상세 패널 (8col) · 컨테이너 1200px 캡 중앙 정렬 · gutter 32px — 아래 blueprint 가 이 variant.
Tablet 768–1279px 별도 blueprint 없음 — Desktop 레이아웃 축소: 목록 컬럼 폭 고정(≈320px) + 상세 패널이 잔여 폭 fluid · gap spacing-medium (16px).
Mobile < 768px 후속 pass 에서 작성 (TBD) — 목록 → 상세 2-step 전환 (master-detail 해체) 예상. 이번 pass 는 1280 baseline 만.

🔄

Global Behavior

화면 전반 cross-cutting 동작. 모바일 spec (목록 · 상세 · 심사 상태)에서 상속한 behavior 는 그 spec 이 SSOT — 여기엔 웹에서 달라지는 점만 추가.

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
브라우저 back / forward 선택 건 변경이 URL 에 반영되므로 back 으로 직전에 보던 건의 상세로 복귀. 다이얼로그 열림은 history entry 아님 — 열린 채 back 하면 페이지가 이동 (닫기는 돌아가기·바깥 클릭·ESC).
새로고침 / URL 직접 진입 URL 의 선택 건으로 동일 상세 복원 — 알림/메일 링크 착지에 사용. 선택 건이 없거나 내 구매가 아니면 최신 건 자동 선택. 서버 렌더로 Default(또는 Empty)가 곧장 표시.
비로그인 접근 로그인 화면으로 유도 — 완료 후 이 화면(같은 URL)으로 복귀. web_user_home 과 달리 public 열람 없음 (개인 결제 정보).
환불 접수/처리로 상태 변경 확정 직후 상세·목록 칩이 즉시 갱신 (화면 이동 없음). 표시 상태는 항상 진입/액션 시점 기준 — 시간 경과·파트너 처리에 의한 변경은 새로고침 시 반영 (자동 폴링 없음).
hover (fine pointer) 목록 item: 배경 미세 강조 + cursor: pointer · 버튼: 배경 강조 — motion-fast (200ms). 비활성 버튼은 not-allowed 커서 + hover 무변화. coarse pointer 는 press 피드백 (motion-micro (100ms)) — foundation 포인터 규칙.
브라우저 탭 비활성 → 복귀 자동 재요청 없음 — 보던 상태 유지. 단, 환불 확정 액션 시점엔 서버가 항상 재판정하므로 stale 화면이어도 잘못된 환불은 발생하지 않음.

Motion & timing

duration 은 MDS motion 토큰 (micro 100 / fast 200 / medium 350 / slow 500) — 웹 구현은 CSS transition-duration / Tailwind duration-N 으로 같은 ms 소비. prefers-reduced-motion 대응은 Global edge cases 참조.

Transition Duration (token) Curve / notes
첫 화면 진입 (서버 렌더) 없음 (0ms) SSR 즉시 표시 — 진입 모션 없음
목록 선택 → 상세 패널 교체 fast (200ms) 패널 내용 crossfade — 패널 프레임은 고정 (점프 없음)
다이얼로그 열림/닫힘 medium (350ms) scrim fade + 모달 fade·미세 scale-in
환불 접수 → 칩/카드 갱신 fast (200ms) 칩 색/라벨 + 환불 카드 내용 crossfade
item/버튼 hover · press fast (200ms) / micro (100ms) 배경색 전환 / press 즉각 피드백
진행 중 step pulse (타임라인) (unscoped) 1.4s loop attention loop — 모바일 심사 상태 spec 의 1.4s pulse 상속

Global edge cases

  • 네트워크 끊김 — 첫 로드 실패는 Error 패턴 (그리드 영역 중앙 안내 + "다시 시도"). 환불 접수 실패는 다이얼로그 안 인라인 에러 (State 5 참조).
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 배경/표면/텍스트/divider 토큰 전환 · 상태 칩의 의미색(성공/경고/에러/info) tint 는 모드 무관 유지 · 선택 item 의 primary 강조 유지.
  • 접근성 — 키보드 tab 순서: 헤더 → 목록 item (위→아래) → 상세 패널 내 인터랙티브 요소 순. 목록에서 ↑↓ 로 선택 이동 검토 (구현 시 확정). 다이얼로그 열리면 포커스가 모달 안에 갇히고 닫히면 트리거 버튼으로 복귀. 상태 칩은 색에만 의존하지 않음 — 라벨 텍스트가 항상 함께.
  • reduced motion — prefers-reduced-motion 시 타임라인 pulse 정지(정적 표시) · 패널 crossfade·모달 전환 0ms.
  • SEO / 공유 — 보호 화면이라 검색 노출 없음 (noindex). URL 공유 시 본인 외에는 로그인 → 본인 구매 기준으로 fallback.
  • 초광폭 (≥1920px) — 1200px 캡 유지, 잉여 폭은 배경 (foundation 규칙).
