Event Checked In

Overview

Status 🚧 디자인중 — 4 state · routed bottom sheet · kit-shared 예정 (현재 구현은 EventNowBottomSheet의 phase 2 콘텐츠 CheckedInContent로 inline)
App app_user (widget은 minglit_kit 패키지로 이전 예정 — kit-shared)
Category event · check-in confirmation · modal sheet
Route / Surface EventCheckedInRoute (ModalBottomSheetRoute · GoRouter pageBuilder) · widget: EventCheckedInScreen (kit-shared) — 현재는 라우트 미등록 · phase 분기로 동일 시트 내부에서 inline swap
Path /events/:id/checked-in
Hierarchy Parent: HomePage (HomeRoute) — 시트가 push 되어도 parent route 그대로 유지. 진입은 EventNowBar의 checkedIn 탭, 또는 EventCheckInScreen 성공 transition.
Children: — (매칭 시작 시 EventMatchingScreen으로 자동 전환 — 별도 spec 예정)
Purpose 체크인이 정상 완료됐다는 시각 confirmation을 주고, 같은 이벤트에 도착한 다른 참석자 수와 아바타로 "곧 함께할 사람들이 모이고 있다"는 사회적 신호를 노출. 매칭 시작 직전의 짧은 lobby 역할.
User journey Entry points: ① EventCheckInScreen에서 QR 스캔 성공 → 백엔드 phase가 checkedIn으로 변경 → 이 시트로 자동 transition. ② EventNowBar가 checkedIn state일 때 직접 탭. ③ push 알림 "체크인이 확인되었습니다" deeplink.
Exit points: ① 백엔드 phase가 matching으로 전환 → EventMatchingScreen으로 자동 transition. ② scrim / 핸들 swipe-down → dismiss (parent HomeRoute 유지 · EventNowBar는 checkedIn state로 노출 지속).
Background 체크인 직후 사용자 심리 — "내가 잘 등록된 게 맞나?" 불안 + "다른 사람들도 왔나?" 호기심을 동시에 해소해야 한다. 그래서 이 화면은 ① 큰 success 체크 (시각 즉시성) ② 참석자 수 (밀도 신호) ③ 곧 매칭 시작 안내 (다음 단계 예고)의 3단 구조. 별도 라우트로 둔 이유는 EventCheckInScreen과 분리해 deeplink / push 알림 / EventNowBar 직접 탭 등 여러 entry로 진입 가능하게 하기 위함.
Frequency 이벤트당 사용자 1회. 체크인 ~ 매칭 시작 사이의 짧은 대기 윈도우 (보통 1~5분 내외).

Global Behavior

cross-cutting — 모든 state에 공통 적용. modal sheet dismiss · phase stream · 참석자 count stream.

Cross-cutting interactions

Interaction Behavior
Sheet dismiss (swipe-down) 핸들 영역 또는 시트 본문을 아래로 드래그 → 임계값 초과 시 dismiss. parent HomeRoute 유지 — back stack pop 1회. EventNowBar는 그대로 노출 (checkedIn state).
Sheet dismiss (scrim 탭) 시트 외부(scrim) 탭 → 동일하게 dismiss. Material default barrier behavior.
Sheet dismiss (system back) 안드로이드 back 버튼 / iOS swipe-from-edge → dismiss. parent route로.
Phase stream 자동 갱신 eventNowBarStateProvider(activeEvent) Riverpod stream을 ref.watch — 백엔드 phase 변경 시 즉시 reflect. matching으로 전환되면 시트 콘텐츠가 transient view로 swap → 350ms 후 EventMatchingScreen push.
Participant count 갱신 activeEvent.event.currentParticipants — Realtime channel 또는 polling으로 갱신. count 변경 시 텍스트와 아바타 row 즉시 재렌더링 (state mini-rebuild). 변경 시 별도 transition animation 없음 — 정수 swap.
다크 모드 토글 sheet bg → color-dark-background. success / primary 등 brand 색상은 dark 변형 자동 적용. scrim 동일.

Global edge cases

  • Deeplink 진입 — push 알림 / share URL로 직접 /events/:id/checked-in 진입 시 parent stack에 HomeRoute가 없을 수 있다. dismiss 시 context.go('/')로 fallback (라우트 가드 필요).
  • Phase mismatch (체크인 미완료 상태로 진입) — phase가 waiting / checkInReady면 이 시트는 의미 없다. 라우트 가드에서 phase 체크 후 EventCheckInScreen으로 redirect 권장.
  • 참석자 수 0 / 1명 — "참석자 1 / 30명" + 내 아바타만 1개. "곧 매칭이 시작될 거예요"가 약간 과장이 될 수 있어 향후 카피 보강 후보 ("다른 분들이 도착하면 매칭이 시작됩니다" 등).
  • Offline — phase stream을 받을 수 없으면 마지막 캐시된 phase 사용. 사용자가 체크인한 직후 비행기 모드 등 → checkedIn 화면 유지되며 매칭으로 자동 전환은 실패. 재연결 시 stream 회복.
  • 매칭이 끝내 시작되지 않음 — 운영 사고 / 인원 미달. 별도 핸들링 미정 — 추후 운영자 push로 EndedScreen으로 강제 전환 또는 "매칭이 지연되고 있습니다" 안내 추가 검토.
  • 다중 활성 이벤트 — bar는 1건만 노출하므로 진입도 1건. 다른 체크인된 이벤트는 향후 별도 진입점 (MyTickets 등) 필요.
