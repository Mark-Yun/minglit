Purpose 탈퇴 wizard의 첫 단계 — 사용자가 떠나는 이유를 선택하게 한다 (선택 자체는 옵셔널). 제품 개선 시그널 수집과 동시에 "잠시 멈추고 한 번 더 생각해보는" 마찰을 의도적으로 만들어준다.
User journey Entry points: PrivacyPage "회원 탈퇴" 항목 탭 → coordinator.start() → push.
Exit points: ① "선택하지 않고 계속하기" 탭 → DeletionInfoPage(reason=null) push · ② 사유 선택 + "다음" 탭 → DeletionInfoPage(reason=선택한 WithdrawalReason) push · ③ 뒤로 가기 → PrivacyPage 복귀.
Background 개인정보 삭제 정책 컴플라이언스 요건상 탈퇴 사유 수집은 강제 아님 — "선택하지 않고 계속하기" CTA를 동등한 무게로 배치한 이유. 6개 사유는 product-led 분류(usage / events / competitor / privacy / usability / other) — Phase 2 retention 분석에 사용된다. "직접 입력할게요"는 200자 제한 · 옵셔널 — "다음" 활성화는 사유 선택만 검사, detail 입력은 요구 안 함.
Frequency매우 낮음 — 계정당 ≤ 1회 (탈퇴 wizard 진입 시).

States

4 state — baseline = 미선택(둘러보기). 일반 사유 선택 · "직접 입력할게요" 선택(textfield 노출) · 데이터 fetch 없음 → loading/error mini-table 없음. coordinator는 동일한 pushInfo()를 두 가지 방식으로 호출 (with reason / without).

State 종류 식별 기준: ① _selectedCode == null ↔ "다음" 비활성 / "선택하지 않고 계속하기"만 활성 (baseline) · ② _selectedCode != null && != other ↔ "다음" 활성 · textfield 미노출 · ③ _selectedCode == other ↔ MinglitTextField 노출 · "다음" 활성(detail 비어도 enable) · ④ "다음" disabled (Default 시점에 자동 — 별도 mini-table로 분리하지 않음, ① 행에 통합). Stateful이지만 widget 자체는 fetch 안 함 → Loading/Error 없음.

Global edge cases

  • Loading / Error mini-table 없음 — 위젯 자체가 fetch하지 않음. 6개 사유는 컴파일타임 const list.
  • 다크 모드 — Scaffold/Card/text 모두 color-dark-* 토큰으로 swap. primary는 동일 brand purple 유지.
  • 접근성 — RadioListTile은 Material default semantics(role=radio, group). screen reader가 6개 옵션을 일관되게 announce.
  • 2번 탭(double tap) — onChanged는 같은 value로 호출되어도 visual 변화 없음. _selectedCode 동일하면 setState는 redundant rebuild만.
  • 화면 회전 — ListView/Card layout이 width-aware라 자연 대응. 텍스트필드 maxLines 4 유지.
