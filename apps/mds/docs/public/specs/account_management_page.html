Account Management Page

Overview

Status 디자인완료 — 6 state · kit-shared (user + partner)
App app_user + app_partner — kit-shared. 동일 위젯이지만 분기 props가 있다: onPartnerProfile(partner 전용) · onCertification + isVerified(user 전용). null이면 해당 타일이 숨겨진다.
Category settings · auth · destructive · sub-page
Route / Surface user — AccountManagementRoute
partner — PartnerAccountManagementRoute
widget: AccountManagementPage (shared/packages/minglit_kit)
Path user — /my/account · partner — /more/account
Hierarchy Parent: user — MyPage "계정 관리" 타일 · partner — MorePage "계정 관리" 타일
Children: 로그아웃 confirm은 MinglitAlert(in-place dialog) · 회원 탈퇴는 외부 coordinator (accountDeletionCoordinator · partner는 moreCoordinator.pushAccountDeletion)로 넘긴다 · 본인인증은 CertificationRoute push (별도 spec).
Purpose 신원/계정에 귀속된 액션(본인인증 · 파트너 프로필 · 로그아웃 · 회원 탈퇴)을 한 곳에 모아놓은 서브-설정 페이지. Fix #1213로 MyPage / MorePage에서 흩어져 있던 destructive 액션을 통합.
User journey Entry points: MyPage(user) / MorePage(partner)에서 "계정 관리" 타일 탭.
Exit points: ① 로그아웃 confirm → GoRouter.of(context).go('/') (LoginRoute) · 직후 signOut · ② 회원 탈퇴 → 외부 coordinator(별도 wizard) · ③ 본인인증 → CertificationRoute push · ④ 파트너 프로필(partner) → 현재 SnackBar "준비 중입니다." (Phase 2 빌드 예정) · ⑤ 뒤로 가기 → 부모 페이지 복귀.
Background 신원(identity)과 자격(qualification)을 2-layer로 분리하는 trust 모델 상, 본인인증은 "계정에 귀속된 신원 속성"이라 이 페이지로 모았다 (Fix #1861). 로그아웃은 즉시 실행 시 사고가 잦아 confirm dialog로 한 단계 분리(Fix #1378). 탈퇴는 기존 wizard를 그대로 재사용(개인정보 삭제 정책 컴플라이언스).
Frequency 매우 낮음 — 계정 정리/이탈 시점에 단발적 진입. 본인인증 1회 · 탈퇴 1회 · 로그아웃 세션당 0~1회.

Tile sub-anatomy

모든 타일은 plain Material ListTile. 두 가지 변주만 존재 — 본인인증은 isVerified로 leading icon / subtitle text / color가 토글되고, 회원 탈퇴는 leading + title 모두 error color로 강조. 그 외 ripple / hit target / 높이는 모두 ListTile default.

States

6 state. baseline = User context · 본인인증 미완(isVerified=false). 분기 props로 user/partner 모드가 갈라지므로 두 모드를 모두 mini-table로 다룬다. loading / error / permissions warning 별도 상태 없음 — controller가 이 페이지에서 아무것도 fetch하지 않는다(StatelessWidget · 부모가 isVerified를 read해 prop으로 주입).

State 종류 식별 기준: ① 부모가 user인지 partner인지(onPartnerProfile · onCertification 두 prop 조합) · ② isVerified · ③ confirm dialog open / 부모 SnackBar 표시. 이 위젯 자체는 fetch하지 않으므로 Loading / Error mini-table은 없다 (Cardinal rules의 "Likely states"에서 의도적으로 제외).

User · 본인인증 미완 🎯 baseline · onCertification 노출 + isVerified=false

Global edge cases

  • Loading / error mini-table 없음 — 이 위젯 자체는 Stateless이고 fetch가 없다. isVerified를 가져오는 currentUserProfileProvider는 부모 Consumer에서 watch하며, AsyncLoading/AsyncError이면 asData?.value?.isVerified ?? false로 unverified fallback. 즉 인증 상태가 미확정인 동안에도 페이지는 즉시 렌더링.
  • Permissions warning 없음 — 진입 시점에 권한/role 검사 없음. AccountManagementRoute는 protected route guard로 보호되므로 비로그인 시 LoginRoute로 redirect (이 위젯 안에선 발생 X).
  • 회원 탈퇴 confirm 위임 — 회원 탈퇴는 이 위젯 내에서 즉시 onDeleteAccount() 호출. confirm dialog는 외부 wizard(accountDeletionCoordinator.start())에 위임 — destructive 액션 위치를 분리해 다단계 확인 가능.
  • 로그아웃 dialog의 confirm 색 — showConfirm 호출이 isDestructive: false default라 confirm 버튼이 primary purple. 로그아웃이 "절대 되돌릴 수 없는 행위"는 아니므로 의도된 톤.
  • signOut 비동기 race — onLogout이 go('/')를 먼저 호출 후 Future.delayed(Duration.zero) 안에서 signOut을 실행 (Fix #404). LoginRoute가 짧게 인증된 token으로 보이는 race가 있을 수 있으나 다음 protected push에서 redirect로 보정.
  • kit-shared 분기 props — onPartnerProfile(partner) · onCertification + isVerified(user). null이면 spread 결과가 비어 ListView children에서 통째로 빠짐 — conditional rendering. partner는 본인인증 타일을 절대 보지 않고, user는 파트너 프로필 타일을 절대 보지 않는다.
  • partner primary 색 차이 — partnerTheme의 primary는 다른 보라. dialog confirm 버튼 color에만 영향 (이 페이지 본문은 primary 미사용).
