Overview

Status ✅ 디자인완료 — 4 PageView 페이지 + logout 변형
App app_partner
Category onboarding · entry · partner-only
Route / Surface PartnerWelcomeRoute · widget: PartnerWelcomePage (ConsumerStatefulWidget · PageView · DotIndicator)
Path /welcome
Hierarchy Parent: — (top-level screen, no shell — outside StatefulShellRoute)
Children: — (내부 PageView 4페이지는 같은 위젯의 sub-state, 별도 spec 없음)
Purpose 파트너 신청 전 사용자에게 밍글릿 파트너 서비스를 4페이지 carousel로 소개하고 신청 마법사(PartnerApplyRoute) 진입점을 제공한다. 로그인은 끝났지만 아직 신청서가 없는 사용자(OnboardingState.needsApplication)만 도달.
User journey Entry: 로그인 직후 또는 보호된 화면 직접 진입 시 router redirect. onboardingStateProvider가 needsApplication으로 resolve되면 모든 경로에서 /welcome으로 강제 이동.
Exit: 하단 "파트너 신청서 작성하기" CTA → PartnerApplyRoute (/apply) · AppBar 우측 ⋮ → 로그아웃 (/login).
Background 신청 플로우는 4단계(기본·사업자·연락처/정산·서류)로 양이 많아 신청서 진입 직전에 가치 제안과 절차를 미리 보여주는 단계가 필요했다. OnboardingState enum의 6 상태 중 이 화면에 도달하는 유일한 상태가 needsApplication — 즉 onboarding 게이트.
Frequency 신청 시작 전까지 진입할 때마다. draft 생성 후엔 router가 자동으로 /apply로 우회 — 일반적으로 1회성.

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
"파트너 신청서 작성하기" CTA 탭 onboardingCoordinator.goToApply() → router.go('/apply') · GoRouter 기본 transition. 한 번 도달하면 application draft가 생성되어 다음부터 router redirect는 /welcome 대신 /apply로 우회.
좌우 swipe (페이지 carousel) PageController + ClampingScrollPhysics (양쪽 끝에서 bounce 없이 hard stop). DotIndicator는 onPageChanged에서 setState로 동기화되며 AnimatedContainer(MinglitAnimation.medium)로 크기/색 transition.
AppBar ⋮ 탭 → 로그아웃 PopupMenu open → "로그아웃" 선택 → MinglitAlert.showConfirm → 확인 시 signOut() → auth provider invalidate → router redirect /login.
시스템 back / 스와이프 back showBackButton: false이며 router redirect로 도달했기 때문에 stack에 이전 항목이 없을 가능성이 큼 — Android에서 종료 / iOS에서 무반응. 위로 갈 곳이 없음.
onboarding state 변경 (외부 트리거) 다른 디바이스에서 application 생성 → onboardingStateProvider가 draftInProgress로 갱신 → router refreshListenable이 트리거 → "If on welcome page but no longer needsApplication" 분기로 /apply로 자동 이동.
다크모드 토글 scaffold gray ↔ dark surface · partner-primary 라이트(#6c3ce1) ↔ 다크(#9b7bec) swap. 모든 토큰은 자동 매핑.

Global edge cases

  • 이미 application이 있는 사용자가 /welcome 직접 진입 — router redirect의 "If on welcome page but no longer needsApplication" 분기가 발동, draftInProgress면 /apply로, 그 외엔 /(home)로 자동 이동. 화면이 잠깐도 안 보임.
  • 로그아웃 직후 /welcome URL 직접 진입 — !isLoggedIn 분기로 즉시 /login으로 redirect.
  • onboardingState가 loading 중일 때 진입 — ref.read(onboardingStateProvider).hasValue가 false면 redirect 분기를 통과 못 해 그대로 /welcome 머무름. provider가 resolve되면 refreshListenable이 router를 재평가, 필요 시 우회. 사용자에겐 짧은 깜빡임.
  • signOut 실패 — authRepo.signOut()은 fire-and-forget(unawaited). 실패해도 화면에 별도 에러 표시 없음. auth state 무변화 → 사용자가 ⋮ → 로그아웃 다시 시도 가능. 의도된 동작.
