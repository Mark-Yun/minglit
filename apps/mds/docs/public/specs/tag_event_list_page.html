Overview

Status 🚧 디자인중 — 4 states · paginated vertical list (infinite scroll · 10/page). HomePage 태그 chip 탭 진입.
Appapp_user
Categorytag · events list
Route / Surface TagEventListRoute · widget: TagEventListPage
Path/tags/:tagId
Hierarchy Parent: HomePage (TrendingTagSection / FeaturedTagChipBar 태그 chip 탭으로 진입 — tagCoordinator.goToTagEventList(id, name))
Children: MinglitEventCard (vertical cell · onTap → eventCoordinator.goToEventDetail · 4 visible state — 별도 spec)
Purpose 한 태그(예: #와인, #스피드데이팅)에 묶인 이벤트들을 시간순으로 한 화면에 펼쳐 보여준다. HomePage의 태그 chip은 발견·키워드 잡기 용도, 이 화면은 "이 키워드로 묶인 이벤트 N개를 천천히 둘러보기" — 태그 기반 탐색의 종착지.
User journey Entry points: HomePage 의 TrendingTagSection 태그 카드 탭 / FeaturedTagChipBar chip 탭 — 둘 다 tagCoordinator.goToTagEventList(tag.id, tag.name). 딥링크 /tags/:tagId도 가능 (단 tagName이 path/query에 없어 AppBar title이 빈 "#"로 노출될 수 있음 — uncertain).
Exit points: 카드 탭 → eventCoordinator.goToEventDetail(event.id) → EventDetailRoute · 뒤로 가기 → HomePage 복귀 · Empty state CTA "홈으로 돌아가기" → HomeRoute (Fix #1136 — pop이 아니라 명시적 go).
Background 태그 chip은 HomePage에서 노출되는 가벼운 affordance지만, 그 뒤에 어떤 이벤트들이 묶여 있는지를 풀어줄 화면이 필요했다. TagEventListController는 10개씩 페이지로 가져오고(_pageSize = 10), 스크롤이 maxScrollExtent − 200px에 도달하면 자동 loadMore() — pull-to-refresh 미장착. loadMore 실패 시 controller가 throw하지 않고 isLoadingMore: false로 silent 복구 (Fix #1149 — 글로벌 async error 폭주 방지).
Frequency관심 키워드에 대해 세션당 0~1회 — HomePage에서 chip을 발견하고 호기심에 진입하는 탐색 단계.

4 states (Default · Empty · Loading · Error). 모두 동일 Scaffold + AppBar — body만 분기. Default가 baseline; 나머지는 additive diff (+ · − · ↔ · 동일 · —). 카드 자체의 4 visible state(normal · today · soldOut · ended) 변형은 MinglitEventCard child spec 참고.

Global edge cases

  • tagName이 빈 문자열 — AppBar title이 그냥 "#"로 노출됨. HomePage 정상 진입 경로에선 사실상 발생 안 함 (tag.name 보장) · 딥링크 / 외부 링크에선 발생 가능 — sanitize 미구현.
  • provider autoDispose — @riverpod default라 화면 떠나면 캐시 폐기. 재진입마다 Loading을 거치며 첫 페이지 다시 받음. PartnerEventsPage(5분 keepAlive)와 다름 — 태그 목록은 짧은 탐색 단계라 캐시 정책이 가벼움.
  • loadMore silent failure — state = AsyncData(current.copyWith(isLoadingMore: false))로 복구 (Fix #1149) → 사용자에겐 spinner가 슬그머니 사라지고 추가 카드가 안 붙는 상황으로 보임. 별도 toast / snackbar 없음.
  • scroll listener leak 방지 — dispose()에서 _scrollController.removeListener(_onScroll) + dispose 호출 (page lifecycle 관행).
  • 접근성 — AppBar BackButton은 Material 기본 a11y. 카드 자체 Semantics는 child spec 참고 (Fix #996, #1558 — 만석/종료 announce 포함). pagination spinner는 별도 a11y 안내 없음.
  • large list memory — pagination이 있어 한 번에 10개씩만 — partner_events_page의 "전부 받아 ListView.builder" 보다 메모리 안전. 다만 N이 매우 커지면 누적 events 길이가 무한정 증가 (페이지 누적 폐기 정책 없음).
