Purpose 파트너가 앱에 진입했을 때 가장 시급한 액션(승인 대기 신청, 임박/진행 중 이벤트, 첫 파티 만들기)으로 한눈에 도달할 수 있게 하는 단일 대시보드. 파트너 lifecycle의 모든 단계 (onboarding · 운영 중 · 이벤트 종료 직후)를 같은 화면에서 phase-별 UI로 분기한다.
User journey Entry points: 앱 cold start (로그인 후 → 홈 redirect) / 다른 탭에서 홈 탭 재선택 / 푸시 알림 → 홈.
Exit points: 알림 센터(우측 상단), 장소 가이드 배너, EventActionCard CTA(신청관리/체크인/이벤트 생성), TodoSummaryChips(승인 대기 → 신청관리 탭), Onboarding CTA(파티/이벤트 생성), 하단 NavigationBar(신청관리/체크인/정산/더보기).
Background 파트너 사용자는 1) 처음 가입 직후(이벤트 0개) 또는 2) 운영 중(이벤트 ≥1)이라는 두 가지 상태를 가진다. 홈은 state.hasAnyEvents로 그 둘을 구분해 완전히 다른 UI를 그린다. 운영 중인 파트너에겐 가장 임박한 이벤트 1개를 EventActionCard로 강조하고, phase(recruiting / preparing / live / ended within 24h)에 따라 메인 CTA가 달라진다.
Frequency 로그인 세션마다 진입. 운영 중인 이벤트가 있을 땐 하루 수회. 진행 중 이벤트(LIVE) 동안엔 새로고침 빈번.

Global Behavior

cross-cutting — 모든 state에 적용되는 액션, motion, 글로벌 에지케이스. 각 state 한정 액션은 위 mini-table 참고.

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
아래로 당기기 (pull-to-refresh) RefreshIndicator → partnerDashboardController.loadDashboardData() 재호출. 갱신 완료 시 자동으로 data 반영. (단, Loading state에선 RefreshIndicator 자체 미렌더 — MinglitAsyncValueWidget loading branch이므로)
알림 아이콘 탭 NotificationCenterRoute 외부 push (shell 밖 — bottom nav 사라짐). 미읽음 카운트는 notificationListProvider에서 계산 (is_read=false). 99 초과 시 "99+".

Global edge cases

  • partner null — currentPartnerInfoProvider가 아직 로드 중이면 greeting 이름 자리 "파트너" placeholder. 다른 컴포넌트는 영향 없음.
  • state.activeParties.length — 0이면 onboarding 내 "첫 파티" CTA · 1이면 EventCreate 직접 push · 2+면 _PartySelectionSheet bottom sheet 노출 후 선택.
  • WeeklyStatsRow 데이터 부재 — 현재 totalRevenue / checkinRate는 placeholder (실 API 미연결). null 들어오면 ₩0 / 0% 표시(Fix #1611). totalApplications만 pendingReviewCount 재사용.
  • upcoming chip 카운트 — upcomingEvents.length(7일 이내 시작 예정) 사용. recruiting/preparing/live phase 모두 포함 — ended는 미포함.
  • SETTLEMENT_VIEW 권한 미보유 — 하단 nav에서 정산 탭 미노출. 직접 URL 진입 시 redirect/에러는 라우팅 상위에서 처리.
