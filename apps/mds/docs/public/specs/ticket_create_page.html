Ticket Create

Overview

Status ✅ 디자인완료 — 5 state (loading + form 4 variants) · single tab · single submit
App app_partner
Category party · event · ticket · create
Route / Surface TicketCreateRoute · widget: TicketCreatePage wraps TicketForm (재사용 atom — Edit 화면도 같은 form)
Path /more/parties/:partyId/events/:eventId/tickets/create
Hierarchy Parent: EventDetailPage (티켓 섹션의 "+ 티켓 추가" CTA에서 진입)
Children: — (편집 변형은 sibling spec TicketEditPage가 같은 TicketForm 재사용 — 별도 spec 없음. 입장 그룹은 부모 파티 단위라 이 화면에선 read-only 선택.)
Purpose 파트너가 특정 회차(event)에 판매할 티켓을 만든다. 이름·가격·발행 수량을 정한 뒤 파티에 정의된 입장 그룹 중 어느 그룹이 이 티켓을 살 수 있는지 다중 선택해 저장한다. 이벤트 단위로 묶이며 한 회차에 N개 티켓을 발행할 수 있다.
User journey Entry points: EventDetailPage 티켓 섹션 → "티켓 추가" CTA — partyId+eventId 전달.
Exit points: 생성 성공 → context.pop() + showMinglitSuccess("티켓이 생성되었습니다.") + ticketsByEventProvider(eventId) invalidate → EventDetailPage 복귀. 실패 → handleMinglitError 스낵바 (page 유지). back 탭 → confirm 없이 즉시 pop.
Background 밍글릿은 같은 회차 안에서도 가격대·인원 풀이 다른 티켓을 여러 종 운영한다 (얼리버드/일반, 남성/여성, VIP 등). 입장 그룹은 부모 파티에서 미리 정의된 인구학적/인증 슬롯이며, 티켓은 그 슬롯에 1:N으로 연결된다. 그래서 이 화면은 "그룹 정의" UI가 없고 — 이미 만들어진 그룹 중 선택만 한다. 그룹이 0개면 명시적 안내(empty 카드)와 함께 진행 자체를 막아 데이터 무결성을 지킨다.
Frequency 회차당 1~5회. 정기 파티의 매주 회차마다 동일한 티켓을 새로 만들 가능성이 높음 — copy/template 기능은 현재 화면에 없음 (drift 후보).

5) 실패 → handleMinglitError 스낵바
back 버튼 confirm 다이얼로그 없이 즉시 pop. 변경사항은 휘발 (form state는 widget dispose 시 사라짐).
provider invalidate eventId 비었으면 template provider, 있으면 event-scope tickets provider. EventDetailPage 복귀 직후 새 티켓이 자동 표시되도록 보장.

Global edge cases

  • partyId가 잘못된 값 — ticketEntryGroupsProvider future가 throw → MinglitAsyncValueWidget이 표준 에러 UI 렌더 (form 자체가 안 그려짐). page는 유지되며 사용자는 back으로만 빠져나옴.
  • 제출 중 back 누름 — 별도 가드 없음. createTicket future는 백그라운드에서 계속 진행. if (context.mounted) 가드로 pop/snackbar는 차단 — 그러나 이미 만들어진 티켓은 server-side에 남는다.
  • 이중 제출 방지 미흡 — TicketCreatePage가 ticketController.state.isLoading을 TicketForm.isLoading prop으로 전달하지 않아 버튼이 자동 disable되지 않음. 사용자가 빠르게 두 번 탭 시 중복 생성 위험 (drift 후보).
  • 그룹 0개 + submit 시 안내 — empty 카드만 표시되고, 탭해도 그룹 추가 화면으로 이동하지 않음. PartyDetailPage 또는 PartyEdit으로 deep link했어야 함 (drift 후보).
  • price 0 허용 — NumberStepperInput min default 0이라 무료 티켓 생성 가능. 정책상 허용 여부 불명 (drift 후보).
  • localization 일관성 — 이름 validator 메시지는 partnerApplication_error_required를 차용 (ticket 전용 키 부재). 다른 ticket_* 키와 prefix 불일치 (drift 후보).
  • 가격 콤마 포맷팅 — NumberStepperInput는 toString만 사용 → 35000으로 표시. KRW 천단위 콤마는 적용되지 않음 (drift 후보).
  • edit-template 변형 — 같은 TicketForm이 TicketEditPage에서도 사용되며 initialTicket이 채워진다. 본 spec은 create only (initialTicket null) — edit 변형은 별도 spec 또는 sibling 화면 참고.
