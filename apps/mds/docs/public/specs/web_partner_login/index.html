Purpose 입점 파트너가 콘솔로 들어가는 단 하나의 문. OAuth 로그인만 제공하고, 성공하면 파트너 홈(/dashboard)으로 보낸다. 파트너 입점은 운영자 수동 승인이므로 가입/신청 퍼널이 없다 — 입점 전 방문자에게는 "입점 문의" 안내 링크 하나만 둔다.
User journey Entry points: URL 직접 진입/북마크 · 파트너 랜딩의 "로그인" 진입 · 콘솔 보호 화면에 비로그인으로 접근해 보내진 경우 · 알림 메일 링크 클릭 시 비로그인 상태.
Exit points: 로그인 성공 → 파트너 홈 /dashboard (보호 화면에서 보내졌으면 원래 목적지로 복귀) · 파트너 아닌 계정 → 권한 없음 카드 → 입점 문의(랜딩) 또는 다른 계정으로 재로그인 · "입점 문의" → 파트너 랜딩의 입점 안내.
Background web-mvp pivot으로 파트너 콘솔이 데스크톱 운영 도구로 재구성됐다 (docs/architecture/web-mvp-pivot.md §9). 로그인은 콘솔 진입 전 단계라 사이드바 셸이 없고, 데스크톱에서 풀폭 로그인은 어색하므로 중앙 카드형으로. 입점이 운영자 수동이라 모바일 spec의 "파트너 입점 문의" CTA는 유지하되 가입/신청 링크는 의도적으로 두지 않는다. 같은 minglit 계정 체계를 쓰므로 일반 사용자가 로그인에 성공할 수 있는데, 이때 콘솔로 들여보내지 않고 "파트너 계정이 아니에요"를 이 화면에서 바로 알려준다 (web_partner_home의 "파트너 아닌 계정 접근" 정책과 한 쌍 — 입구 쪽 표현).
Frequency 로그아웃 상태에서만. 세션이 살아 있으면 보이지 않고 통과 — 파트너당 가끔 (첫 진입 · 세션 만료 · 로그아웃 후).

Global edge cases

  • 네트워크 끊김 — OAuth 버튼 클릭 시 핸드오프가 실패하면 로그인 실패 state로 (별도 풀-페이지 에러 없음 — 카드가 곧 에러 표면).
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 캔버스/카드/텍스트 토큰 전환 + primary → color-partner-dark-primary + OAuth 버튼 brand 규칙 교체.
  • 접근성 — tab 순서: Google → Apple → Kakao → 입점 문의 (권한 없음 카드는 입점 문의하기 → 다른 계정으로 로그인). 모든 버튼·링크에 visible focus ring. 버튼 라벨이 그대로 읽혀 의미 전달 ("Google로 시작하기"). 실패 배너는 표시 즉시 보조기기에 알림.
  • reduced motion — prefers-reduced-motion 시 fade/hover transition 0ms. 진행 스피너는 진행 인지를 위해 유지.
  • SEO / 공유 — 로그인 화면은 noindex. 공유 프리뷰 대상 아님 — og 메타 불필요.
  • 초광폭 (≥1920px) — 카드 400px 고정 중앙, 잉여 폭은 surface 배경 (web_foundation_responsive 규칙 — 컨테이너 캡 이전에 카드 자체가 고정 폭).
