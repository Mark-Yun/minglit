Event Matching

Overview

Status 🚧 디자인중 — EventMatchingRoute는 아직 미구현. 현재 동등 콘텐츠는 EventNowBottomSheet의 matching phase에서 MatchingContent(matching_content.dart)로 inline 렌더 — showModalBottomSheet 내부, 라우트 아님. 본 spec은 routed sheet 추출 후의 사양.
App app_user
Category event · routed bottom-sheet · vote
Route / Surface EventMatchingRoute — ModalBottomSheetRoute (Material 3 sheet · top corners radius-card · scrim ~50%) · 신규 추가 예정
Path /events/:id/matching
Hierarchy Parent: HomeRoute via EventNowBar (matchingReady / matching state · bar tap → push)
Children: — (투표 확정은 인라인 showMinglitConfirm 다이얼로그, 별도 route 없음)
Purpose 매칭 phase에서 사용자가 후보 목록을 보고 "선택" 버튼으로 투표를 행사하는 화면. 잔여 투표 수 / 투표 완료 후보 / 양방향 매치 성공 알림을 한 시트에서 모두 다룬다. 후보는 2-col grid로 노출, 카드 오버레이의 "선택" 버튼이 1차 액션. 양방향 매치가 성립한 상대는 상단 banner에 즉시 reveal — 결과가 phase 종료 전에 점진적으로 누적된다.
User journey Entry points: ① EventNowBar 탭 (matchingReady action variant — 가장 흔한 진입). ② 동일 bar의 matching passive variant (사용자 vote 완료 후 진입 — view-only). ③ push 알림 "매칭이 시작됐어요" deeplink.
Exit points: 후보 카드 "선택" → _confirmAndVote 다이얼로그 → 확정 시 SnackBar "투표가 완료되었습니다" + grid에 voted 마스크 표시 (시트 유지). · 모든 vote 소진 또는 phase가 results로 전환되면 시트 자동 dismiss + EventNowBar가 results state로 전환.
Background 매칭 phase는 EventNow 5단계의 클라이맥스 — 사용자 입력이 강하게 요구되는 구간 (bar의 matchingReady가 action variant인 이유). 기존 인라인 MatchingVoteContent는 화면을 가득 채우지만, EventNowBar 진입 흐름과 일관되게 모달 시트로 통일하면 "탭하고 끝, 닫으면 홈"의 UX가 그대로 유지된다. 시트 안에서 다중 vote / 양방향 match reveal / partner contact 노출이 모두 일어나기 때문에 isScrollControlled: true로 max-height 88%를 차지한다.
Frequency 이벤트당 1회 phase — 사용자는 보통 진입 후 N번의 vote를 마치고 닫는다. push 알림 / EventNowBar 재탭으로 재진입 가능 (vote 추가 / 매치 누적 확인).

States

시각 변형 5종. baseline = matchingReady (vote 첫 reveal). voting in progress / voting complete / loading / error로 분기. matching passive(시스템 처리 중)는 voting complete의 변형으로 처리.

State 식별 기준: matchCandidatesProvider(eventId) · myMatchesProvider · myVoteCountProvider · maxVoteCountProvider · myVotedCandidateIdsProvider 5개 AsyncValue 조합. baseline은 후보 data 도착 + voted 0건 + matches 0건. voting in progress = voted 1+건 (allUsed 아님). voting complete = voteCount >= maxVote → bar는 matching passive로 변환. loading = candidates AsyncValue.loading. error = candidates AsyncValue.error 또는 voteMeta error.

Global edge cases

  • Vote 더블탭 / 동시 요청 — controller state가 AsyncLoading인 동안 후보 카드의 disabled 조건은 직접 체크하지 않음. UI 측에서는 이미 voted 카드가 disabled 처리되므로 같은 카드를 다시 탭할 수는 없으나, 다른 카드 더블탭 가능성은 존재 — 서버에서 unique constraint로 가드 (DB match_votes upsert + RLS).
  • 잔여 vote = 0인데 candidate fetch는 OK — 모든 카드 disabled, "선택" 버튼 회색. 사용자 입장에서 read-only 상태. EventNowBar의 phase가 곧 results로 넘어감.
  • Push 알림 deeplink 진입 — parent stack에 HomeRoute가 없으면 dismiss 시 context.go('/')로 fallback (라우트 가드 필요).
  • Offline — candidates / vote-meta 모두 fail → error state. vote action도 fail → SnackBar. 캐시된 candidates가 있으면 read-only로 grid는 노출되나 vote 자체는 불가.
  • 이벤트 phase 미스매치 — 사용자가 deeplink로 진입했는데 backend phase가 이미 results / ended면 candidates fetch는 빈 리스트 또는 error. error state로 노출.
  • Vote 중 partner 차단 — 차단된 partner의 후보는 candidates에서 자동 제외 (백엔드 RLS).
