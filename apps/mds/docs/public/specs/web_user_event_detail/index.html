Purpose 이벤트 참여를 결정하고 신청으로 넘어가는 화면. 방문자(로그인 여부 무관)가 이벤트의 모든 정보(이미지 · 소개 · 일시/장소 · 파트너 · 신청 현황 · 환불 조건)를 읽고, 우측 패널에서 티켓을 골라 "신청하기"로 결제 단계(WebUserCheckout)에 진입한다. 웹 MVP 코어 퍼널 "이벤트 탐색 → 상세 → 구매·신청"의 가운데 화면.
User journey Entry points: WebUserHome 카드 클릭 · URL 직접 진입 / SNS·메신저 공유 링크 (비로그인 다수) · 검색엔진 유입.
Exit points: ① "신청하기" 클릭 → 신청·결제 화면 (WebUserCheckout) · ② 비로그인 신청 시도 → 로그인 화면 (완료 후 이 화면으로 복귀) · ③ 로고 클릭 / 브라우저 back → 홈 목록 · ④ 파트너 카드 클릭 → 파트너 상세 (웹 파트너 페이지 범위는 열린 질문 — Reference 노트).
Background web-mvp pivot — 모바일 이벤트 상세의 5탭 scroll-spy · 하단 고정 바 · 티켓 선택 바텀시트 3단 구조를, 데스크톱에서는 좌측 정보 컬럼 + 우측 sticky 티켓 패널의 커머스형 2col 로 재구성했다. 티켓 선택이 화면 안에 항상 보이므로 시트를 띄우는 중간 단계가 사라지고, 정보를 읽는 동안에도 가격/신청 버튼이 시야에 유지된다 (모바일 하단 바와 같은 역할). 매칭/투표/QR/NowBar/태그 계열은 deprecated 로 제외하고, 참여 현황의 blur 프로필 리스트는 개인정보 노출 없이 정원 충족도만 전달하는 남/여 게이지로 축소했다. 환불 조건 요약은 결제 전 고지 의무(전자상거래법 — refund-policy-v2)에 따라 CTA 바로 위, 패널 안에 상시 노출한다. 1280px 데스크톱을 주 캔버스로 설계 (Mark 지시 2026-06-07) — 모바일 variant 는 후속 pass.
Frequency 관심 이벤트마다 1회 이상 — 신청 전 반복 열람.

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. 이 화면은 Desktop (≥1280) variant 가 주 blueprint — breakpoint variants 표 참조.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 이 화면은 Desktop-first 예외 화면 — 1280 baseline 으로 먼저 설계하고 Mobile blueprint 는 후속 pass 에서 추가한다 (History 참조).

Variant Breakpoint 이 화면에서의 차이
Desktop (주 variant) ≥ 1280px 헤더(로고 + 검색 + 아바타) + 2col 그리드 — 좌측 정보 컬럼 (12col 중 8col) + 우측 sticky 티켓 패널 (4col) · 컨테이너 1200px 캡 중앙 정렬 · gutter 32px · grid gap 24px — 아래 blueprint 가 이 variant.
Tablet 768–1279px 별도 blueprint 없음 — Desktop 레이아웃 축소: 2col 유지하되 패널 고정 폭 320px · 좌측 컬럼이 잔여 폭 fluid · gutter 24px.
Mobile < 768px 후속 pass 에서 작성 (TBD) — 단일 컬럼 + 티켓 패널이 모바일 spec 의 하단 고정 바 + 시트 패턴으로 복귀 예정 (behavior source 그대로). 이번 pass 는 1280 baseline 만 (Mark 지시 2026-06-07).

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
브라우저 back / forward 홈 목록으로 복귀 — 목록의 스크롤 위치·필터 상태는 홈 spec 규칙대로 복원. 패널의 티켓 선택은 history entry 아님 — back 으로 선택만 되돌릴 수 없음.
새로고침 / URL 직접 진입 /events/:id 만으로 동일 화면 복원. 서버 렌더로 Default(또는 비로그인/마감) 가 곧장 표시 — 첫 화면에 스켈레톤 없음. 추천 티켓이 다시 자동 선택됨 (이전 수동 선택은 유지하지 않음).
비로그인 접근 public 열람 — 차단·redirect 없음 (비로그인 state 참조). 로그인 유도는 "신청하기" 시점 1곳.
좌측 컬럼 스크롤 본문(이미지·소개·파트너)만 흐르고 티켓 패널은 헤더 아래 24px 에 고정. 본문이 짧으면 스크롤 자체가 없음. 패널이 화면보다 길어지는 좁은 높이에서는 패널도 페이지와 함께 흐름 (내부 스크롤 만들지 않음).
hover (fine pointer) 티켓 카드: border 강조 · CTA/공유/파트너 카드: 배경 미세 강조 — motion-fast (200ms) + cursor: pointer. 잠금 요소는 hover 변화 없음 (비활성 시그널). coarse pointer 는 press 피드백 (motion-micro (100ms)) — foundation 포인터 규칙.
"신청하기" 클릭 시점 재검증 클릭 순간 서버에서 판매 상태·자격을 다시 확인 — 그 사이 마감됐으면 "방금 마감되었어요" 토스트 + 패널이 매진·마감 state 로 갱신 (조용한 실패 금지).
브라우저 탭 비활성 → 복귀 자동 재요청 없음 — 보던 내용 유지. 신청 현황 게이지가 오래된 값일 수 있으나 CTA 클릭 시점 재검증이 안전망.

Motion & timing

duration 은 MDS motion 토큰 (micro 100 / fast 200 / medium 350 / slow 500) — 웹 구현은 CSS transition-duration / Tailwind duration-N 으로 같은 ms 소비. prefers-reduced-motion 대응은 Global edge cases 참조.

Transition Duration (token) Curve / notes
첫 화면 진입 (서버 렌더) 없음 (0ms) SSR 즉시 표시 — 진입 모션 없음
티켓 선택 이동 (border/tint 전환) micro (100ms) 즉각 피드백 — 합계 금액은 모션 없이 즉시 교체
카드/버튼 hover 진입·이탈 fast (200ms) ease-out — border/배경 강조
히어로 캐러셀 이미지 전환 medium (350ms) 가로 슬라이드 — 모바일 캐러셀 체감과 동일
패널 state 갱신 (마감 전환 등) medium (350ms) 패널 내용 crossfade — 레이아웃 점프 없이
"링크가 복사되었어요" 토스트 fast (200ms) 진입 fade + 살짝 위로 · 2초 후 자동 사라짐

Global edge cases

  • 네트워크 끊김 — 첫 로드 실패는 Error state. 신청 시도 중 끊김은 "잠시 후 다시 시도해 주세요" 토스트 + 패널 유지 (입력 유실 없음).
  • 다크 모드 — 우측 상단 Dark 토글로 확인. 배경/표면/텍스트/divider 토큰 전환 · 히어로 위 스크림/점 인디케이터는 dark 고정이라 모드 무관 · 선택 티켓의 primary 강조 유지.
  • 접근성 — 키보드 tab 순서: 로고 → 검색 → 로그인/아바타 → 공유 → (본문 링크) → 파트너 카드 → 티켓 옵션 → "자세히 보기" → CTA. 티켓 옵션은 라디오 그룹처럼 화살표로 이동 + visible focus ring. 게이지는 수치 텍스트(12/20)가 있어 스크린 리더로 동일 정보 전달. 200% 줌에서 2col 이 하위 tier 로 reflow (foundation 규칙).
  • reduced motion — prefers-reduced-motion 시 캐러셀 슬라이드/패널 crossfade 0ms · skeleton shimmer 정지 (정적 표시).
  • SEO / 공유 — public 페이지: title/og 메타 = 대표 이미지 + 이벤트명 + 일시 (공유 프리뷰가 카드처럼 보이게). 서버 렌더 — 비로그인 공개 열람과 한 쌍의 결정. 마감/종료 후에도 페이지 유지 (매진·마감 state).
  • 존재하지 않는 이벤트 주소 — 별도 404 페이지 (사이트 공통 — TBD). 비공개 전환/삭제된 이벤트도 동일.
  • 초광폭 (≥1920px) — 1200px 캡 유지, 잉여 폭은 배경 (foundation 규칙 — 패널 폭을 늘리지 않음).
