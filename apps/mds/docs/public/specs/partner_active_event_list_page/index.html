Overview

Status ✅ 디자인완료 — #3040 MDS contract. Flutter route/widget는 #3072에서 추가.
Appapp_partner
Categoryhome · event operations · active event hub
Route / Surface PartnerActiveEventListRoute · widget: PartnerActiveEventListPage (planned)
Path/events/active (planned HomeBranch child route)
Hierarchy Parent: PartnerHomePage overview stat "모집 중인 이벤트"
Children: event cards only. Detail / check-in / create flows stay in PartnerEventDetailPage, OngoingEventListPage, EventCreatePage.
Purpose 파트너가 현재 운영해야 하는 활성 이벤트를 한 화면에서 필터링하고 다음 action으로 진입한다. 홈 피드는 가장 시급한 카드만 요약하고, 이 화면은 모집 중 / 진행 임박 / LIVE 이벤트 전체를 관리하는 목록 hub다.
User journey Entry points: PartnerHome overview stat "모집 중인 이벤트" 탭 · 향후 푸시/deep link /events/active?filter=live.
Exit points: 카드 영역 탭 → PartnerEventDetailPage · LIVE/체크인 CTA → OngoingEventListPage · Empty CTA → EventCreatePage · 뒤로가기 → PartnerHome.
Background 기존 임시 흐름은 홈의 "모집 중인 이벤트" stat이 PartyListPage를 경유했다. 그러나 파티 리스트는 파티 관리 목적이고, app_user PartnerEventsPage는 소비자 탐색 화면이라 파트너 운영 action과 섞이면 안 된다. 이 화면은 partner-side 활성 이벤트 전용 surface를 독립시켜 route 확장과 필터 추가를 안전하게 만든다.
Frequency이벤트 모집/운영 중 매일. 여러 이벤트를 동시에 운영하는 파트너는 홈에서 가장 자주 진입하는 보조 hub.

Layout

AppBar + summary/stats + sticky filter + active event cards. Bottom nav shell is retained.

Blueprint & tree

HomeBranch child route로 push되어 하단 NavigationBar는 유지한다. 상단 summary는 전체 활성 이벤트 수와 위험 신호를 요약하고, sticky filter는 목록 scroll 중에도 접근 가능해야 한다.

① AppBar — back + title
② Summary — title + active count context
③ Stat row — 모집 / 임박 / LIVE
④ Sticky filter chips
⑤ Active event card list
⑥ Partner bottom NavigationBar

Layout anatomy

RegionContract
① AppBar Back icon + centered title "활성 이벤트". 우측 action 없음. 홈에서 push된 route라 뒤로가기는 PartnerHome으로 복귀.
② Summary 전체 활성 이벤트 수와 목록 범위를 설명. 카운트는 모집 중·진행 임박·진행 중 합계이며 종료/draft/canceled는 제외.

⑥ Bottom nav StatefulShell HomeBranch child route이므로 하단 nav 유지. 다른 탭 전환 후 홈 탭 재선택 시 이 route stack 유지.

Global Behavior

Route contract, filtering, sorting, lifecycle ownership.

Route and shell contract

ItemContract
Route placement PartnerActiveEventListRoute는 HomeRoute child로 추가한다. Planned path: /events/active. Bottom nav shell 유지.
Home stat tap PartnerHomePage overview "모집 중인 이벤트" stat은 이 route로 direct push한다. 더 이상 PartyListRoute 경유하지 않는다.
Filter deep link /events/active?filter=recruiting|upcoming|live는 해당 chip selected로 진입. 잘못된 값은 전체 filter로 fallback.
Back behavior Back은 PartnerHome으로 복귀. 다른 bottom tab으로 이동했다가 Home tab 재선택 시 route stack은 유지한다.

Filtering and lifecycle rules

RuleDetail
Included events 모집 중, 진행 임박, 체크인 가능, LIVE. 종료/draft/canceled/private archived는 제외한다.
Recruiting 시작까지 7일 초과 또는 active check-in 전이며 공개/판매 중. CTA는 "상세 보기"; capacity와 승인 대기 count를 표시.
Upcoming T-7 이내부터 T-2 전까지. CTA는 "참가자 리스트" outline. QR/check-in primary는 아직 쓰지 않는다.
Live / check-in ready T-2 이후부터 이벤트 종료 전. CTA는 "참가자 체크인" primary. QR은 OngoingEventListPage 내부 mode로 처리.
Sort 기본은 시작 시각 빠른 순. LIVE는 목록 상단 pin 가능하지만 filter 전체에서만 적용한다. 같은 시작 시각이면 승인 대기 많은 순.
Refresh Pull-to-refresh와 화면 재진입 시 fetch. 시간 경계(T-2, 시작/종료)는 refresh 후 재분류한다.

Screen boundaries

ScreenBoundary
PartnerHomePage Shows summary count and most urgent feed cards. It should not become the full active list.
PartnerEventDetailPage Owns single-event detail, edit entry, tickets, application status, event-level ops.
OngoingEventListPage Owns participant roster, QR mode, manual check-in, walk-in, no-show, call actions. This list only routes into it.
PartyListPage Owns party management. It is not the active event destination, although event cards need partyId for detail routing.
EventCreatePage Owns new event creation and draft/resume. Empty state may route there after party guard.
PartnerEventsPage app_user consumer browse list. Do not reuse for partner operations or home overview destination.
