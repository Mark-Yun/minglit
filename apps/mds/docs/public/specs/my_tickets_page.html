Purpose 사용자가 신청/구매한 active 티켓(paid / approved 등)을 한곳에서 확인할 수 있는 단일 list 화면. 오늘 시작하는 이벤트는 상단 banner로 강조하고, 나머지는 "다가오는 이벤트 / 지난 이벤트" 두 섹션으로 시간순 정렬한다.
User journey Entry points: 마이 페이지 "내 티켓" 항목 / 결제 완료 후 푸시 알림 / 외부 딥링크.
Exit points: 오늘 배너 또는 다가오는 카드의 "입장 QR" 탭 → 입장 QR 화면 · 카드 본체 탭 → 이벤트 상세 화면 · 빈 상태 CTA "이벤트 둘러보기" → 홈 · 뒤로 가기 → 마이 페이지로 복귀.
Background 티켓이 단순 리스트로만 늘어나면 "오늘 갈 이벤트"가 묻혀버려 입장 시 우왕좌왕한다 — 오늘 시작하는 이벤트를 화면 상단 배너로 분리 노출한다. 다가오는 이벤트는 가까운 순, 지난 이벤트는 최근 순으로 정렬해 일반적인 캘린더 시간 흐름을 따른다. 지난 이벤트 카드는 옅게 톤 다운되고 입장 QR 버튼이 사라져 "끝난 것"을 시각적으로 명확히 한다.
Frequency 이벤트 당일 입장 직전 + 일정 확인 시 — 활성 사용자 기준 이벤트 사이클당 1-3회.

States

4가지 시각 변형. baseline = Default(티켓 보유). 데이터를 불러오는 동안 Loading, 결과가 비어있으면 Empty, 실패 시 Error로 분기된다.

State 식별 기준: 티켓 데이터를 불러오는 동안 Loading, 결과를 받으면 Default(보유) 또는 Empty(없음), 실패하면 Error로 분기된다. 비로그인 사용자는 빈 결과로 처리되어 Empty 화면이 보인다.

Global edge cases

  • todayEvent 추출 시점 — build() 호출 시 DateTime.now() 기준. 화면 떠 있는 동안 자정이 지나도 자동 재계산 안 됨 (재진입 시 갱신).
  • past sort fallback — event 관계 끊긴 ticket은 startTime이 DateTime(0)로 처리되어 past 맨 끝에 배치 (orphan 정렬 안전장치).
  • QR navigation — TicketEventMeta가 GoRouterState.extra로 전달되어 URL deep-link로는 메타가 안 보임. share-link 유즈케이스 부적합 (의도된 제약).
  • Hot reload 시 stale data — Riverpod 관행대로 invalidate 호출 안 하면 캐시 유지. 결제 직후 push되더라도 invalidate 트리거가 없으면 빈 채로 보일 수 있음.
