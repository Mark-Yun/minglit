Overview

Status ✅ 디자인완료 — 5 state · 파트너 신청관리 entry hub
App app_partner
Category application · partner ops · approval workflow
Route / Surface ApplicationListRoute · widget: EventApplicationManagePage (StatefulShell · ApplicationBranch)
Path /applications
Hierarchy Parent: — (top-level partner shell screen — bottom-nav 신청관리 탭)
Children: EventApplicationDetailRoute (승인됨/거절됨 항목 탭 시 push) · _EventGroupSection · _ApplicationItem · _StatusBadge · _RejectDialog (internal widgets — no separate spec)
Purpose 파트너가 자기 이벤트들에 들어온 신청을 한 화면에서 빠르게 승인/거절한다. 이벤트별로 grouping된 신청 목록을 3개 탭(대기중 · 승인됨 · 거절됨)으로 분기해 보여주고, "대기중" 탭에서는 row-inline의 승인/거절 버튼 + 하단 "전체 승인" CTA로 bulk 처리까지 한 번에 가능하게 한다.
User journey Entry points: 하단 NavigationBar "신청관리" 탭 / PartnerHomePage TodoSummaryChips "승인 대기" chip 탭 / 푸시 알림(신청 도착) 탭.
Exit points: 승인/거절 인라인 액션 후 같은 화면 stay (snackbar) · "전체 승인" CTA · 승인됨/거절됨 항목 row 탭 → EventApplicationDetailRoute push · 다른 bottom-nav 탭으로 전환.
Background 신청관리는 파트너의 일일 운영 task 중 가장 빈도가 높은 액션 — 모든 신청을 1) 승인하거나 2) 거절(사유 필수)해야 이벤트 capacity가 확정된다. 이벤트별로 group을 묶은 이유는 같은 이벤트의 여러 신청을 동시에 판단하는 게 자연스럽기 때문(나이/성별 mix 보고 판단). pending vs approved/rejected를 별도 탭으로 분리한 이유는 처리할 일과 이력을 명확히 구분하기 위함. Fix #1597로 7일 제한이 풀려 모든 미래 이벤트를 fetch하므로 chunk size 10으로 RPC pool 보호.
Frequency 활성 파트너는 매일 1~수회. 푸시 알림이 trigger인 경우 즉시 진입.

States

시각 변형 5종. baseline = Default(대기중 탭 · grouped events with pending applications), 나머지는 additive diff.

State 식별 기준: 활성 탭 인덱스(0=pending · 1=approved · 2=rejected) · eventApplicationsGroupedProvider async lifecycle (loading / error / data) · grouped.isEmpty · showActions 플래그 (탭 0만 true). 색상은 partner brand #6c3ce1이며 user app(#9900ff)과 다르다.

Global Behavior

cross-cutting — 모든 state에 적용되는 액션, motion, 글로벌 에지케이스. 각 state 한정 액션은 위 mini-table 참고.

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
탭 전환 (대기중 ↔ 승인됨 ↔ 거절됨) TabController.animateTo · TabBarView가 swipe/tap 모두 수용. 각 탭은 statusFilter가 다른 별도 family entry로 fetch — 하나의 캐시가 다른 탭의 cache를 무효화하지 않음.
아래로 당기기 (pull-to-refresh) RefreshIndicator → 활성 탭의 eventApplicationsGroupedProvider invalidate. 다른 탭은 stale 유지 (탭 전환 시점에 자기 fetch). Empty / Loading / Error state에서는 RefreshIndicator 미렌더 (Center widget).
하단 탭 전환 (다른 branch로) StatefulShell branch 전환 — 신청관리 stack은 유지되어 돌아왔을 때 이전 탭/스크롤 위치 복원. 단, autoDispose family라 다음 진입 시 데이터는 refetch.
OS back / 시스템 뒤로 shell의 default back — 홈 branch로 pop하지 않고 앱 종료(Android) 또는 무반응. 신청관리는 top-level 탭이라 pop target 없음.
다크 모드 토글 scaffold bg → color-dark-background(#0f0f0f) · primary → color-partner-dark-primary(#9b7bec). status badge의 success/error 색은 dark에서도 유지(채도만 약간 보정).

Global edge cases

  • partner 객체 null — currentPartnerInfoProvider가 데이터로 null을 반환하면 body에 '파트너 정보를 불러올 수 없습니다' 단일 텍스트 (TabBar는 그대로 노출되지만 TabBarView 미렌더).
  • future events 0개 — partner가 미래 이벤트가 하나도 없으면 grouped는 빈 맵 → 모든 탭이 Empty state.
  • chunk fetch pool saturation — Fix #1597 — 10개씩 직렬화. 100+ 이벤트 partner는 loading이 수 초 걸릴 수 있음 (skeleton 도입 후보).
  • 승인/거절 race — 같은 application을 두 번 빠르게 탭하면 두 번째는 이미 처리된 상태로 RPC 실패. snackbar에 '승인 실패: ...' / '거절 실패: ...' 표시.
  • 전체 승인 partial failure — Fix #1953 — 일부 이벤트만 실패하면 실패한 이벤트 title을 줄바꿈으로 모두 표시. 성공한 부분은 invalidate 후 list에서 사라짐.
  • 다크 모드 — partner dark primary(#9b7bec)로 indicator/CTA 색이 흐려짐. badge bg @ highlight(.10)도 dark scaffold 위에서는 거의 안 보일 수 있어 채도 보정 필요. 다크 토글로 확인 권장.
  • 접근성 — IconButton tooltip ('승인' / '거절') 제공 · CircleAvatar의 이름 첫 글자는 시각 보조용. screen reader는 row의 _ApplicationItem 전체 Semantics를 합쳐 읽음 (이름 + 메타 + 액션).
