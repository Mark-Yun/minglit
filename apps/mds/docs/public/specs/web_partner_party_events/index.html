Purpose 파트너의 모든 파티와 회차가 한 화면에 모인다. 파티(반복되는 모임의 템플릿) 단위로 그룹핑된 목록에서 행을 펼쳐 소속 회차(이벤트)의 일시·상태·정원·신청 현황을 테이블로 확인하고, 새 파티 만들기 · 회차 추가 · 회차 수정 · 회차 취소를 이 화면에서 시작한다.
User journey Entry points: 사이드바 "파티·이벤트" 클릭 · 홈 대시보드의 "오늘·임박 이벤트" 카드/"전체 보기" · 회차 생성/수정 완료 후 복귀 · URL 직접 진입/북마크.
Exit points: "새 파티 만들기" → web_partner_party_create · "회차 추가" / 회차 행 "수정" → web_partner_event_edit · 회차 행 "취소" → 취소 확인 다이얼로그(이 화면 안) · 사이드바 4메뉴 · 비로그인이면 파트너 로그인으로.
Background 모바일 파트너 앱은 파티 목록(party_list_page) → 파티 상세 3-tab(party_detail_page) → 이벤트 상세로 3단계 내비게이션이었다. 데스크톱은 가로 폭이 넉넉하므로 파티 행 펼침 + 회차 테이블로 중간 단계를 접고, "내 운영 일정 전체"를 스프레드시트 보듯 한 화면에서 훑게 한다 (docs/architecture/web-mvp-pivot.md의 파트너 코어: 이벤트/파티 관리 → 신청 → 정산). 반복 규칙(recurring-events)이 회차를 자동 생성하므로, 파티 헤더의 반복 뱃지("매주 금요일")가 "이 회차들이 어디서 왔는지"를 설명한다. 모바일 파티 카드의 hero 이미지·태그·좋아요는 운영 허브 목적에 불필요해 제외 — 정보 밀도를 일시/상태/정원/신청 4열에 집중.
Frequency 운영 중인 파트너가 거의 매일 진입. 홈 다음으로 자주 보는 화면 — 회차 추가·수정·취소의 시작점.

Responsive Layout

화면 구조 — 영역, 정렬, 간격 규칙. 색·타이포 무시. web_partner는 데스크톱 우선 (web_foundation_responsive surface priority) — Desktop(≥1280) blueprint가 1차 산출물.

Breakpoint variants

Breakpoint · 컨테이너 · 그리드 정의의 SSOT는 web_foundation_responsive. 운영 도구 화면이므로 콘솔 셸 전체 폭 1440px 캡 (web_partner_home과 동일). 1280 viewport 기준: 사이드바 240px 고정 + 메인 컬럼 fluid.

회차 취소하기
 조건 모집 전/모집 중 회차의 "취소" 클릭 직후. 고지 내용은 회차 데이터로 채움 — 결제 참가자 수 · 환불 총액 · 대기 신청 수. 결제 참가자 0명이면 환불 문장 대신 "신청자가 없어 환불 없이 바로 취소돼요"로 단순화.

Cross-cutting interactions

사용자 액션 화면에 보이는 결과
브라우저 back 이전 페이지로. 취소 다이얼로그·펼침 상태는 history entry가 아님 — 다이얼로그가 열린 채 back을 누르면 다이얼로그만 닫히는 것이 아니라 페이지를 떠난다 (다이얼로그 닫기는 ESC/스크림/돌아가기).
새로고침 / URL 직접 진입 URL만으로 복원 — 펼침 상태는 URL에 저장하지 않고 기본 규칙(다음 회차 가장 가까운 파티 1개 자동 펼침)으로 착지. 지난 회차 토글도 접힘으로 초기화.
비로그인 접근 파트너 로그인으로 이동, 로그인 완료 후 이 화면으로 복귀. public view 없음 — 콘솔 전체가 로그인 필수 (web_partner_home과 동일).
회차 만들기/수정에서 복귀 목록 재조회 — 방금 작업한 회차가 속한 파티가 펼쳐진 채 착지 (작업 결과를 바로 확인).
브라우저 탭 비활성 → 복귀 마지막 갱신 후 일정 시간이 지났으면 자동 재조회 — 신청 수·상태 칩이 오래된 채 보이지 않게. 갱신 중에도 기존 내용 유지 (skeleton 재진입 없음).
hover (fine pointer) 파티 헤더 행·버튼·회차 행 액션에 hover 피드백 (motion-fast (200ms) · 배경/테두리 톤 변화 + cursor: pointer). hover로만 노출되는 정보 없음 — 수정/취소 액션은 항상 보임 (web_foundation_responsive 포인터 규칙).
다크 모드 surface/카드 배경이 다크 토큰으로 전환, partner primary는 다크 변형(color-partner-dark-primary #9b7bec)으로 매핑. 상태 칩 5종은 같은 의미-색 매핑의 다크 변형 사용.

Motion & timing

duration은 MDS motion 토큰 — 웹 구현은 CSS transition-duration / Tailwind로 같은 ms 값을 소비.

Transition Duration (token) Curve / notes
화면 진입 (사이드바 라우트 전환) fast (200ms) 메인 영역 fade — 사이드바는 고정 (web_partner_home과 동일)
파티 행 펼침 / 접힘 (+ 지난 회차 토글) fast (200ms) height ease-out + chevron 180° 회전 동기
취소 다이얼로그 진입 / 닫힘 medium (350ms) scrim fade + 다이얼로그 fade/scale (0.96→1) — 모달 진입 표준
hover 피드백 (행 · 버튼 · 액션) fast (200ms) ease-out — 배경/테두리 톤 변화
Loading skeleton → 데이터 cut (0ms) 즉시 교체 — Behavior Source 상속 (fade 없음)

Global edge cases

  • 네트워크 끊김 — 메인 콘텐츠 영역만 "다시 시도" 안내로 교체 (사이드바 유지). 취소 확정 중 끊기면 다이얼로그의 실패 에지케이스와 동일.
  • 다크 모드 — 우측 상단 Dark 토글로 확인. surface/배경/텍스트 토큰 전환 + primary → color-partner-dark-primary. 상태 칩·환불 고지 박스는 의미 색(warning/error/success) 다크 변형으로.
  • 접근성 — 회차 테이블은 시맨틱 table(또는 role="table")로 — 칼럼 헤더가 스크린 리더에 읽히게. tab 순서: 사이드바 → "새 파티 만들기" → 파티별 (헤더 행 토글 → 회차 추가 → 펼친 행의 수정/취소 순). 펼침 토글은 aria-expanded 표현. 다이얼로그 진입 시 포커스 트랩 + "돌아가기"에 초기 포커스 (파괴 버튼에 첫 포커스 금지). 상태 칩은 색에만 의존하지 않음 — 텍스트 라벨 항상 동반.
  • reduced motion — prefers-reduced-motion 시 펼침/다이얼로그 모션·shimmer 정지 (즉시 전환), hover transition 0ms.
  • SEO / 공유 — 비공개 콘솔 화면. noindex — og 메타 불필요.
  • 초광폭 (≥1920px) — 콘솔 셸 1440px 캡 중앙 정렬, 잉여 폭은 배경 (web_foundation_responsive 도구 화면 규칙).
  • 파티가 많은 경우 — 세로 스크롤 단일 리스트 (페이지네이션 없음 — 파트너당 파티 수는 한 자릿수 전제). 자동 펼침은 여전히 1개만.
  • 반복 자동 생성과의 동기화 — 반복 규칙 크론이 새 회차를 만들면 다음 재조회에서 모집 전 행으로 자연 등장 (실시간 push 없음 — recurring-events 1개월 윈도우 규칙).
